## Decisions and assumptions
- Contract shape followed: `usual_range` is a `tuple[int, int]` (per `contracts.md` and the prompt), not the `usual_range_min` / `usual_range_max` pair in `domain-rules.md` 1.1. The prompt says it wins where they differ.
- `limited_level_percent` range is 1 to 100 inclusive, because the prompt rejects 0 and accepts 80 and 100. The default 80 is the named constant `LIMITED_LEVEL_PERCENT_DEFAULT` marked `[ASSUMED]` (DEC-007).
- Validation beyond the prompt, each pinned by a test:
  - `days` must be a `frozenset` of plain ints (not `bool`, not floats, not strings), so the value stays hashable.
  - An all-day window with an end time is rejected at `end`.
  - Window times must be `time` values with no timezone, because window times are London local and naive. A timezone-aware time is rejected.
  - A name, unit label or id that is only whitespace is rejected as blank.
  - Numeric fields reject `bool` and non-int values rather than coercing them.
- The stub-based red commit follows DEC-010. The stub raises `NotImplementedError`, so the red failures are not assertion failures (see the limit under Red run).
- Commit `7a5946f` (type-guard tests) was written after the green commit, to bring branch coverage to 100%. Those 19 tests passed on first run against code already written, so they were not seen to fail first. This departs from the test-first order in the standard for those 19 tests; the verifier should weigh that.
- Constants `ALL_DAYS`, `MONDAY_TO_FRIDAY`, `ESTABLISHED_CAPACITY_MIN`, `LIMITED_LEVEL_PERCENT_MIN` and `LIMITED_LEVEL_PERCENT_MAX` are public module constants that `contracts.md` does not list. They are not shared cross-task names, so no `contracts.md` entry was added.
- Not used: `decisions.md` DEC-012 (Neo4j connections) and DEC-008 (harness) do not apply to a pure value object.
