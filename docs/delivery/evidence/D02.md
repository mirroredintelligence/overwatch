## Decisions and assumptions
- The prompt says `value ≥ 0` and `effective_at` aware. The code checks `value < 0` only. It does not reject non-integer values (for example `2.5`) or `bool`, because the prompt does not require it. Callers in D10/U01 must pass an int. This is a known gap, not a tested behaviour.
- `effective_at` check accepts a datetime with a `tzinfo` whose `utcoffset()` is None as naive. Covered by the naive test only for `tzinfo=None`.
- `latest_report` compares aware datetimes with `>=`. Mixing naive and aware datetimes would raise TypeError inside the comparison; the constructor already rejects naive ones, so this cannot happen for valid reports.
- No deviation from `contracts.md` (`model/capacity.py` (D02) entry) or DEC-017 (not applicable here).
