## Decisions and assumptions
- **DEC-023** (committed before the red commit): `current_due` searches back 8 days, not only today and yesterday as the prompt says. The prompt's version returns None on a Monday before 08:00 for a weekday-only service that was due on Friday evening, which loses the overdue state for D05 and D07.
- **[ASSUMED]** alignment and 14:00 second slot from domain-rules 1.4, held as the named constant `TWICE_A_DAY_SECOND`.
- **Twice-a-day rule** read literally: 14:00 is added only when start < 14:00 < end, by plain time comparison. An overnight window such as 10:00 to 06:00 therefore gets the opening only. The owner should confirm this reading.
- **Spring-gap collision:** on 2026-03-29, a local 01:00 (absent from the clock) maps to 01:00Z, the same instant as local 02:00. The due list keeps one instant, so there are no duplicates.
- **every-2-hrs window end:** the closing time is included (prompt wording). domain-rules 1.4 says "up to its end". Both give 20:00 for 08:00 to 20:00.
- **next_due** returns None only if no due time falls in its search; for any valid profile it does not.
