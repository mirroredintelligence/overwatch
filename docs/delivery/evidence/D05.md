## Decisions and assumptions
- **DEC-027**: prompt test 7 (no report ever, before the first Monday due, not overdue) conflicts with prompt test 6 and with domain-rules 1.5. No rule built on due times can give both. Implemented the rule book: overdue, `was_due` Friday 19:00Z. The owner should confirm. This is a deviation from the prompt's acceptance text, not a silent change.
- DEC-027 (additional conventions): `stale_warning` is False with no report (no figure to warn about); a report later than `now` raises ValueError; `was_due` is found with `current_due` only (L30); a report exactly at a due time answers it.
- Look-back: `current_due` looks back 8 days (DEC-023), so a no-report service is overdue from the most recent missed due within 8 days.
- The three boundary tests (`test_report_exactly_at_the_due_time_answers_it`, `test_reply_by_exactly_now_is_not_yet_missed`, `test_one_microsecond_after_reply_by_is_overdue`) were added after the green commit. They were not red first; they pin boundaries the prompt implies and were checked by the mutation run above.
