## Summary
`diucs/domain/rules/reply_policy.py` now decides what happens to one capacity reply: record a figure, record a correction, refuse a late reply with a new reply-by, refuse a third Y, ask for an out-of-range figure again, or ask for a number when a Y has no figure to confirm. It is a pure function of the reply, the prompt state and `now`. It does not change state.

## Decisions and assumptions
- **DEC-027** (in `decisions.md`, green commit) records the points the rule book leaves open: a Y is never a correction, correction precedes open-prompt for figures, the window is inclusive and measured between instants, a late out-of-range figure gets `RejectLate`, a repeated out-of-range correction gets the flag, and naive datetimes raise `ValidationFailed`.
- `CORRECTION_WINDOW = 15 min` and `MAX_CONSECUTIVE_CONFIRMS = 2` are the `[ASSUMED]` values from DEC-007 and the prompt.
- The reply-by for a late reply is `now + REPLY_WINDOW`, with `REPLY_WINDOW` = 30 min from `schedule.py` (prompt says the same value).
- **Test file changed in the green commit.** After the red commit, `ruff format` reflowed one multi-line expression (`accepted = ...`), and one assertion in `test_correction_window_is_fifteen_minutes` was reordered from `CORRECTION_WINDOW == timedelta(minutes=15)` to `timedelta(minutes=15) == CORRECTION_WINDOW` to satisfy SIM300. Neither change alters what is asserted. `git diff d811276 94d691d -- backend/tests/unit/domain/rules/test_reply_policy.py` shows exactly these two hunks. The red run above was taken before these edits.
- Prompt-silent choices, all in DEC-027: Y after the prompt closed is `RejectLate` even within the correction window; a figure inside the correction window is a correction even with the prompt open; decision inputs with no UTC offset raise `ValidationFailed`.
- Lessons L27 and L28 say consumers of lettered replies iterate the parser tuple. This policy takes one `Confirm | Number` as the prompt defines, so it does not read the tuple. The use case (U05, U04) must loop over the items.
- The `RejectLate` new reply-by is returned in the caller's timezone (`now + REPLY_WINDOW`). Equality is by instant, so the tests compare fine.
