## Decisions and assumptions
- `is_open` is true only for `requested`. Confirmed bookings are live but are not "open" in the sense of the one-per-service rule in `domain-rules.md` 3.2, which names requested bookings. [ASSUMED]
- `statusReason` is set only for `expired` and `withdrawn`, the two rows that show it in `domain-rules.md` 3.1. The graph table in `fhir-data-model.md` also says decline, cancel and withdraw reason codes go in `statusReason`. Those reason codes are not part of this state mapping and are left to the mapper and the booking tasks. [ASSUMED]
- `transition` raises `InvalidTransition` for a value that is not a `BookingStatus` (for example `ReportType.CONFIRMED`). `allowed_targets`, `is_open` and `to_fhir` raise `ValidationFailed` for the same input. [ASSUMED]
- No DEC entry is needed: nothing in the prompt or the spec was changed.
