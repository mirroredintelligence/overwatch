## Decisions and assumptions
- DEC-016 applied: reference matching is exact string equality. Prefix and longer-number replies are refused (tests added beyond the prompt, written in the red commit).
- DEC-007 / `[ASSUMED]`: 4-digit references from 1000 to 9999, 50 attempts before `Conflict`. `REFERENCE_ATTEMPTS` is the named constant.
- `can_request` reuses `is_open` from D13, so a value that is not a `BookingStatus` raises `ValidationFailed` (lesson L3 safe).
- Timers take the requested instant as given. Naive datetimes are not rejected. The prompt does not ask for that check, and no test covers it.
- Open point, not guarded: if two open bookings carry the same reference (which the rule book says must not happen), `match_reply` returns the first one that matches. Uniqueness among open bookings has to be enforced where bookings are created (RequestBooking, later task).
- Open point, behaviour of the 50-attempt limit: when most of the 9000 references are taken, `new_reference` can raise `Conflict` while free numbers still exist. Harmless at realistic volumes, but it is what `[ASSUMED]` 50 attempts implies.
- No deviation from `domain-rules.md` 3.2 or from the prompt's names and signatures.
