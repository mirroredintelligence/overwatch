On the "999 is rejected" request: the current code does not reject 999, but it does not need to. `randint` is called with a lower bound of 1000, so a real draw can never be 999. A test that feeds a fake rng the value 999 would need a runtime guard. That guard would compare against the same constant, so it could not catch the `_REFERENCE_LOWEST=999` mutant. The pinned contract is therefore the bound arguments, which is what the tests assert. No redundant guard was added.
