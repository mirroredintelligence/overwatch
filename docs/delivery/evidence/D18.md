## Decisions and assumptions
- **Field names in `ValidationFailed`** are chosen by the builder (the prompt does not name them): `news2`, `clinical_frailty`, `ambulance_category`, `manchester_triage`, `pathways_dx`, `scores`, `opened_at`, `closed_at`, `urgency`, `destination_service_id`.
- **Validation beyond the prompt**, each covered by a test:
  - Booleans are refused as scores (`True` is an `int`). Test: `test_news2_rejects_a_bool_even_though_it_is_an_int`.
  - `opened_at` and the close time must be timezone-aware UTC (repo convention: datetimes are UTC). Tests: `test_naive_opened_at_is_refused`, `test_naive_close_time_is_refused`.
  - `priority_for` refuses an unknown urgency instead of returning `routine`, so a bad value cannot downgrade a case. Test added after the green commit (see below).
- **Pathways Dx** is validated for format only. The prompt's "chosen from a list" needs a list that is not in the spec; the list is not built.
- **Red-commit corrections (disclosed).** Two strings in the red test file were wrong as tests. The accepted boundary was `DX0123456789`, which is 12 characters, not 10. The refused string `DX0123456789A` was 13 characters, not the 11 used now. In the green commit both were corrected to 10 characters (`DX01234567`, accepted) and 11 characters (`DX012345678`, refused). The red run failed on `NotImplementedError` both before and after the change, so the red proof is unchanged, but the red file is not byte-identical to `2a377fd`. Verifier: please check the diff `git diff 2a377fd b9c2c5c -- backend/tests` for these two lines.
- **Test added after the green commit.** `test_priority_for_refuses_an_unknown_urgency_rather_than_routine` was written after the implementation, to cover the fail-closed branch (the coverage gap at `case.py` line 118). It is not red-first. The mutation check above shows it fails when the guard is removed.
- **Open question, not decided.** `destination_service_id` is stored as given for outcomes other than accepted-and-booked (a destination on a declined case is accepted). The prompt does not forbid it; the rule book does not say. Left as given.
- **`reference`** is stored as a non-empty string but not format-checked: no reference format is in the spec for cases (booking references are 4 digits in DEC-007; cases are not covered).
- **Constants**: no `[ASSUMED]` constant beyond the Pathways Dx format (`PATHWAYS_DX_PATTERN`) is introduced. Score ranges are the spec's values, named as module constants.
- No new decision (DEC) was written and `contracts.md` was not changed: the names used are the contracts.md names.
