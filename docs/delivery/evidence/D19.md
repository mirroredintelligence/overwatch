## Decisions and assumptions
- DEC-027 (new, in `docs/delivery/decisions.md`): postcode normalisation removes any whitespace (including NBSP); non-ASCII input is refused, not converted; a district is trimmed only at its ends, so `DT4 8` is not read as `DT48`.
- The prompt says "section 4.1 (districts)", but `domain-rules.md` 4.1 is the hard criteria filter. The prompt's rules were used. Owner may wish to add a normalisation rule to the rule book.
- Module-level regexes are named constants (`FULL_POSTCODE`, `DISTRICT`, `INWARD_LENGTH`). They are not `[ASSUMED]` thresholds from the rule book.
- The prompt's example `SW1A 1AA` is a public postcode; the brief asked for synthetic fixtures, so this is disclosed here. Fixtures contain no patient data.
