## Decisions and assumptions
- DEC-035 (renumbered from DEC-032, which main took for D22): unknown codes fail closed with the reasons `Need not recognised` and `Age not recognised`. The status gate and enum checks use exact member types (lesson L3). Recorded in `docs/delivery/decisions.md`.
- `contracts.md` (criteria line): added `AGE_OVERLAP_WARNING` and the two reasons.
- `ServiceCriteria` validates district codes with `normalise_district` from D19 (so `dt4`, `DT4 8`, and the empty string are refused). This is the D19 rule, applied to the criteria.
- `ServiceCriteria` accepts an empty `districts` set. Such a service is never covered, so it is excluded.
- `[ASSUMED]` values used: the age overlap warning text (domain-rules 4.1). No other constants.
- `check_hard_criteria` takes `criteria` as a `ServiceCriteria` (contract). A `None` criteria raises `AttributeError`, not an exclusion. The caller must pass a criteria version. Use cases that look one up must check for absence before calling the filter.
