## Decisions and assumptions
- DEC-044 (in `docs/delivery/decisions.md`, commit `495f855`) records the choices the prompt leaves open: the locking attempt's outcome is `locked`; attempts on a locked PIN do not change the count; entries against a verified code are `expired`; clock-backwards inputs fail closed; datetimes are UTC-normalised and naive ones are refused; the PIN never enters the module; device-known is a caller input.
- The number is DEC-044. DEC-043 is D17's, and DEC-046 is D24's (lesson L43; coordinator note on this branch).
- `[ASSUMED]` resend cooldown of 60 seconds is used as the named constant `CODE_RESEND_AFTER`.
- Errors raised for bad input are `ValidationFailed`, which is a `DomainError`, as the brief asks. Other rule modules raise `ValueError` for naive datetimes. D27 uses `ValidationFailed` for consistency with the prompt's error rule. Not changed elsewhere.
