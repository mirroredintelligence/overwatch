## Decisions and assumptions
- **Python 3.14.8.** `uv` installed 3.14 without network trouble; `requires-python = ">=3.14"`, pinned in `.python-version`. `python` on PATH is 3.12.10, so the uv-managed interpreter is what runs the checks. This is consistent with DEC-009.
- **Dependency versions** were taken from the `uv add` resolution and locked in `uv.lock`: fhir-resources (>=8.3.0), pydantic (>=2.14.1), pydantic-settings (>=2.16.1); dev: pytest 9.1.1, pytest-asyncio 1.4.0, ruff 0.17.2, mypy 2.4.0, import-linter 2.15 or later. The `>=` floors are the resolved versions.
- **Build backend is hatchling** (needed so `uv` installs the `src/diucs` package for tests). Not named in the prompt, but it is the minimum needed to make `import diucs` work from the src layout.
- **`[tool.importlinter] root_packages = ["diucs"]`** was added so `lint-imports` runs. F02 adds the real contracts.
- **Empty packages** under `adapters/` and `bootstrap/` contain only `__init__.py`. The prompt's list (`adapters/inbound/` and so on) was followed exactly. Subfolders such as `inbound/fhir_rest/` listed in `contracts.md` are not created here, because the prompt's build list did not name them and the owning tasks create them.
- **Test layout:** the pytester test writes its probe files into a temporary project, with a copy of `tests/conftest.py`, so the real hook is exercised.
- **Warning:** pytester emitted a `PytestDeprecationWarning` about the fixture loop scope when the inner project had no setting. Fixed by setting `asyncio_default_fixture_loop_scope = function` in both the outer `pyproject.toml` and the inner ini. The shipped test run has no warnings from the repo's own configuration.
