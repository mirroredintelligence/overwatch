## Decisions and assumptions
- **Config location.** Contracts are in `backend/.importlinter` (INI, `[importlinter]` section), as the prompt's owned-files list says. F01 had put a `[tool.importlinter] root_packages = ["diucs"]` stub in `backend/pyproject.toml` so that `lint-imports` ran. That stub duplicated the new config and was removed from `pyproject.toml` in the green commit. This is an edit to an F01 file, outside `src/`.
- **`containers = diucs`** with layer names relative to it (`bootstrap`, `adapters`, `application`, `domain`). Full module names in `layers` fail with "module diucs.diucs.bootstrap does not exist" in import-linter 2.15.
- **Wildcards.** `diucs.adapters.inbound.*` matches no module today (the `inbound` package is empty). The contract is KEPT but checks nothing for `inbound` until a child is added. `.importlinter` has a comment telling later tasks to keep wildcards or append their packages. No test asserts that each adapter package is covered. `outbound.*` matches `audit_neo4j` and `graph_store` today.
- **Probe tree.** `_BASE_TREE` in the test file holds every package the real contracts name, with no violations, so each negative probe differs from a clean baseline by one import. The probe config is the real `.importlinter` with `\bdiucs\b` replaced by `diucs_probe`.
- **Beyond the prompt.** The prompt asks for three probes. The test file adds one more domain probe (external `neo4j`) and three application probes (`adapters`, `bootstrap`, external `fastapi`) because the prompt's Build list names those forbidden modules and the rule should be shown to bite for each class of rule. No test covers the `Layers` contract with a negative probe; that is a gap (see Not done).
- **Lint invocation from the test.** The test runs `lint-imports` through `sys.executable -c "from importlinter.cli import lint_imports_command; lint_imports_command()"`, because import-linter 2.15 has no `__main__` module and `uv` is not on PATH in this environment. `PYTHONIOENCODING=utf-8` is set for the subprocess (lesson L1).
- **Assertion tightening.** The negative probe tests in the red commit asserted only that the contract name appeared in the output plus a non-zero exit. A kept contract would also print its name, so a non-zero exit caused by a different contract could pass. The green commit asserts `<name> BROKEN`. This is a stricter check, but it is a change to a test file after its red commit.
- **Red commit trailer.** The red commit `9f5e2ef` lacks the `Co-Authored-By` trailer; the green commit has it.
- Findings fix (after verification failed at `f388b3f`): the three new probes were written after the red and green commits. They test rules that already exist in `.importlinter`, so they pass on the first run; they were not seen failing first. The swap mutant was also run by hand: reversing the layer order makes `Layers` report BROKEN for the adapter-to-application import.
- Lesson L3 (StrEnum equality across enums, applies to F07) read and acknowledged. F02 adds no enum-keyed lookup and no `StrEnum` code, so no change is needed.
- No DEC was added. No shared name in `contracts.md` changed.
