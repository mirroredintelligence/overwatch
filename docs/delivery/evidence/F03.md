Changes to red-commit files after red, all in later commits:
- `page.test.tsx`: the axe call is now `runAxe(container)` from `test/a11y.ts`, which turns the `color-contrast` rule off. Reason: jsdom has no canvas, so axe's colour-contrast rule throws `HTMLCanvasElement.prototype.getContext not implemented`. - `test/setup.ts`: added `afterEach(cleanup)`. Vitest runs without globals, so Testing Library does not clean up itself, and without it the second axe run saw two `<main>` landmarks. Removed a side-effect import in favour of `test/vitest-axe.d.ts`.
- `playwright.config.ts`: removed `port` from `webServer`, because Playwright 1.56 rejected the config with "Either 'port' or 'url' should be specified".
- `package.json`: `"type": "module"`, a Playwright install step in the `e2e` script, and version changes (see table below).
- `tsconfig.json`: Next added `.next/dev/types/**/*.ts` to `include`.
- `frontend/AGENTS.md` and `frontend/next-env.d.ts` were generated by Next and are in the implementation commits.

## Smoke e2e red proof (retrofitted, not red-first)
`e2e/smoke.spec.ts` was NOT red-first. It was committed in the red commit `7bb9459`, but at that commit it never reached an assertion: the `webServer` `port` setting rejected the config, and once that was fixed Next returned 500 because there was no root layout. So the smoke test was never seen failing on an assertion until this section was made.

To get that proof without rewriting history, a temporary worktree was made at `7bb9459` (`../overwatch-wt/F03-redproof`). In it, only these were changed on top of the red commit: remove `port` from `webServer` in `playwright.config.ts`; add a root layout stub (`app/layout.tsx`, `<html><body>{children}</body></html>`, no `lang`, no title); add a root page stub (`app/page.tsx`, returns `null`). Playwright's `webServer` waits for a 2xx at `/`, which 404s without a root page, so the root page stub was also needed. The `package.json` and `pnpm-lock.yaml` of the tip were copied in so the run used Playwright 1.61.1 and the cached Chromium 1228, the same toolchain the tip runs. That is the one difference from the red commit's own lock file (Playwright 1.56.1, whose browser does not install here).

Result (`pnpm exec playwright test` at proof commit `cfcf491`, captured output in `docs/delivery/evidence/F03/redproof-e2e.txt`):
```
Running 1 test using 1 worker
  x  1 [chromium] › e2e\smoke.spec.ts:3:1 › wall screen shows its heading and a page title (5.2s)
  1) [chromium] › e2e\smoke.spec.ts:3:1 › wall screen shows its heading and a page title
    Error: expect(locator).toBeVisible() failed
```

The failure is the heading assertion (line 8 of the spec), so the test fails for the right reason. The title assertion (`toHaveTitle`) was not reached.

Note on a false failure seen during this work: a `pnpm dev` server from the temporary worktree was still on port 3000 when the tip's `pnpm e2e` ran. `reuseExistingServer` made Playwright use that server, which served the red stubs, so both tests failed. After the server was stopped, the tip's `pnpm e2e` passed (`docs/delivery/evidence/F03/e2e-tip3.txt`, 2 passed). Local runs reuse a server already on port 3000 by design (`reuseExistingServer: !process.env.CI`).

The proof commit `cfcf491` is on the local branch `task/F03-redproof`, parented on `7bb9459`, and that branch is kept. It is not an ancestor of the task branch tip. It was not placed on `task/F03-frontend-scaffold`, because that would have meant rewriting the branch history.
