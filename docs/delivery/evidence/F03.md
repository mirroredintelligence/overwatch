## Red commit contents and what changed after red
Red commit `7bb9459` holds these files:
- `frontend/app/(wall)/screen/page.tsx`: a stub returning `null`, so the tests fail on assertions, not imports.
- `frontend/app/(wall)/screen/page.test.tsx`: the two prompt tests. The axe test was written as `axe(container)` directly.
- `frontend/e2e/smoke.spec.ts`: heading and title smoke test.
- `frontend/package.json`, `frontend/pnpm-lock.yaml`, `frontend/tsconfig.json`, `frontend/vitest.config.ts`, `frontend/playwright.config.ts`, `frontend/test/setup.ts`, `frontend/.gitignore`.

Changes to red-commit files after red, all in later commits:
- `page.test.tsx`: the axe call is now `runAxe(container)` from `test/a11y.ts`, which turns the `color-contrast` rule off. Reason: jsdom has no canvas, so axe's colour-contrast rule throws `HTMLCanvasElement.prototype.getContext not implemented`. Contrast is covered by the Playwright axe check (`e2e/smoke.spec.ts`, WCAG 2 AA tags) instead.
- `test/setup.ts`: added `afterEach(cleanup)`. Vitest runs without globals, so Testing Library does not clean up itself, and without it the second axe run saw two `<main>` landmarks. Removed a side-effect import in favour of `test/vitest-axe.d.ts`.
- `playwright.config.ts`: removed `port` from `webServer`, because Playwright 1.56 rejected the config with "Either 'port' or 'url' should be specified".
- `package.json`: `"type": "module"`, a Playwright install step in the `e2e` script, and version changes (see table below).
- `tsconfig.json`: Next added `.next/dev/types/**/*.ts` to `include`.
- `frontend/AGENTS.md` and `frontend/next-env.d.ts` were generated by Next and are in the implementation commits.
