## Decisions and assumptions
- **DEC-008 overrides part of the F05 prompt.** The prompt says the `backend` job runs `docker compose -f infra/docker-compose.yml up -d --wait` before pytest and `down -v` with `if: always()`, and `docker compose logs neo4j` on failure. DEC-008 says the test harness starts its own throwaway Neo4j per pytest session, that `infra/docker-compose.yml` is for local runs only, and that "CI does the same". So `ci.yml` does not run compose at all. The `backend` job runs `docker version` and then `uv run pytest`. The `up`, `logs` and `down` steps are not in the workflow, and test 4 was rewritten as `test_backend_job_does_not_use_compose_for_tests`. This is the deviation to confirm with the owner.
- **F04 is not on main.** `infra/docker-compose.yml` does not exist yet (F04 is in progress). The workflow does not reference it, so F05 does not depend on F04 being delivered.
- **Harness not on main.** F10 (the Neo4j test harness) is not delivered, and there are no integration tests on main. The `backend` job therefore runs only the existing unit and architecture tests and does not yet exercise Neo4j. It will once F10 lands.
- **`UV_PYTHON`** pins the Python version per job (`${{ matrix.python-version }}` for `backend-static`, `"3.14"` for `backend`), because `.python-version` is 3.14 and would otherwise override the matrix.
- **Python 3.15 leg** is `continue-on-error` via expression `${{ matrix.python-version == '3.15' }}`. Python 3.15 was not installed locally, so that leg was not run.
- **`PYTHONIOENCODING: utf-8`** is set on the lint-imports step. It is harmless on Linux and matches lesson L1.
- **pyyaml** added as a dev dependency with `uv add --dev pyyaml`, resolving to `pyyaml>=6.0.3`.
