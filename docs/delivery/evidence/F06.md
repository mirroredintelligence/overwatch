## Decisions and assumptions
- Gap and fold use zoneinfo's PEP 495 `fold=0` behaviour, which matches the prompt. The gap-shifting property is tested explicitly.
- Consequence of "shift forward" that the schedule tasks must know: local 01:00 to 01:59 on 2026-03-29 map to 02:00 to 02:59 BST, and local 02:00 maps to the same UTC instant as local 01:00 (01:00Z). Wall-clock order is therefore not monotonic across the gap, so the monotonic property excludes gap times. D04 should not schedule inside 01:00 to 02:00 on that date.
- FixedClock converts input to UTC, so `now()` always returns UTC.
- `tzdata` and `hypothesis` added as dependencies (see Red run).
- No DEC entry was needed; behaviour follows the prompt and `contracts.md`.
