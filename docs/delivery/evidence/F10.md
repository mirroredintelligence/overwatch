## Decisions and assumptions
- **DEC-013** (`docs/delivery/decisions.md`): the harness starts its own container each session, sets `NEO4J_URI`, `NEO4J_USER` and `NEO4J_PASSWORD` for the session, overwrites a shell `NEO4J_URI`, and wipes only through the harness driver. It clarifies DEC-008 and the F10 prompt, which disagree on whether an unset `NEO4J_URI` fails the session. I followed "the harness sets the URI itself".
- **Container timing:** the 5 s limit in the prompt applies to `connect_or_fail`. Container readiness is polled for up to 120 s.
- **Failure message:** Docker failures get their own message, not the docker-compose start message, which points at the shared stack.
- **No testcontainers:** the container is started with the `docker` CLI through `subprocess`. No dependency added.
- **Edit to G01's file:** `backend/tests/integration/graph_store/test_driver.py` lost its module-scoped `neo4j_driver` fixture, which read `NEO4J_URI` and failed when it was unset. G01's docstring said F10 would supply the URI. The tests use the session driver, and `loop_scope` is `"session"`. Otherwise unchanged.
- **Fixture naming:** `harness_driver` is the session driver. `neo4j_driver` returns it, so a module can override the name (`test_infra_up.py` does, for the compose stack). `clean_graph` depends on neither name; it wipes `_active`, which holds only the harness's drivers.
- **Clean-graph timing:** `clean_graph` does nothing until the harness has started. A fresh container is already empty, so this loses nothing.
- **Loop scopes:** `asyncio_default_fixture_loop_scope` and `asyncio_default_test_loop_scope` are `"session"` in `backend/pyproject.toml`; `pythonpath = ["."]` added.
- **Out of scope, not built:** `uow_factory` (P06), repositories, Redis and Service Bus fixtures.
