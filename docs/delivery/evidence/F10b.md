## Summary
Several agents running pytest at once each started a Neo4j and overloaded the machine. Now one container exists at a time machine-wide (a flock held from start to removal), it has a memory limit, its owner process is recorded so a leaked container is removed as soon as its owner dies (and a live owner's never is), readiness is a cheap Bolt check that starts counting only after the image is present, and a hung test fails in minutes. No new dependency, no existing assertion changed, DEC-008 (one throwaway Neo4j per session) holds, tenancy untouched.

## Decisions and assumptions
DEC-135 (this task) amends DEC-013 (readiness timing: Bolt probe, 120 s counted after the image is present) and DEC-108 (reaper: owner first, age only as fallback; labelled containers no longer lose a run that lasts over 90 minutes). The values heap 256m, page cache 128m, memory 1g, lock wait 3600 s, readiness 120 s, test limit 300 s are chosen from the measurements above and are environment-overridable. `[ASSUMED]`: containers made by the old harness that are still running during rollout keep the 90-minute rule, so a legacy run longer than 90 minutes could still be reaped by a new-harness session; no run is expected to last that long.
