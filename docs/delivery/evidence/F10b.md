# Evidence: F10b Test harness load protection

Builder: build-F10b · Branch: `task/F10b-harness-load-protection` · Prompt: none (orchestrator brief; no ledger task id, so no `claim`; same test-first and evidence discipline). Decision: DEC-135.

## Summary
Several agents running pytest at once each started a Neo4j and overloaded the machine. Now one container exists at a time machine-wide (a flock held from start to removal), it has a memory limit, its owner process is recorded so a leaked container is removed as soon as its owner dies (and a live owner's never is), readiness is a cheap Bolt check that starts counting only after the image is present, and a hung test fails in minutes. No new dependency, no existing assertion changed, DEC-008 (one throwaway Neo4j per session) holds, tenancy untouched.

Round 2 (after the first independent verification failed, see the end of this file): the reaper no longer reads an unreadable `/proc` entry as "owner gone" (B1); the decisive age constants, the lock freed after a failed `docker rm` and the hard backstop are now pinned by tests (B2); this file's wrong statements are corrected (B3); and seven non-blocking items were done (N1 to N5, N7; N6 recorded as a known limit).

Round 3 (after the second independent verification failed on B4, see "Verification, round 2"): an owner whose pid this process cannot see is no longer read as gone. The owner label now also records the pid namespace and the boot; an owner in another namespace, boot or host, or one that cannot be seen (a hidden stat file with a pid that still exists, EPERM, a garbled line), is kept until the six-hour age. Only a pid the kernel confirms is absent (`kill(pid, 0)` says no such process) or a zombie is gone. The non-blocking items N8 to N11 are done or recorded (N11 as a known limit). The round-2 counts at `741ed94` are corrected (N10), and DEC-135 now says exactly what is handled.
