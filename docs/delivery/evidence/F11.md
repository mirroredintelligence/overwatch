## Decisions and assumptions
- The two new tests are in a new file, `tests/integration/support/test_harness_restart.py`, not in the F10 file `test_neo4j_harness.py`. Neither the prompt nor the owned-files list names a test file for them. The F10 file is untouched.
- Tests 1 and 2 use their own `throwaway_driver()` container, not the session container, so a stop does not affect other tests.
- The harness gains `stop_container`, `start_container` and `wait_until_ready` in `tests/support/neo4j.py`. `_wait_until_healthy` stays in the G14 test module as the readiness gate for health, as the prompt says.
- `start_throwaway_neo4j` now calls `wait_until_ready` and removes the container on timeout. Its behaviour is unchanged.
- Without `--rm`, a container left running when pytest is killed hard stays until removed by hand. With `--rm` it also stayed running in that case, because `docker run -d` detaches, so this does not change the leak profile.
- `harness_neo4j` is a session fixture that yields `(container, driver)`. `harness_driver` and the new `harness_container` both depend on it. Other tests see no change.
- The G14 module's stop and start calls now go through the harness helpers, which raise `RuntimeError` on failure, not `CalledProcessError`.
- Stop and start use Docker's default stop timeout.
- No `[ASSUMED]` values were used.
