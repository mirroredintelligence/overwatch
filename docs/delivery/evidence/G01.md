## Summary
The back end has one Neo4j driver factory (`create_driver`), built with the DEC-012 pool bounds and with server notifications off. It is the only place the driver is constructed. A registry of named Cypher queries sends only the query id to the observer. An idempotent migration runner applies the eight first constraints and indexes and records each one. The composition root builds one driver from settings and exposes it as `Container.neo4j_driver`.

## What changed for the verifier's findings
1. **DEC-012 pool options are set in `create_driver`.** The option names were checked against the installed driver (neo4j 6.4.1). They are constructor keywords on `AsyncGraphDatabase.driver`. The values were confirmed on the built driver by a probe, which printed `1800.0 30.0 50 30.0`.
   - `max_connection_lifetime` = 1800 s, stored at `driver._pool.pool_config.max_connection_lifetime`.
   - `liveness_check_timeout` = 30 s, stored at `driver._pool.pool_config.liveness_check_timeout`.
   - `max_connection_pool_size` = 50, stored at `driver._pool.pool_config.max_connection_pool_size`.
   - `connection_acquisition_timeout` = 30 s, stored at `driver._default_workspace_config.connection_acquisition_timeout`. Tests read it there. It is a private attribute of neo4j 6.4.1, so a driver upgrade must re-check it.
   - These are the defaults of `create_driver`. `Settings` carries them as `DIUCS_NEO4J_MAX_CONNECTION_LIFETIME_S`, `..._LIVENESS_CHECK_TIMEOUT_S`, `..._CONNECTION_ACQUISITION_TIMEOUT_S` and `..._MAX_CONNECTION_POOL_SIZE`, and the container passes them through.
   - Tests: `test_driver.py::test_create_driver_sets_the_dec_012_pool_options`, `::test_create_driver_passes_its_pool_arguments_through`, and `tests/unit/bootstrap/test_container.py::test_build_passes_the_dec_012_pool_settings_to_the_driver`.
   - DEC-012 is followed as written. Nothing is deferred to G14 for these four options.
2. **No Cypher text in logs.** The driver logs each server notification at WARNING with `for query: '<cypher>'`. `create_driver` sets `notifications_min_severity="OFF"`, which stops the server sending them. Nothing in the code base uses those notifications.
   - Test: integration `test_run_query_logs_no_cypher_text_even_when_the_server_warns` (a query on a missing label, caplog at WARNING). Unit `test_run_query_logs_no_cypher_text` covers the stub path.
   - Mutation check: a `logging.getLogger(__name__).warning(query.cypher)` added inside `run_query` makes `test_run_query_logs_no_cypher_text` fail. It was restored afterwards.
   - Limit: the `neo4j.io` logger writes the Bolt messages, including `RUN '<cypher>'`, at DEBUG. The logging configuration must keep the `neo4j` loggers at INFO or above. The observability task (O01) owns that configuration. The caplog test asserts at WARNING, the level a service logs at.
3. **Fresh-schema tests.** Two integration tests were added. `test_every_migration_statement_runs_twice_in_separate_sessions` runs each statement twice, each in its own session. `test_reapplying_over_an_existing_schema_recreates_a_dropped_index` drops `obs_by_service`, clears `(:Migration)`, and re-applies all eight. Either fails when `IF NOT EXISTS` is missing.
   - Mutation check: `IF NOT EXISTS` removed from `concept_key`. Five integration tests fail (`test_apply_migrations_applies...`, `test_each_applied_migration...`, `test_schema_has...`, `test_every_migration_statement_runs_twice...`, `test_reapplying_over...`). The file was restored from a copy and the diff is empty.
4. **Query mode is a label.** `run_query` does not check the mode against the transaction, and does not need to. The caller chooses the transaction type (`execute_read` or `execute_write`), and Neo4j enforces it: a write is refused in a read transaction. `NamedQuery.mode` is checked at construction and is used as the telemetry label passed to the observer. ## Decisions and assumptions
- **DEC-012 pool bounds are applied in G01**, as DEC-012 names G01. Values are the DEC-012 `[ASSUMED]` values. They are settings, so changing them needs no code change. Changing a default still needs a decision, as DEC-007 says.
- **Server notifications are off (`notifications_min_severity="OFF"`).** Reason: the driver logs each notification with the query text. The cost is that the server's warnings (for example a missing label) are no longer reported to the driver. Nothing in this code base depends on them.
- **Migration statement and bookkeeping write run in two managed transactions.** Neo4j rejects a data write in the same transaction as a schema change (`Neo.ClientError.Transaction.ForbiddenDueToTransactionType`). Both steps are idempotent (`IF NOT EXISTS`, `MERGE`), so a crash between them re-runs a no-op statement.
- **Query mode is a label, not enforced by `run_query`.** The caller's transaction type (`execute_read` or `execute_write`) is what Neo4j enforces. `NamedQuery` checks the value at construction. The observer gets the label.
- **Observer is called only after a successful run.** A failed query reports nothing. The prompt says "after each run_query". A failure signal is left to O01.
- **Migration ids** are `0001_resource_id` to `0008_location_position`. The prompt named the constraints and indexes, not the ids.
- **`(:Migration)` has no uniqueness constraint.** The prompt fixes the first eight migrations exactly, so none was added. Two processes starting at once could both record the same id. `MERGE` prevents the duplicate in the usual case, not always. G14 or a later migration can add `Migration.id` uniqueness.
- **`build_for_tests` takes its driver from a fixture.** It no longer creates one. The fixture gives each test one driver and closes it.
- **Logging configuration.** The `neo4j.io` logger writes Cypher at DEBUG. The observability task (O01) must keep the `neo4j` loggers at INFO or above. Recorded here so O01 picks it up.
- **Integration tests delete `(:Migration)` nodes, and one drops an index.** They do this only so the migrations can run again over an existing schema. They run only against an isolated instance, selected by `NEO4J_URI`. The default `bolt://localhost:7687` is the shared stack, which these tests were not run against.
- **Known limitation:** `run_query` passes parameters as keyword arguments to `tx.run(cypher, **params)`. A query parameter named `parameters` would collide with the driver's own argument. No query uses that name. Not changed.
- Neo4j prints a notification for `MATCH (m:Migration)` before the label exists. With notifications off, it no longer does.
