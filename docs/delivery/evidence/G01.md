## Decisions and assumptions
- **Migration statement and bookkeeping write run in two managed transactions.** Neo4j rejects a data write in the same transaction as a schema change (`Neo.ClientError.Transaction.ForbiddenDueToTransactionType`, found on the first integration run). Both steps are idempotent (`IF NOT EXISTS`, `MERGE`), so a crash between them re-runs a no-op statement. This is a choice the prompt did not spell out.
- **Observer is called only after a successful run.** A failed query reports nothing. The prompt says "after each run_query", so a failure telemetry signal is left to O01 if it is wanted.
- **`NamedQuery` checks `mode` at runtime** as well as in the type hint, so a bad mode from data fails at construction.
- **Migration ids** are `0001_resource_id` … `0008_location_position`. The prompt named the constraints and indexes, not the ids.
- **`(:Migration)` has no uniqueness constraint.** The prompt fixes the first eight migrations exactly, so none was added. Two processes starting at once could both record the same id; `MERGE` prevents the duplicate in the usual case but is not a guarantee. G14 or a later migration can add `Migration.id` uniqueness.
- **`create_driver(uri, user, password)` sets no pool options.** The DEC-012 lifetime, liveness and acquisition values belong to G14, which builds on this one function.
- **`build_for_tests` builds its driver from default settings** when none is passed. The driver does not connect until used. Callers close it. Build does not close it either; G14 owns shutdown.
- **Integration tests delete only `(:Migration)` nodes first**, so the migration test can re-run on the same database. They touch no other data. They need `NEO4J_URI` set to an isolated instance; the default `bolt://localhost:7687` is the shared stack, which these tests were not run against.
- **Known limitation:** `run_query` passes parameters as keyword arguments to `tx.run(cypher, **params)`. A query parameter named `parameters` would collide with the driver's own argument. No query uses that name. Recorded here, not changed.
- Neo4j prints a notification for `MATCH (m:Migration)` before the label exists. It is harmless.
