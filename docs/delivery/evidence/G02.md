# Evidence: G02 FHIR-to-graph mapper: resources, primitives, references

Builder: build-G02 · Branch: `task/G02-fhir-graph-mapper` · Prompt: `docs/plan/prompts/G02.md`

## Summary
A pure mapper turns a FHIR R4B resource (dict) into a graph fragment (one node per resource, one relationship per reference, primitives as properties) and back. It covers resources (R1), primitives and lists of primitives (R2), and references with `fhirPath`, `order` and `display` (R3). Unmapped elements raise `UnsupportedElement`. No `json` property is written (DEC-001 overrides R1; see DEC-049).

## Decisions and assumptions
- **DEC-049** (written in this task): the mapper writes no `json` property, following DEC-001 over R1 and prompt test 6. Also: fail-closed refusals, sorted element order, `order` on lists of one, no placeholder target nodes, `meta` limited to `versionId` and `lastUpdated`.
- Open risk for G05, not settled here: datetimes are kept as FHIR ISO strings in the fragment. DEC-001 says Neo4j stores `datetime` values, and a Neo4j datetime does not keep the offset text. G05 must keep the original text or the offset, or the round trip will not return the same string. Published as lesson L58.
- Coverage tests added after green: 7 tests (`test_a_resource_whose_id_is_not_text_is_refused`, six others in section 10 of the file, and `test_a_resource_without_a_resource_type_is_refused`) cover error branches that were not covered at green. They test existing behaviour, not new behaviour, and they pass on their first run. Disclosed here so the verifier can judge them.
- Red-state stub: `mapper.py` at `e8fe913` held the real dataclasses and error classes and `NotImplementedError` bodies (DEC-010).
- Shape rules used: a dict is a Reference only if it has `reference` and only `reference`/`display` keys. Anything else is refused. This is a choice, not from the prompt.
- Contracts: added the mapper names and the node shape to `docs/spec/contracts.md` (Additions, before the DEC-032 section).
