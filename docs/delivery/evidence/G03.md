# Evidence: G03 Mapper: concepts, identifiers, periods and quantities

Builder: build-G03 · Branch: `task/G03-mapper-concepts` · Prompt: `docs/plan/prompts/G03.md`

## Summary
The FHIR-to-graph mapper now turns CodeableConcept codings into shared `Concept` nodes (with `IN_SYSTEM` to `CodeSystem`), Identifier entries into shared `Identifier` nodes (with `IDENTIFIED_BY`), Period, Quantity and Range values into flattened properties on their owner, and copies the ODS organisation code and the filter code (`odsCode`, `measureCode`) to the resource node. A rebuild from the fragment returns the original resource, including the original order of codings, identifiers and concept lists. Every case that cannot be kept exactly is refused with a `DomainError`. Decisions are in DEC-051. Round 2 answers the verify-G03 FAIL on `0edfadc`.

## Decisions and assumptions
- **DEC-051** (new, the number after DEC-050, checked on `main` and every `task/*` branch): concept, identifier, period, quantity and range mapping choices. Item 13 (round 2) records the UCUM exemption and the full IN_SYSTEM check.
- **Deviation from the prompt (R6):** `use` is stored on the IDENTIFIED_BY relationship only, not on the Identifier node. Reason: DEC-049 item 7 forbids a shared value being overwritten. Recorded in DEC-051 item 5.
- **Test folder:** the prompt names `tests/unit/adapters/graph_store/`. The tests are in `tests/unit/adapters/outbound/graph_store/`, which is where G02 put its tests.
- **Refusal and shape rules:** a Period, Quantity or Range is recognised by its keys, and an Identifier by its element name `identifier`. An object with the same keys as a Coding (`system`, `code`) and a non-identifier element name would be flattened as a Quantity. The round trip stays exact. The FHIR type is set by the element name in later tasks.
- **Test changes, all listed here:**
  - Red-commit error, fixed in round 1 (`86957f5`) and corrected in round 2: `test_coding_becomes_code_relationship_to_a_concept_with_an_in_system_link` compared all IN_SYSTEM relationships to one concept. Round 1 narrowed it to one concept, which hid the other two. Round 2 restores the full set of three.
  - Graph-safety helper, corrected in round 3. The original check at `0edfadc` is a `json.loads` test: a string that parses as a JSON object or array is refused. Round 1 (`86957f5`) kept that test but added no other rule. Round 2 wrongly described the original as a prefix test and reintroduced a prefix rule with a broad UCUM exemption. Round 3 restores the exact `json.loads` check for every string, and adds a second rule: a string starting with `{` or `[` is refused, unless it is a strict UCUM annotation in a property whose name ends in `_code` (DEC-051 item 13). The carve-out cannot reach a value that parses as JSON. The round-3 tests went red first (`ad01c21`), then green (`5c7e0cd`). The G02 helper is unchanged.
  - **Tests written after the red commit `b13b5e7`, in the implement commit `86957f5` (round 1). Nine test functions** (parametrised cases make more cases): `test_a_single_identifier_round_trips_with_and_without_use`, `test_a_code_that_is_not_a_codeable_concept_is_kept_and_not_copied_as_a_filter_code`, `test_a_coding_with_a_non_text_or_non_boolean_detail_is_refused`, `test_a_range_part_that_cannot_be_flattened_exactly_is_refused`, `test_from_graph_refuses_a_flattened_property_with_too_many_parts`, `test_from_graph_refuses_a_fragment_whose_element_mixes_reference_and_concept`, `test_from_graph_refuses_a_concept_list_mixed_with_a_single_concept`, `test_from_graph_refuses_codings_of_one_concept_that_disagree_on_text`, `test_a_range_with_only_one_end_round_trips`.
