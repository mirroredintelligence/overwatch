# Evidence: G03 Mapper: concepts, identifiers, periods and quantities

Builder: build-G03 · Branch: `task/G03-mapper-concepts` · Prompt: `docs/plan/prompts/G03.md`

## Summary
The FHIR-to-graph mapper now turns CodeableConcept codings into shared `Concept` nodes (with `IN_SYSTEM` to `CodeSystem`), Identifier entries into shared `Identifier` nodes (with `IDENTIFIED_BY`), Period, Quantity and Range values into flattened properties on their owner, and copies the ODS organisation code and the filter code (`odsCode`, `measureCode`) to the resource node. A rebuild from the fragment returns the original resource, and every case that cannot be kept exactly is refused with a `DomainError`. Decisions are in DEC-051.

## Hazards
- **H-24** (a second copy of a fact can disagree): verified by G03 test references, appended in the same commit as this file. The derived copies `odsCode` (of an Identifier value) and `measureCode` (of a Concept code) are a deliberate exception to DEC-001, set by the G03 prompt. The mapper derives them from the same fragment and never reads them back, so they cannot disagree inside the mapper. G05 must write them from the same fragment, in the same write, and keep them equal. This residual is recorded under "Not done / human-required".

## Decisions and assumptions
- **DEC-051** (new, the number after DEC-050, checked on `main` and every `task/*` branch): concept, identifier, period, quantity and range mapping choices.
- **Deviation from the prompt (R6):** `use` is stored on the IDENTIFIED_BY relationship only, not on the Identifier node. Reason: DEC-049 item 7 forbids a shared value being overwritten. Recorded in DEC-051 item 5.
- **Test folder:** the prompt names `tests/unit/adapters/graph_store/`. The tests are in `tests/unit/adapters/outbound/graph_store/`, which is where G02 put its tests.
- **Refusal and shape rules:** a Period, Quantity or Range is recognised by its keys, and an Identifier by its element name `identifier`. An object with the same keys as a Coding (`system`, `code`) and a non-identifier element name would be flattened as a Quantity. The round trip stays exact. The FHIR type is set by the element name in later tasks.
- **Tests changed after the red commit, in the green commit:**
  - `test_coding_becomes_code_relationship_to_a_concept_with_an_in_system_link` had an assertion that compared all IN_SYSTEM relationships to one concept. It was a test error, and now filters by concept. It did not change the mapper's behaviour.
  - `_assert_graph_safe` (new test file) used to flag any string beginning with `{`. The UCUM annotation `{referral}` is not JSON, so the helper now flags only text that parses as a JSON object or array. The G02 helper is unchanged.
  - Tests added in the green commit to reach 100% branch coverage: `test_a_single_identifier_round_trips_with_and_without_use`, `test_a_code_that_is_not_a_codeable_concept_is_kept_and_not_copied_as_a_filter_code`, `test_a_coding_with_a_non_text_or_non_boolean_detail_is_refused`, `test_a_range_part_that_cannot_be_flattened_exactly_is_refused`, `test_from_graph_refuses_a_flattened_property_with_too_many_parts`, `test_from_graph_refuses_a_fragment_whose_element_mixes_reference_and_concept`, `test_from_graph_refuses_a_concept_list_mixed_with_a_single_concept`, `test_from_graph_refuses_codings_of_one_concept_that_disagree_on_text`, `test_a_range_with_only_one_end_round_trips`. These test refusal paths and corrupt fragments, not new features. The verifier should judge them.
- **G02 tests changed** (`test_mapper.py`): `test_codeable_concept_raises_unsupported_element_with_its_path` now tests an unmapped element inside a CodeableConcept, and the identifier row of `test_other_unmapped_shapes_are_refused` is removed. Both were the refusals that DEC-051 supersedes. No other G02 test changed.
- **ODS URIs are unverified.** Both carry `# VERIFY against NHS England FHIR docs`.
- **`ODS_SITE_SYSTEM`** is defined and tested, but the mapper does not use it for any property. This is intended, pending verification.
- **`FILTER_CODE_PROPERTIES`** has one entry, `("Observation", "code")`, as the prompt gives.
