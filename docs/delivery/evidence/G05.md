# Evidence: G05 Graph writer and reader with versions

Builder: build-G05 · Branch: `task/G05-graph-writer-reader` · Prompt: `docs/plan/prompts/G05.md`

## Summary
`ResourceStore(tx, clock)` writes a FHIR resource (its mapper fragment) into Neo4j in the caller's transaction and reads it back from the graph alone, with `put`, `get`, `history` and `exists`. Versions are graph copies (no json property, DEC-001). Writes are serialised on the root node, so a stale expected version is `Conflict`. Every case round-trips or is refused with `ValidationFailed`, `Conflict` or `NotAllowed` before the graph changes.

## Decisions and assumptions
- **DEC-053** (in `docs/delivery/decisions.md`, numbered after DEC-052, the highest on `main` and all `task/*` branches): layout with `key` on every node; datetimes stored as Neo4j types only when they read back identically; versions as graph copies with ResourceVersion labels; root write lock; shared nodes never overwritten; relationships created, not merged; placeholders; dynamic label queries; `meta.lastUpdated` to whole seconds.
- **Lesson corrections:** L58 said Neo4j does not keep the offset. The probe shows it does (fixed offsets are kept). Published as L61.
- **Prompt deviations:** (1) the prompt's `json` property on `ResourceVersion` and the canonical `json` on get: replaced by graph copies and rebuild (DEC-001 overrides, DEC-049 item 1). (2) `Q-RES-SNAPSHOT` is not a separate query (see DEC-053 item 9). (3) `Patient.address` is not a mapped element, so the Patient privacy test uses the `uprn` extension (DEC-053 item 13).
- **Test changes after red:** (a) the `STAMP` test constant changed from `…00.000Z` to `…00Z` after the first green run (Neo4j refuses `.000`; DEC-053 item 10). (b) The snapshot labels were changed in the implementation after the first green run, so history copies do not match live labels (lesson L62). (c) One test added after green (`test_a_stored_filter_code_is_written_with_its_coded_value`, commit `54773d2`).
