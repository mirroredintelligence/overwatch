# Evidence: G05 Graph writer and reader with versions

Builder: build-G05 · Branch: `task/G05-graph-writer-reader` · Prompt: `docs/plan/prompts/G05.md`

## Summary
`ResourceStore(tx, clock)` writes a FHIR resource (its mapper fragment) into Neo4j in the caller's transaction and reads it back from the graph alone, with `put`, `get`, `history` and `exists`. Versions are graph copies (no json property, DEC-001). Writes are serialised on the root node, so a stale expected version is `Conflict`. A put may carry an idempotency key: a replay returns the same version and writes nothing. Refusals on the input, the shared nodes and the version happen before the lock write, so a refused put leaves nothing in the graph, even if the caller swallows the error and commits.

The idempotency record stores a SHA-256 digest of the request, not the request.

## Decisions and assumptions
- **DEC-053** (in `docs/delivery/decisions.md`, after DEC-052, the highest number on `main` and all `task/*` branches): layout with `key` on every node; datetimes stored as Neo4j types only when they read back identically; versions as graph copies with their own labels; root write lock; shared nodes never overwritten; relationships created, not merged; placeholders; dynamic-label queries; `meta.lastUpdated` to whole seconds (item 10, the `.000Z` to `Z` change of the test constant, kept as recorded); idempotency key (item 15); refused writes leave nothing (item 16); owner decisions and residuals (items 17 and 18).
- **Lesson corrections:** L58 said Neo4j does not keep the offset. The probe shows it does. Published as L61. Also L62 (copies must not carry live labels) and L63 (lock before reading the version).
- **Prompt deviations:** (1) the prompt's `json` property is not stored; reads rebuild from the graph (DEC-001, DEC-049 item 1). (2) `Q-RES-SNAPSHOT` is not a separate query (DEC-053 item 9). (3) `Patient.address` is not mapped, so the Patient privacy test uses `uprn` (DEC-053 item 17a).
- **Test changes after red 1:** the `STAMP` constant changed from `…00.000Z` to `…00Z` (DEC-053 item 10); snapshot labels changed in the implementation (L62); one test added after green 1 (`54773d2`). After red 2, no existing test was altered.
- **Idempotency:** the P15 `IdempotencyStore` does not exist on `main` (`application/idempotency.py` is absent), so the key is recorded by the store itself (DEC-053 item 15).
