# Evidence: G14 Neo4j connection lifecycle, health and recovery

Builder: build-G14 · Branch: `task/G14-neo4j-lifecycle` · Prompt: `docs/plan/prompts/G14.md`

## Summary
One `Neo4jConnection` owns the process's single `AsyncDriver`: it verifies connectivity on `open()`, closes idempotently, hands out sessions that always close, and rolls back failed writes. `neo4j_health` reports `ok` or `degraded`, is bounded by its timeout, and never raises. The container holds the connection, and `startup()` and `shutdown()` open and close it. Recovery was run for real: the Neo4j container was stopped during an in-flight write and restarted, and no partial write survived.

## Recovery timing (test 5, run for real)
Command: `pytest ... -k "in_flight or stopped" --log-cli-level=INFO`, container `diucs-g14-neo4j-1`, `docker stop` then `docker start`. Log: `scratchpad\g14-recovery-timing-2.txt`.
- In-flight write (create node, then loop inside the managed write transaction) failed **32.1 s after `docker stop`** with a retryable error (`is_retryable()` true). That is the driver's default 30 s transaction retry budget, so the failure is bounded.
- First successful call **16.9 s after `docker start`** (1 attempt).
- No partial write: probe count 0 after recovery.
- `neo4j_health` reported `ok` after recovery.
- Health while stopped: `degraded` within the bound (5 s timeout, 2 s margin), and it did not raise.
- Earlier runs of the same tests: in-flight read 31.3 s and first success 17.3 s; in-flight read 32.7 s and 16.4 s. The numbers vary with Neo4j start-up.

## Decisions and assumptions
- Connection, health and container wiring follow DEC-012. The four pool values are the [ASSUMED] defaults.
- `Neo4jConnection` takes the four values as `Neo4jPoolOptions`, a frozen dataclass, instead of reading settings, because adapters may not import bootstrap (import-linter layers contract).
- `pool_connection_count()` reads `driver._pool.connections`, a private attribute of neo4j 6.4.1. It is for tests and diagnostics only.
- The driver's own transaction retry (30 s default) is kept. `run_read` and `run_write` can run a write more than once, so writes must be idempotent (P15).
- `Container.neo4j_driver` is replaced by `Container.neo4j` (a `Neo4jConnection`). Later tasks call `container.startup()` and use `container.neo4j.run_read` or `run_write`. Lessons L12 and L13 cover this and the retry budget.
- Recovery tests need `NEO4J_CONTAINER` and `NEO4J_URI`, and never default to the shared stack. Both fail with a message when unset.
- Per L11 (F10), the harness will own the Neo4j container. This file is not yet on the harness. It must move onto `harness_driver` after F10 is delivered, and the branch rebased again.
