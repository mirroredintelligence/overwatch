## Redis isolation (root cause)
Hypothesis (verifier): the contract's Redis harness deletes every `diucs:*` key at start and close, so concurrent runs delete each other's keys.

Proof, before the fix (two `tests/contract/test_cache_contract.py -k redis` processes at the same time, against the same Redis, 3 rounds, script `scratchpad/overlap.sh`):
| Round | Run a | Run b |
|---|---|---|
| 1 | 6 failed, 17 passed | 6 failed, 17 passed |
| 2 | 1 failed, 22 passed | 3 failed, 20 passed |
| 3 | 2 failed, 21 passed | 4 failed, 19 passed |

Red tests first (`tests/contract/test_redis_isolation.py`, commit `a23cd3b`): both failed with `assert None == 'accepting'`. A new harness deletes another run's key; a closing harness deletes the other harness's key.

Fix (`ed1720c`): `RedisCache(client, key_prefix="diucs:")` (default unchanged). The contract harness uses `diucs-contract-<uuid>:` and flushes only that prefix. The integration suite still flushes `diucs:*`; it is not isolated (see Not done).

After the fix, the same overlap, 3 rounds: every run `23 passed`.
