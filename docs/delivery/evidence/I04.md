## Summary
`IdempotentConsumer` (consumer.py) marks (message id, consumer name) as processed and runs the handler in one Neo4j unit of work, so the marker and the handler's writes commit together or not at all. `ServiceBusRunner` (servicebus_runner.py) feeds it from a queue or subscription and completes, abandons or dead-letters each message by the outcome. Before this task there was no consumer framework.

## Decisions and assumptions
No new DEC. Assumptions: (1) a dead-letter reason is the PermanentError text cut to 100 characters, so a handler must not put payload text in it; (2) the BusMessage `topic` is the entity name (queue or topic), the event type is the Service Bus subject, falling back to the `event_type` application property; (3) only PermanentError dead-letters, so a ValidationFailed from a handler is retried until the bus's max delivery count; (4) no lock renewal for long handlers (the queue lock is one minute); (5) the session path (`sessions=True`) opens `max_concurrency` NEXT_AVAILABLE_SESSION receivers and is not run against the emulator, which has no session-enabled entity in this test; (6) no OpenTelemetry span: no telemetry dependency exists yet (O-series).

## Not done / human-required
