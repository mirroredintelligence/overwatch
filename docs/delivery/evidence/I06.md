# Evidence: I06 Twilio SMS adapter

Builder: build-I06 · Branch: `task/I06-twilio-sms` · Prompt: `docs/plan/prompts/I06.md` · Decisions: DEC-101

## Summary
`TwilioSms` implements `SmsSender` over the Twilio Messages API with an injected `httpx.AsyncClient` and no SDK. It sends a text, turns the provider's answer into a `SendReceipt` or an error from the port, normalises UK mobile numbers to E.164, and maps Twilio status callbacks to `queued | sent | delivered | failed`. Before this task there was no SMS sender for Twilio.

**No live Twilio call was made.** Every test goes through an `httpx.MockTransport`. No real credential, account SID, token or phone number was used. The live send path is human-only (see "Not done / human-required").

## Privacy
- Scan of the diff for UK postcode shapes, NHS-number shapes and titled names (`git diff main -- backend docs`): the only matches are the sample number `07700 900123` (the Ofcom drama range) and its E.164 form `+447700900123` in tests and docstrings, plus the placeholder `AC` and 32 zeros. No real number, name or postcode.
- The adapter logs the message id, the Twilio sid, the status code and the provider error code. A test reads the log and asserts the number, its E.164 form, the body and the token are absent.
- Refusal and error messages carry the status and the code only. `to_e164_uk` never echoes its input.

## Decisions and assumptions
All decisions are in `docs/delivery/decisions.md` as DEC-101. Summary:
- The I06 prompt's "Open decision: Twilio or GOV.UK Notify" is settled by DEC-002 (Twilio fixed, I16 cancelled). No provider switch is built.
- httpx moves from the dev group to runtime dependencies. It is already locked at 0.28.1; the lock change is metadata only. R01 (DEC-070) will also touch `pyproject.toml`.
- A listed refusal returns `SendReceipt("", False)`: Twilio issued no sid, so the provider id is empty.
- Other 4xx and unexpected answers raise `SendFailedError` (not retried), so a bad token stops sending loudly.
- `to_e164_uk` reuses `normalise_uk_mobile` (identity port) and adds only the bare 44 form. Landlines are refused.
- Status mapping: `sending` maps to `queued`, `undelivered` to `failed`. Unknown status or a missing field is `ValueError`.
- Settings: `twilio_account_sid`, `twilio_auth_token` (SecretStr) and `twilio_from` are added, unset by default. The prompt's `public_base_url` is not added; the existing `base_url` is the public base, so there is one source for it.
- `DeliveryUpdate`, `TransientSendError` and `SendFailedError` are in `messaging.py`, and the contracts "Additions" table lists them.
- Assumptions: the Twilio error codes, status names and form fields are taken from the prompt, not from live Twilio documentation.
- No `[ASSUMED]` constants from `domain-rules.md` are used.
