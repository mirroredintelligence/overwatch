# Evidence: I07 SMS inbound webhook

Builder: build-I07 · Branch: `task/I07-sms-inbound` · Prompt: `docs/plan/prompts/I07.md` · Decision: DEC-149

## Summary
Twilio texts and delivery receipts now reach the system through `POST /webhooks/sms/twilio` and `POST /webhooks/sms/twilio/status`. The tenant is resolved from the number called and the Twilio `AccountSid` through a port (a fake number-to-tenant map until TEN-007 and TEN-041), the signature is verified with that subaccount's token over the public URL from settings, and only then is the tenant bound. Unverified and unknown requests get one identical 403. A verified text from a registered sender is queued on `inbound.replies` with the tenant, a tenant-prefixed one-day replay marker, and the answer to Twilio is empty TwiML. No real message is sent; no credential is in the repo (tokens in tests are made-up strings).

## Tenant isolation
- **Tenant-scoped, added by this task.** The replay key `idem:sms:<tenant>:<MessageSid>` (built in `replay_key` from the bound tenant, one function); the `tenantId` property of every queued message (`BusMessage.tenant_id`, sent by `to_service_bus_message`). No Cypher added. No new global singleton, counter or unique key.
- **Where the tenant comes from.** The inbound number (`To`) and `AccountSid` choose a line in `InboundLineDirectory`; the line's secret reference gives that subaccount's auth token; the request signature is verified over the public URL; only then `bind_tenant`. Never from the sender, body, query string, header or host (test: `test_a_tenant_in_the_body_a_header_or_the_host_changes_nothing`). Receipts: `AccountSid` alone, with the same signature check.
- **Two-tenant tests** (`tests/integration/adapters/inbound/sms_webhook/test_tenancy.py`): the same sender and the same `MessageSid` on tenant A's and tenant B's numbers give two queue messages, one per tenant, with separate replay markers, and a repeat of either is a replay of that tenant only; A's number signed with B's token (and the reverse) is refused; B's number under A's account is refused; every refusal (unknown number, unknown account, wrong account for the number, bad signature, no signature, missing or malformed `To` or `AccountSid`) is byte-identical, so nothing says which numbers or tenants exist; no unit of work is opened for a refused request; the tenant is bound while the allow-list read runs and unbound after; a line with an invalid tenant id or no token in the secret store is refused like an unknown number. `test_status.py::test_a_receipt_of_the_other_tenant_is_queued_for_that_tenant_only` covers receipts.
- **Predicate-removal analogue.** There is no tenant predicate in new Cypher. The mutants that stand in for it, each killed by a test: `bind_tenant` removed, the tenant removed from the replay key, the tenant taken from the body, the account ignored when the number picks the line, the signature check disabled, an unknown number answered 200 (see Mutation check).
- **Tenant-pending statements.** `Q-PERSON-PHONE-FIND` (through `uow.people.find_by_phone_hash`): unconverted (no `$tenant`, DEC-144 item 3), so the allow-list lookup is not filtered by tenant in Neo4j; a person who is in the graph is found for any tenant's number until the statement is converted. The route binds the tenant before it runs, so converting it needs no change here. The unit of work opened for the read touches the other repositories only by construction; nothing else is read or written.
- **Fakes standing in for TEN-007 and TEN-041.** `FixedInboundLines` (a number-to-tenant map) is the only `InboundLineDirectory`; `FixedSecretStore` holds the tokens. The port is where TEN-041 plugs in. Real subaccounts, numbers and tokens are "needs a real credential at deploy".
- **Cross-scope reads this task would need under DEC-132:** none.

## Decisions and assumptions
DEC-149 (all items). The departures from the prompt: an unknown number gets the 403 a bad signature gets, not a 200 with empty TwiML (a 200 against a 403 would let a caller tell tenants' numbers from other numbers); the replay marker and queue send needed two port methods (`Cache.set_if_absent`, `EventBus.enqueue`) and an optional `BusMessage.tenant_id`; collaborators are read from `app.state.sms_webhook`. Assumed: 1,600 characters, 64 KiB and 100 fields as limits; Twilio statuses that I06 does not map are dropped with 200; a text with no usable field is dropped with 200, not refused. Names added to `docs/spec/contracts.md` (section "Inbound SMS webhook") and `architecture.md` F1 and the allow-list bullet updated.
