## Summary
A reporter's one-tap link now works end to end: `GET /links/{token}` shows what is on record and changes nothing, `POST /links/{token}` records a confirm, a new number or "closed" through `ConfirmCapacity` or `ReportCapacity` exactly once (hazards H-31 and H-32 and the report flags apply as for a text), and `POST /links/{token}/renew` queues a fresh prompt. The tenant comes from the request host through the tenant directory, a link is found only in the tenant it was issued in (the four `Q-LINK-*` statements are converted), every failure has one fixed body, and no token, hash, figure or address reaches a response, a header, a record or a log.

## Tenant isolation
**Tenant-scoped statements this task adds or converts:** `Q-LINK-ADD`, `Q-LINK-GET`, `Q-LINK-MARK-USED`, `Q-LINK-BURN-KEY` (each writes `tenantId: $tenant` on the node it matches or creates, has a scenario, and left the ratchet: 101 to 97). No other Cypher is added. **Keys and messages:** the replay key `link:<tenant>:<hash>` and `renew:<tenant>:<hash>` (the replay statements are unconverted, L160), the rate-limit keys `diucs:linkpage:<tenant>:<kind>:<part>` (built in one function, the address hashed), the outbox message of a renewal (stamped by the unit of work, sealed with this tenant and role as associated data). **Where the tenant comes from:** the request host through `TenantDirectory.by_host`, active tenants only, bound once at the edge (`bind_tenant`, in `BINDING_MODULES`); never the path, query, body or any other header (a body field that names one is refused with 400); the use cases read it from the unit of work (`TenantNotBound` if none or a network). **Two-tenant tests:** `test_capacity_links_tenants.py` and `test_link_access_tenants.py` (on a contracted container): tenant A cannot read, answer, renew or burn B's link and gets exactly the answer a link nobody holds gets, B's link is untouched and works in B, a tenant in the query, header or body changes nothing, the budgets are separate; `test_link_token_repository.py`: B cannot get, mark or read A's token, and B cannot store A's hash (it stays globally unique by design, DEC-131 item 5); the generated `test_tenant_isolation.py` runs the four statements. **Predicate-removal mutants:** M1 and M2 above (the tenant kept in the RETURN, L161): killed by the repository test, and by the generated test. **Tenant-pending statements** (unconverted, so not filtered by tenant in Neo4j; what holds another tenant's records back is that a link is found only in its own tenant and its ids are its own tenant's): the Communication reads (`Q-COMM-GET`, `Q-COMM-LATEST-PROMPT`, `-ADD`), the capacity statements (`Q-CAP-LATEST`, `-LOCK-SERVICE`, `-TRAILING-CONFIRMS`, `-SINCE`), the person statements (`Q-PERSON-PHONE-FIND` and the role reads), the flag statements, the replay statements (`Q-IDEM-*`), the audit chain, the outbox lock; the service read is the resource store's (converted by TEN-009). The two-tenant tests give each tenant its own service id and reporter phone for that reason. **Cross-scope reads this task would need under DEC-132:** none: a link concerns one tenant's one service. **Global statements:** none added (DEC-134 item 9's link-hash lookup is not needed, DEC-167 item 1).
