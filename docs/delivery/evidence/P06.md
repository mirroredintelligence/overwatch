# Evidence: P06 Outbox and unit of work on Neo4j

Builder: build-P06 · Branch: `task/P06-outbox-uow` · Prompt: `docs/plan/prompts/P06.md`

## Summary
The change, its audit entry and its outbox messages now commit together or not at all, on one Neo4j explicit transaction per unit of work. The outbox stores messages as platform nodes with typed payload properties (no JSON, DEC-001). A write that raised `Conflict` can never be committed, even if the caller caught it (DEC-083 item 9). The container hands out the unit of work on its one connection, and `uow_factory` is the test fixture every use-case test takes.

## Decisions and assumptions
Decisions are in `docs/delivery/decisions.md` as **DEC-084** (one entry, items 1 to 9). Summary:
1. Payload stored as typed `payload_<field>` properties; null fields in `payloadNulls`; canonical UTC instant text stored as datetime and read back identically (DEC-001 item 1). The prompt's `payloadJson` is not built.
2. Write guard (item 3): a `Conflict` from any repository marks the unit of work refused; commit then rolls back and raises `Conflict`. Residual: Neo4j errors that a repository does not map to `Conflict` are not marked.
3. Registry (item 5): 17 factories, the 14 port names plus `contacts`, `pins`, `devices` for P16 (DEC-071 item 9).
4. Audit factory (item 6): provenance time uses the system clock, since the factory signature has no clock. No provenance write path exists yet (DEC-055 item 18).
5. Outbox (item 7): published is idempotent; dead cannot be published; `mark_failed` on a published message counts the attempt and keeps the status.
