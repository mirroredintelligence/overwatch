# Evidence: P10 Link token, secret and phone-hash ports with Neo4j token store

Builder: build-P10 · Branch: `task/P10-link-token-ports` · Prompt: `docs/plan/prompts/P10.md`

## Summary
The link-token store exists. `LinkTokenService` issues, resolves and burns single-use tokens; the Neo4j store holds only the token's keyed hash. A phone field holds only a 64-character hex hash, refused at the record and again at the repository before any write (H-09, DEC-047). A retried burn with the same key returns the original result without a second write (DEC-012). The stored `mark_used` takes the write lock first, so concurrent callers cannot both win (DEC-060 item 4).

## Tests added after the first green run (written after the implementation)
These five were written after round-1 green (`627a9bb`), in `76f5490`, to cover branches the first green run did not reach. Each was added after the implementation existed:
- `test_a_number_that_is_not_text_is_refused` (`test_identity.py`): a non-text phone number is refused with ValidationFailed on the phone field. Purpose: the one branch of `normalise_uk_mobile` that handles a non-string.
- `test_burning_malformed_text_is_not_found_and_writes_nothing` (`test_link_token_service.py`): text that cannot be a token is NotFound on burn and writes nothing. Purpose: the malformed-burn branch of the service.
- `test_an_empty_secret_is_refused_and_never_used_as_a_key` (`test_link_token_service.py`): an empty secret raises ValidationFailed on the secret field. Purpose: an empty HMAC key must not be accepted.
- `test_two_racing_adds_of_one_hash_store_one_node_and_refuse_the_other` (`test_link_token_repository.py`): two concurrent adds of one hash store one node and refuse the other with Conflict. Purpose: the race outcome of duplicate adds.
- `test_a_duplicate_the_precheck_missed_is_still_a_conflict` (`test_link_token_repository.py`): with the existence check forced to miss, the unique constraint still refuses the duplicate as Conflict, and one node remains. Purpose: the constraint-to-Conflict mapping, which the race test reaches only by timing.

Also changed after the first green run (recorded here so the verifier can see them): the property-set assertion (Neo4j stores no null property, so an unused link has no `usedAt` key), and the concurrency test widened from 3 rounds of 8 to 5 rounds of 16 callers, made in the same edit as the first query change, after that query had failed the 8-caller test.

Changed in round 2: the `_burn` helper and the replay tests; `test_a_second_burn_is_a_conflict_and_changes_nothing` was renamed `..._with_another_key_is_a_conflict_...` and now uses a different key for the second attempt (the original same-token second-burn test is still true for a second attempt by another caller).
