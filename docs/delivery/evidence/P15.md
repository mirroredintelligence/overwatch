# Evidence: P15 Idempotency store and processed-message markers on Neo4j

Builder: build-P15 · Branch: `task/P15-idempotency-store` · Prompt: `docs/plan/prompts/P15.md`

## Summary
Command results can now be stored under a command key and replayed without a second effect, and
consumers can mark a message as handled once per consumer. Both are Neo4j-backed, join the unit of
work (`uow.idempotency`, `uow.processed`), and are guarded by unique keys and held-transaction
race tests. The prompt's JSON result text and composite uniqueness are not used (DEC-090 items 1
and 5).

## Decisions and assumptions
- DEC-090 (`docs/delivery/decisions.md`) records the decisions. Items:
  1. No JSON result text is stored (DEC-001 overrides the prompt's `resultJson`). The result is a
     typed node tree.
  2. Decoding allows `diucs.application` and `diucs.domain` (deviation from the prompt, which says
     application only). Reason: results carry domain enums (`Role` in `Actor` in `AuditEntry`).
     Test: `test_a_domain_enum_nested_in_a_result_decodes_as_itself`.
  3. Results must be dataclasses or enum members, and encode refuses naive datetimes, dicts and
     other types at the first write.
  4. Put is idempotent for an equal result, Conflict for a different one, and first-write races
     are Conflict through the unique key.
  5. The prompt's composite uniqueness does not exist on Community (lesson L90). The processed
     marker has one unique key, `<len(consumer)>:<consumer>:<messageId>`, and stores both values.
  6. A racing second mark waits and then returns False (it matches the committed marker).
- Test expectations corrected in Red 2 (`bdfb2bc`), before any implementation commit:
  (a) the London round trip compared a fold-ambiguous local time with a UTC instant; PEP 495 makes
  that inter-zone comparison unreliable, so the test now compares with `astimezone(UTC)`;
  (b) the held racing mark expected Conflict, but the MERGE waits and returns False (item 6).
  The racer in the sixteen-put test rolled back after a successful commit, a harness bug, fixed in
  Red 2 as well. Red 3 (`0c8fcc4`) updates the registry's expected names to include the two new
  factories, which the existing assertion pinned to 17 names.
- Assumed: `mark_if_new` raises Conflict when a racing first mark is refused; the caller must
  not commit (lesson L106). The consumer task (I04) must treat Conflict as retry-later.
- Assumed: the database writes `createdAt` and `processedAt` in UTC (no clock argument on the
  ports, the same as DEC-084 item 7).
- Open, not changed: the header of `graph_store/migrations.py` says composite UNIQUE works on
  Community. Lesson L90 contradicts that. The file is shared; the owner should reconcile it.
