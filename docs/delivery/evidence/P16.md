## Verifier findings, and what changed
1. **Credential race: not accepted (DEC-074, supersedes DEC-073 item 3).** Migration 0026 makes `Credential.deviceId` unique. `get` fails closed on two rows, and a constraint error on `set_pin` is a Conflict. The proof is deterministic: a raw second CREATE raises (M1). Nine clean runs were never evidence.
2. **Racing `set_pin` test: deleted.** It passed without the fix, so it guarded nothing. The deterministic tests above replace it.
3. **Contact race guard: order-dependent (fixed).** The timing race test failed alone without migration 0025 but passed in the full file, because whether 16 timing racers interleave depends on run order and timing. It is replaced by a deterministic interleaving test: the first write is held uncommitted while the second runs. Without the key the second write creates a second node (M2 alone: `assert 2 == 1`). Each contact and credential test applies the schema with `apply_migrations` first, which is idempotent.
   Disclosure: the interleaving test was added after the guard it proves existed (round 2), and was shown failing by mutation M2, not by a red run. The deterministic contact test was committed in Red 3 and passed there, because the key already existed.
4. **Lesson.** L94 updates L92 (an update, since the ledger is append-only). It records that a race test's timing is not a guard, and the interleaving pattern.
