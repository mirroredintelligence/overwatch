## Decisions and assumptions

- DEC-086 (error bodies, body types, unexpected errors) and DEC-087 (app wiring, metadata registry, API fixtures). Both are "accepted, for the owner to confirm", written by build-R01b.
- Prompt deviations, each recorded in DEC-086 or DEC-087:
  - The 415 code is `not-supported`. The prompt's error list does not name one (DEC-086 item 1).
  - `api_app` is a fixture of its own, so route tests can add test-only routes. The prompt names only `test_container` and `api_client` (DEC-087 item 6).
  - `api_client` uses `httpx.ASGITransport(app=api_app)` with default exception handling. The unhandled-error middleware, not the transport, turns an error into a 500.
  - F08's `build_for_tests` requires `neo4j=` as well as `clock=`, so the fixture opens a `Neo4jConnection` on the harness container. This is the same pattern F08 uses (DEC-087 item 6).
  - `create_app` takes an `ApiContainer` Protocol, because the layers contract forbids adapters from importing bootstrap (DEC-087 item 1).
  - The app does not call `container.startup()` or `shutdown()`. The serving process owns that (DEC-012, DEC-087 item 2).
  - OpenAPI pages are off (DEC-087 item 3).
  - `GET /fhir/metadata` reads the clock from `request.app.state`, not from `app.py`'s `get_container`, to avoid an import cycle (`app.py` imports `capability.py`).
- Names: the prompt says "use them exactly" for contracts. `docs/spec/contracts.md` is not edited, because the orchestrator's brief says not to edit `docs/spec` source files. The R01 names are recorded in DEC-087 item 8 instead. The owner should add them to the Additions section.
- Assumption: `Content-Type` missing on POST or PUT is treated as an unaccepted body type (415).
