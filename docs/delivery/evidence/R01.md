Builder: build-R01b · Branch: `task/R01-fhir-rest-skeleton` (from `main` at 54a0d50) · Prompt: `docs/plan/prompts/R01.md`

## Summary

The FHIR REST app exists. `GET /health` returns `{"status": "ok"}`. `GET /fhir/metadata` returns an R4B CapabilityStatement (4.3.0), dated from the container clock. Every error under `/fhir` is an OperationOutcome. A POST or PUT with a body type other than `application/fhir+json` or `application/json` gets 415. An unexpected error gets a 500 that logs the exception class name only. The API test fixtures (`test_container` on the harness Neo4j, `api_app`, `api_client`) are in place. There are no business routes.

## Decisions and assumptions

- DEC-086 (error bodies, body types, unexpected errors) and DEC-087 (app wiring, metadata registry, API fixtures, httpx to dev). All are "accepted, for the owner to confirm", written by build-R01b.
- Prompt deviations, each recorded in DEC-086 or DEC-087:
  - The 415 code is `not-supported`. The prompt's error list does not name one (DEC-086 item 1).
  - `api_app` is a fixture of its own, so route tests can add test-only routes (DEC-087 item 6).
  - `build_for_tests` needs `neo4j=` as well as `clock=`, so the fixture opens a `Neo4jConnection` on the harness container (DEC-087 item 6).
  - `create_app` takes an `ApiContainer` Protocol, because the layers contract forbids adapters from importing bootstrap (DEC-087 item 1).
  - The app does not call `container.startup()` or `shutdown()`; the serving process owns that (DEC-087 item 2).
  - OpenAPI pages are off (DEC-087 item 3).
  - httpx is a dev dependency, not a runtime one: a deviation from DEC-070 item 1, recorded in DEC-087 item 9.
- Names: `docs/spec/contracts.md` is not edited, because the orchestrator's brief says not to edit `docs/spec` source files. The R01 names are in DEC-087 item 8 for the owner to add to Additions.
- Assumption: a missing Content-Type on POST or PUT is treated as an unaccepted body type (415).
