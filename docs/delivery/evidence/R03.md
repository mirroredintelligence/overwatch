# Evidence: R03 ETag, If-Match and Idempotency-Key handling

Builder: build-R03 · Branch: `task/R03-etag-idempotency` · Prompt: `docs/plan/prompts/R03.md`

## Summary
Reads of a versioned resource return `ETag: W/"<versionId>"`. A PUT needs If-Match (428 when missing, 412 when stale or malformed). A POST needs Idempotency-Key (400 when missing or invalid). A repeat with the same key and body is answered from a 24-hour cache without running the use case; a different body is 422; the use case's durable IdempotencyStore (P15) stops a second record after the cache entry expires. No production write route uses this yet: the first is R04.

This branch was rebuilt from main after the verifier's FAIL at `c14ec1c` (old tip kept on `backup/R03-tip-c14ec1c`). The rebuilt red commit holds every guard test, including the held-write, returned-failure, missing-cache and unreadable-entry tests.
