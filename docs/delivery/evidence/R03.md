# Evidence: R03 ETag, If-Match and Idempotency-Key handling

Builder: build-R03 · Branch: `task/R03-etag-idempotency` · Prompt: `docs/plan/prompts/R03.md`

## Summary
Reads of a versioned resource return `ETag: W/"<versionId>"`. A PUT needs If-Match (428 when missing, 412 when stale or malformed). A POST needs Idempotency-Key (400 when missing or invalid). A repeat with the same key and body is answered from a 24-hour cache without running the use case, a different body is 422, and the use case's durable IdempotencyStore (P15) stops a second record after the cache entry expires. Nothing in production calls these yet: the first real write route is R04.

## Privacy

The replay cache stores a request digest and the response of a create; no request body is stored. Residual (DEC-101 item 5): a create route's response body is held in Redis for 24 hours, so every create route from R04 must keep patient detail out of its response.
