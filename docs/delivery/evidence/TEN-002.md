# Evidence: TEN-002 Unit of work, connection and health on the scoped transaction

Builder: build-B1a · Branch: `task/B1a-uow-harness` (bundle B1a with TEN-003; built first) · Prompt: `docs/plan/prompts/TEN-002.md` (its warn and enforce parts are superseded by DEC-142 item 7 and DEC-144 item 8) · Decision: DEC-146

## Summary
A unit of work now binds exactly one scope and keeps it. `Neo4jUnitOfWork` reads the scope bound in the context once, when it is entered, wraps its transaction in a `ScopedTx` that carries that scope, and every repository and the resource store run on the `ScopedTx`; `run_query` takes the scope from the `ScopedTx`, so rebinding the context afterwards changes nothing for that unit. Entering a second unit while one is open in the same context raises `UnitOfWorkAlreadyOpen`. `DriverIdempotencyStore`, `ensure_audit_head` and two new `Neo4jConnection` helpers (`run_scoped_read`, `run_scoped_write`) read the scope once before the session opens and carry it on a `ScopedTx`, so a driver retry uses the same scope. The health ping (global since TEN-001) and the migration runner stay on the global path. Nothing is converted or stamped: no existing statement is isolated by this task.
