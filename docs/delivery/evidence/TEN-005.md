## Decisions and assumptions
DEC-159 (see `docs/delivery/decisions.md`). Where the prompt and the code on `main` differed, the prompt is followed except for:
1. The prompt says the generated test passes unchanged and that TEN-004's `contracted_container()` exists. TEN-004 was built as DEC-150: on the shared schema with `Unique` values, and no `contracted_container()`. The orchestrator's brief for this task asks for the scenarios to share every key and for the tables to be emptied; that cannot be proved on a schema that keeps the old single-property keys (this task is expand-only), so the test now runs on a private contracted container that this task builds (DEC-159 item 2). `SINGLE_PROPERTY_UNIQUE` is not emptied: it keeps `link_token_hash`, which the prompt itself leaves global.
2. The prompt says the exemption glob `migrations*.py` covers the new modules. The architecture test now names the files that may run Cypher (three) and a new `migrations_x.py` that runs Cypher is flagged (a known issue of TEN-001, closed).
3. The 0031 statements are written out literally instead of generated, because the architecture rule forbids Cypher built from pieces anywhere in `src` (DEC-144 item 7). A unit test reads each back against its row.
4. `migration_loop.py` is a fourth addition to the plan's file list (beside `migration_types.py`, `test_migration_runner.py`, `test_tenant_migrations.py`), so the runner and `backfill_default_tenant` share one loop.
5. `invariant_violations` returns `{"unstamped_nodes": [...], "cross_scope_relationships": [...]}` (the prompt names no keys).
6. A loop that returns a boolean or a float for `changed` is a failure (the prompt says "an integer").
No `[ASSUMED]` value was used. No consult of another model was made.
