## Decisions and assumptions
- **DEC-106** (new): a stored key is decided before the other checks and again inside the unit of work. Amends DEC-104 item 4.
- **DEC-100 item 2** is now implemented (`replaced_value` range check).
- **ValueError branch, changed to DomainError (`c9785d3`).** `execute` raises `DomainError` if `next_due` returns `None`. The prompt's convention is that every deliberate error subclasses `DomainError`; the first version used `ValueError` and was a deviation, now corrected. It is a `DomainError` base, not a `ValidationFailed`, because no field is at fault. **Deviation:** the prompt asks for a subclass of `DomainError`; the raise uses the `DomainError` base class itself. The test catches `DomainError` and matches the message, so the behaviour is covered, but the exact type is not pinned. No valid profile reaches this, so `test_an_echo_with_no_next_prompt_is_refused_and_writes_nothing` replaces `next_due` to build the state and checks that the error is raised and nothing is written. The test passes; it is not red.
