# Evidence: U04 Grouped prompts for multi-service phones

Builder: build-U04 · Branch: `task/U04-grouped-prompts` · Prompt: `docs/plan/prompts/U04.md`

## Summary
When a prompt is due for a service whose reporter's phone also holds other services due within 10 minutes, `SendPrompts` now sends that phone one lettered C9 text instead of one text each, stores the records U05 reads, and makes the other services' own jobs do nothing. A single-service prompt is unchanged (all 45 U03 tests pass). Decision: DEC-158 (13 items).

## Tenant isolation
**Tenant-scoped statements, keys, channels, queues and messages this task adds:** none. No Cypher, no cache key, no channel and no queue is added. The idempotency keys `prompt:<service>:<due>` are stored through the idempotency store, which scopes them (as for U03). The `SendMessage` is the U03 message sealed under the tenant given to the use case (DEC-116); a grouped message is sealed the same way. **Where the tenant comes from:** the unit of work's bound scope (the consumer binds it from the message property, DEC-130); the use case takes no tenant from a command and its constructor `tenant_id` only seals content, as for U03. The other services of the phone are found by `uow.people.services_for_phone_hash`, so only the bound tenant's are seen. **Two-tenant test:** not written, and why: no node carries `tenantId` yet (the resource store and the mapper do not stamp it, TEN-009), so a second tenant's phone, with the same hash and the same service ids, cannot be seeded apart. Known issue recorded, with the trigger (TEN-009 and TEN-011). **Predicate-removal mutant:** n/a, no statement added. **Tenant-pending statements** (all on the ratchet, none added or converted here): `Q-PHONE-SERVICES-HELD`, `Q-PHONE-SERVICES-AT` (the lookup of the phone's other services), `Q-COMM-ADD`, `Q-COMM-LATEST-PROMPT` and the service, flag, capacity, scheduled-work, outbox, audit and idempotency statements the use case already reached. **Cross-scope reads this task would need under DEC-132:** none: a phone, its services and its reporters are one tenant's, and the network board is not read.
