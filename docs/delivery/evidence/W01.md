# Evidence: W01 BFF foundations: typed FHIR client and MSW test setup

Builder: build-W01 · Branch: `task/W01-bff-foundations` · Prompt: `docs/plan/prompts/W01.md`

## Summary
The front end now has one typed server-side client for the back end's FHIR R4B API (`fhirFetch`, `FhirError`), a `toBffError` that turns any thrown error into a code and a fixed message, a W3C `traceparent` generator, and an MSW server that fails any test which makes an unmocked request. Nothing calls the back end yet; route handlers come in W02 onward.

## Decisions and assumptions
- **DEC-109** (in `docs/delivery/decisions.md`): msw 2.15.0 pinned exactly rather than 3.0.3; fixed error messages per status (placeholder API text, not screen wording); a 2xx body that is not JSON is a 502 FhirError; `init` is optional and `method` defaults to GET, or POST with a body.
- `msw` added to `frontend/package.json` (devDependency, `2.15.0`) and `pnpm-lock.yaml` in the red commit, so the red tests can import it.
- `test/setup.ts` already existed and is wired through `vitest.config.ts`; the MSW lifecycle was added there, so `vitest.config.ts` is unchanged.
- The `FhirError` constructor, the `types.ts` declarations and the `server.ts` setup were written in the red commit: they hold no behaviour (DEC-010).
- `lib/fhir/types.ts` is minimal: `Resource`, `Coding`, `CodeableConcept`, `Reference`, `OperationOutcome`, `Parameters`, `Bundle<T>`. Later tasks extend it.
