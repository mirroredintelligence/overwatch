## Summary
The BFF now has an encrypted HttpOnly session cookie (`diucs_session`), a double-submit CSRF check (`diucs_csrf`, header `X-CSRF-Token`, constant-time), a `withBff` wrapper for role and CSRF checks, and `GET`/`DELETE /api/bff/session`. No sign-in exists yet (W09); tests mint sessions with `sealSession`.

## What was wrong the first time (rework after failed verification)
The first verification failed. Findings, all accepted:
1. `session.test.ts` "returns null for a modified string" flipped the last character of the ciphertext segment. Those low bits are unused base64url padding, so the token was sometimes unchanged and the test failed about 1 run in 8. It is now a change in the middle of the segment.
2. The evidence claimed the mutant "contentEncryptionAlgorithms restriction removed" was killed. It was not: the algorithm test sealed with a 16-byte key and failed on the key whatever the pins were. Removing either pin or both survived. New tests seal with the real 32-byte secret.
3. Moving the `SESSION_SECRET` check after the empty-cookie early return survived. Tests now require a throw (session) and a 500 (withBff) for no cookie with a missing or malformed secret.
4. The red-run text was partial and typed from memory. It is replaced below by a literal re-run.
5. Minor: a dead branch in `test/cookies.ts` was removed; thrown-error responses from `withBff` now send `Cache-Control: no-store` (done in `withBff`, not in `lib/bff/errors.ts`, which belongs to another task).
