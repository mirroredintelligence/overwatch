# Evidence: W04 Capacity link pages

Builder: build-W04 · Branch: `task/W04-capacity-link-pages` · Prompt: `docs/plan/prompts/W04.md`

## Summary
The one-tap capacity link pages now work: a reporter opens `/l/[token]` from a text or email, sees the figure on record with its time (or, with none, asks for a number), and confirms, sends a new number or says closed with one press. The thank-you page shows what was recorded and when. An expired, used or unknown link shows one identical message, and the page offers a new link. The browser reads each link through the BFF (`/api/bff/links/[token]`), which forwards the page's host to the back end so the tenant is the host the link was sent to. Nothing else leaves the page's own origin.

## Decisions and assumptions
Decision **DEC-172** (`docs/delivery/decisions.md`) records every open choice. Summary of what differs from the prompt, and why:
- **Read path (DEC-172 item 1):** the page reads the link through the BFF from the browser, not from its server component. Next.js allows cookie writes only in Server Actions and Route Handlers, and two back-end reads per view would exhaust the 60-a-minute link budget (DEC-167 item 8) in a prompt wave.
- **Shapes (item 4), as L01 built them:** out-of-range is 422 (the prompt says 409 with `code`); a refused confirm is 409 `send-number`; a 410 has no time, so "It closed at 12:30" is not shown; GET has `replyBy`, `asOf`, `nextDue`, `csrfToken`, not `expiresAt` and `recordedAt`.
- **Wording (items 5, 6, 8):** the unit is shown as the back end sends it ("in the next 2 hrs", not "2 hours"), so the page says what the text said; expired copy is the same for expired, used and unknown; an outage is a separate message.
- **Button (item 12):** `components/ui/Button.tsx` (a W03 file) gains an additive `disabled` prop.
- **"See the live board"** links to `/sign-in` (W09). Until W09 is delivered the link is not found.
- **Assumptions:** `DIUCS_FHIR_BASE_URL` ends in `/fhir` in every environment (`backendRoot` refuses it otherwise). The Host the browser sends is the tenant's host, which the deployment must preserve through its proxy (DEC-167 item 1).
