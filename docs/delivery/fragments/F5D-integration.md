# F5D integration fixes (two failures of the final full run)

## What the run found

- `test_tenant_directory.py::test_no_global_statement_returns_anything_from_a_graph_that_also_holds_data`: the set of ids it covered was the tenant directory's eight statements, the ping and the two invariant counts. TEN-051 put nineteen network registry statements on `GLOBAL_QUERY_IDS` and the test's own completeness assertion (right) caught it. The test now exercises the eleven registry reads as well, in a world that holds a network, its memberships, a grant and a listing and, for each of the two tenants, data nodes that carry the registry's ids and keys and the marker: each read must answer a row and nothing from a data node (no marker, no `tenantId` in a row). The eight registry writes cannot be shown by "answers nothing" (they answer an id) and need their own world, so they are a named set, `WRITES_TESTED_IN_THEIR_OWN_WORLD`; `test_network_registry.py::test_a_write_statement_changes_no_node_that_is_not_a_registry_node` runs each of them against a lookalike tenant node. `assert_every_global_statement_is_accounted_for` requires the allowlist to be exactly the union of the exercised reads, the whole-graph counts, the ping and the named writes, with no id in two sets, and that the named writes equal `GLOBAL_WRITE_IDS`; a new global statement, read or write, fails it by name until it is exercised or named. A second test shows the guard refuses an unlisted id and an id in two sets.
- `test_person_scope_tenants.py::test_a_seeded_relationship_keeps_the_properties_it_is_given`: `seed_tenant` ended with a whole-database scan for a node with no tenant. Five `TestMark {messageId: 'm-1'}` nodes with no `tenantId` were on the shared Neo4j. Their only creator was the idempotent consumer test before TEN-035 (`CREATE (:TestMark {messageId: $id})`, commit 51baf20 stamps it); the current test creates them with the run's tenant and `clean_graph` removes them (checked: a run of `test_consumer.py` leaves the count unchanged). They were left by runs of branches that still had the old test against the shared container. No current test creates an unstamped node.

## Fix

- `tests/support/tenant_seed.py`: the seed's check is now on the seed's own work. The seed statement counts the nodes it created and the nodes among them that carry a `tenantId`, in the same transaction, and `seed_tenant` fails unless both equal the seed's node count. The whole-database scan stays, but only on a database the run owns (`is_owned`, a private container); on a shared database another run's or an earlier run's unstamped node is not the seed's doing. The invariant that seeding never creates an unstamped node is kept, and is stricter than before: the old scan only saw a node that was joined to nothing if it was on the whole database.
- Debris: the five stale unstamped `TestMark` nodes were removed from `diucs-test-shared-neo4j` with a delete scoped to the label `TestMark` and no `tenantId`; nothing else on it was touched.
