# O03 fragment: friction rules engine (build-wave, bundle W2F)

## Decision
Friction rules are a pure engine, one `ui.friction` event per firing, with the element id it happened on

1. `createFrictionEngine({ now, emit })` in `frontend/lib/telemetry/friction.ts` takes time only from `now()` and touches no DOM. All thresholds live in `FRICTION_THRESHOLDS` [ASSUMED values, see Assumed].
2. The page-level kinds carry fixed element ids so every event has an element id that passes the O05 pattern: `PAGE` (u-turn, thrash, hesitation, scroll-thrash), `LIVE-STREAM` (stream-gap), `UNTAGGED` (a click on no `data-el`).
3. Dead click is answered by a navigation, a DOM change, a state change or a network call started from the page. `onNetwork(elementId)` is added beside the spec's method list; `attachFriction` feeds it from a second request observer (`addRequestObserver` in `trace.ts`), because the single observer slot belongs to O02.
4. `attachFriction()` wires the engine to the DOM and to `track('ui.friction', ...)`. It does not observe HTTP status codes (the trace hook carries only the trace id), so `error-click` on an HTTP error is raised only by the caller, through `onRequestEnd`. The caller also calls `handle.route(template)` on page change and `handle.stream(state)`; no screen calls them yet.
5. O02 change: `ui.friction` is added to `ALLOWED_EVENTS` and `kind`, `count`, `window_ms` to `ALLOWED_ATTRIBUTES` (both files are O02's and are edited here, as O05 requires).

## Known issues
| task | what | where | trigger |
|---|---|---|---|
| O03 | HTTP status codes are not observed in the browser, so `error-click` on a 4xx/5xx is never raised by `attachFriction` | `frontend/lib/telemetry/friction.ts` `attachFriction` | the first screen that needs error-click on HTTP errors: wrap `fetch` in `trace.ts` to report status |
| O03 | `handle.route()` and `handle.stream()` are not called by any screen yet, so route-level and stream-gap rules are inert in production | `attachFriction` callers | when the advisor and wall screens mount the handle |
| O03 | the dead-click classifier counts a request started from the page through `addRequestObserver`, but a click whose only effect is a background timer is still `dead` after 1 s | `friction.ts` | a rule review with real sessions |

## Contracts
- `FRICTION_THRESHOLDS`, `QUICK_ACTION_ROUTES`, `PAGE_ELEMENT_ID`, `STREAM_ELEMENT_ID`, `UNTAGGED_ELEMENT_ID`, `FRICTION_EVENT` (`'ui.friction'`), `FrictionKind`, `FrictionEvent`, `ClickInput`, `ClickResult`, `FrictionEngineInit`, `FrictionEngine`, `FrictionHandle`
- `createFrictionEngine(init)`: `onClick`, `onClickResult`, `onNetwork` (added), `onRequestStart`, `onRequestEnd`, `onError`, `onRoute`, `onValidation`, `onFocus`, `onSubmit`, `onLeave`, `onInteraction`, `onScroll`, `onStream`, `tick`
- `attachFriction(now?) -> FrictionHandle | null`: `route(template)`, `stream(state)`, `detach()`
- `frontend/lib/telemetry/trace.ts`: `addRequestObserver(observer) -> remove`
- `frontend/lib/telemetry/events.ts`: `ALLOWED_EVENTS` gains `ui.friction`; `ALLOWED_ATTRIBUTES` gains `kind`, `count`, `window_ms`

## Tenant pending
- None. The engine holds no server data and no tenant.
