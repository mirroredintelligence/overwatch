## Decision

TelemetryQuery port and Azure Monitor adapter, built partly (O07, build-A2): the port, both adapters and the contract tests are in; container wiring is not, and the attribute allow-list is an argument until O01 lands.

1. The port is `application/ports/outbound/telemetry_query.py`: `session_timeline`, `trace`, `search_sessions`, with the dataclasses `TimelineEvent`, `SpanRecord`, `SessionSummary`, `SessionFilters` and the enum `TimelineKind`. No method takes a tenant. Each adapter reads the bound tenant with `application.tenancy.current_tenant()` and refuses to run when none is bound (TenantNotBound), as link_access and the SMS route do.
2. The Azure adapter sends the tenant, the session id, the trace id and the search filters as query parameters, never in the KQL text. The KQL is one module (`adapters/outbound/telemetry/kql.py`). The session id and trace id are checked by `check_session_id` and `check_trace_id` before any query runs.
3. After the query, the adapter drops any row whose `customDimensions["tenant.id"]` is not the bound tenant (defence in depth; the KQL filters too). A row with an unknown kind is dropped.
4. Attributes pass `allowed_attributes(raw, allowed)`: only listed keys, only scalar values. The allow-list is a required argument of both adapters. Until O01 (`adapters/outbound/telemetry/otel.py`) exists, the tests pass a stand-in list and the container does not wire the query.
5. The fixture fake (`adapters/testing/fixture_telemetry.py`) reads `backend/tests/fixtures/telemetry/s-7f3a.json` and applies the same tenant rule and the same allow-list. The contract test runs one set of assertions on the fake and on the Azure adapter, with the Azure stub returning the fixture's rows for the bound tenant.
6. Raw retention lookback for a trace or a search is `RAW_LOOKBACK` (90 days, [ASSUMED]), taken from the clock port.
