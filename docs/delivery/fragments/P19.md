## Decision

P19 push subscription repository on Neo4j (build wave, bundle C)

1. A push subscription is stored on a Device node labelled `Resource:Device` (key `Device/<id>`, so the store's uniqueness and later FHIR reads find it): properties `status` (`active` on each save), `pushSubscriptionJson` and `pushSavedAt`. `USED_BY` links the device to its practitioner; `TYPE` links it to a Concept `mobile-app` in CodeSystem `device-type`.
2. The port is `PushSubscriptionRepository` and the value `PushSubscription(device_id, practitioner_id, subscription, saved_at)` in `application/ports/outbound/messaging.py`, as the contract names. One device has one subscription; saving again replaces the JSON and the save time; a second `USED_BY` is removed on save, so a device has one practitioner.
3. The subscription JSON is stored as canonical text (sorted keys, no spaces). A subscription without an endpoint, or without both the p256dh and auth keys, is refused with ValidationFailed on the field `subscription`; the message names no value.
4. Saving for an unknown practitioner raises NotFound and writes nothing. A racing first save of one device raises Conflict (the device id is unique per tenant).
5. Delete removes `pushSubscriptionJson` and `pushSavedAt` and keeps the Device. Deleting an unknown device does nothing.
6. No statement outside Q-PUSH-* names the JSON property, and nothing in this module logs.

## Known issues

| ID | What | Where | Trigger |
|---|---|---|---|
| P19 | Device ids are unique per tenant across kinds. A push device whose id equals a wall-display Device id in the same tenant is the same node: Q-PUSH-SAVE attaches the subscription to the wall display and sets its `status` to `active`. | `push_subscription_repository.py`, Q-PUSH-SAVE | a push device id reused for a wall display |
| P19 | `delete` of an unknown device is silent (the port says nothing). U-tasks that depend on a refusal should check first. | `push_subscription_repository.py` | a delete for an id that does not exist |
| P19 | The integration tests in `tests/integration/graph_store/test_push_subscription_repository.py` were written and not run (build wave: no Neo4j). | tests | verification |

## Contracts

- `PushSubscription`, `PushSubscriptionRepository` (`application/ports/outbound/messaging.py`)
- `UnitOfWork.push_subscriptions` (`application/ports/outbound/unit_of_work.py`, factory in `graph_store/unit_of_work.py`)
- `Neo4jPushSubscriptionRepository(tx)`, `checked_subscription`, `subscription_json`, `subscription_from_json` (`graph_store/push_subscription_repository.py`)
- Statements `Q-PUSH-SAVE`, `Q-PUSH-FOR`, `Q-PUSH-DELETE`

## Tenant pending

None. Each Q-PUSH statement names `$tenant` on every node it matches or creates and carries a scenario. Device uniqueness is the tenant-composite constraint `tenant_device_id`, already in the schema.

## Assumed

- Device `status` is `active` after every save.
- CodeSystem for the device type: `code_system_url("device-type")`; concept `mobile-app`.
- The Device has no `deviceName`: the port carries none.
