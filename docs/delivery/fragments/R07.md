# Fragment R07: case endpoints and $filter-options

## Decisions
- DEC-397: POST /fhir/ServiceRequest runs two use cases in two units: OpenCase (referrer) and then UpdateCase (age band, district, needs, urgency), with idempotency keys `<key>` and `<key>:details`. Priority maps urgent to within-2-hrs and routine to today; planned is answered as routine. Roles: advisor and clinical only (require_role); any other role gets the NotAllowed 404.
- DEC-398: cases carry no version, so PUT needs If-Match (428 when absent) but its value is not compared: last write wins within an open case; the ETag returned is constant. Stored patient data is the postcode district and age band only; a Patient with name, identifier, birthDate or telecom is refused 400 invalid before anything is read or written; the message names the element and not the value. A closed case answers its ServiceRequest without postal code, needs or reasonCode.
- The $filter-options, $advisor-phoned, $declined and $close answers: Parameters (filter, declined), an Observation (advisor-phoned, 201), a closed ServiceRequest (close, 200). The routes hold no rule.

## Hazards
- H-192: no case version: two concurrent PUTs on one open case are last-write-wins (If-Match is not compared). Trigger: two advisors editing one case. Fix: a case version (a new property with a check in UpdateCase) in a later task.

## Known issues
- R07: the CapabilityStatement registers ServiceRequest create and update only; HealthcareService operations are not added. Trigger: a client that reads the capability to find $filter-options.
- R07: the open-case route is two units: a failure between them leaves a case with no details. Trigger: a failure of the second unit (the case is then open with the referrer only and can be updated).

## Contracts
- routes_cases: POST /fhir/ServiceRequest; PUT /fhir/ServiceRequest/{id}; POST /fhir/ServiceRequest/{id}/$close; POST /fhir/HealthcareService/$filter-options; POST /fhir/HealthcareService/{id}/$advisor-phoned; POST /fhir/HealthcareService/{id}/$declined.
- ApiContainer gains postcodes (PostcodeLocator), travel (TravelTime) and rng (random.Random) (app.py).
- Extensions: https://diucs.example/StructureDefinition/age-band (valueCode), .../referrer-type (valueCode); reasonCode system code_system_url("need-category").

## Tenant pending
- The routes read no tenant; the edge binds it from the token. Case, service and report reads and writes are the use cases' (tenant-scoped statements).

## Tenant isolation
- test_routes_cases.py: an unknown case or service answers 404; the exec role gets the same 404 (NotAllowed). Two-tenant route tests are not yet written for R07 (pending, see known issues).
