## Decisions

### DEC-984 The network tests run over a table of every network route, held equal to the routes the app serves (TEN-062, extends TEN-060 and DEC-544)
Status: accepted (build wave 9, bundle W9B; under DEC-133). Affects: `tests/support/network_routes.py` (new), `tests/support/network_fixtures.py` (new), `tests/support/network_board_samples.py` (new), `tests/integration/adapters/inbound/fhir_rest/conftest.py`.

1. **The route table.** `ROUTES` lists each network route (the member routes, the lead's three, the wall's two) with who may use it. `discovered(app)` reads the same list from the app's own route table (walking FastAPI's lazily included routers as `test_edge_binding.py` does). A test requires the two to be equal, so a network route added to the API and left out of the role matrix, the isolation test and the privacy scan fails a test. The administration of networks (members, grants, listings: TEN-077 to TEN-079) is listed apart by prefix (`/network-admin`, `/admin/`) and has its own role and privacy tests with those tasks.
2. **The role matrix** (`test_network_roles.py`): every route by every role (13; the operator's token is refused at the edge with 401 on every route) in one world, so the 130 cases cost one build; the answer is 200 for the route's roles and the one 404 for any other, with one body per route and no network id in it. A stream route is not opened for a 200 in a test client (it never ends): its allowed path is `test_network_stream.py`.
3. **The generated isolation test over the routes**: for every route that names a network, a viewer who may use it asks for another network, for its own with no claim, as a tenant that never joined, and for a network that does not exist; each is the one 404 with one body.
4. **The privacy scan** (`test_projection_privacy.py`): a sentinel for every category of `NEVER_SHARED` is planted in the member's own tenant (or in the source record the producer reads), patient-shaped text is put in the service comment, the projector runs and the whole network scope is read: no sentinel, no patient-shaped value, no member id; every label, property and relationship is on the allowlist (`SYSTEM_PROPERTIES`, `NETWORK_RELATIONSHIPS`, the scope-generic audit labels); the sentinels are shown to be in the members' tenants so the scan proves something; and every network route's response is scanned with the privacy guard (`scan_value`) and for tenant ids, grant ids and the planted values. A category added to `NEVER_SHARED` fails a test until it is planted or declared a shape.
5. **Scope binding** (`test_network_scope_binding.py`): a tenant unit cannot reach a network repository and a network unit cannot reach a tenant one (before any Cypher), a unit cannot be opened inside another in either direction, the projection is two units that never nest and a failure between them leaves nothing half projected, a retry converges and a replay changes nothing, the apply step refuses a binding that is not the network the message names, and a request's scope is not left bound in the next one.
6. **Redis** (`test_network_keys.py`): the network board is cached under `diucs:_net-<id>:cache:...` and nowhere else; one logical name is three keys in a tenant and two networks; channels and locks are separate; a message in one network never reaches another network's or a tenant's subscribers and the other way round; the cached board and the stream event name no tenant, grant or service.
7. **The owner** is a tenant like the others: its staff read the network board and `GET /fhir/HealthcareService/svc-1` is a 404 for them although every member holds a `svc-1`; they cannot change a member's screen.
