# TEN-069: scope header and organisation label components (and the wall heading)

Bundle WB10. Tests: `components/scope/ScopeHeader.test.tsx` (21), `lib/network/orgs.test.ts` (7), `components/board/Board.scope.test.tsx` (5), `lib/copy/index.test.ts` (capacity heading), `components/scope/OwnScopeHeader.test.tsx` (6), `components/board/StatusAnnouncer.test.tsx` (6). Red `f2e415a` parent.

## Decisions

### DEC-1193 The scope header is a component of the board and of every network page, never chrome; the switch is two links (TEN-069; docs/design/network-ui.md section 3)
Status: accepted (bundle WB10). Affects: `components/scope/{ScopeHeader,ScopeSwitch,OrgLabel,ReadOnlyNote,ScopeNotice,OwnScopeHeader,PhoneLink}.tsx`.
1. `ScopeHeader` (`scope: 'own' | 'network'`, `networkName`, `switchTo`, `variant: 'page' | 'wall'`) is a region named "Which board you are viewing" that says `Showing: Our organisation` or `Showing: Network, {name}` (the network's display name; it takes no id). `ScopeSwitch` is a nav of two links (`Our organisation`, `Network`) with `aria-current="page"` on the current one; the links are fixed routes with no parameter. The wall variant has the display size and never a switch, even when given the routes.
2. `OrgLabel` (the organisation under a service name, caption size) with the words `Your organisation` in a bordered label (tint, ink, primary border: existing tokens) on the viewer's own rows; a word, never a status colour. `ReadOnlyNote` is the info Banner of section 2 (title `Read only`), once above a list. `ScopeNotice` is a Banner of the existing tones with the id `SCOPE-BANNER-NOTICE`. No tone, token, status word or motion is added.
3. `OwnScopeHeader` is the header of the organisation's OWN pages (the advisor's board, the lead's System now and phones, the executive's week): it says `Showing: Our organisation` at once and offers the switch only when the viewer's organisation is in a network (it reads `GET /api/bff/network`); a read that fails leaves the label and no switch. The own page never waits for or breaks on the network read. The default test handler answers "no network" (`ownScopeHandlers`).
4. The "Network view not available" panel has NO scope header: there is no network to name, and any name would say the network exists (the one-refusal rule outranks "the header never disappears", which holds for every state that names a network: paused, ended, offline, last known).
5. The service line is a `PhoneLink`: the number is seen, the words "Phone {service} on" are read out (visually hidden), so the visible text is part of the name (WCAG 2.5.3) and a list of links is not a list of bare numbers.

### DEC-1194 The wall board's heading is the tenant's own word for its system (TEN-069; KI-545, KI-559; DEC-234 wording)
Status: accepted. `copy.capacityHeading(profile, organisation)` is `{organisation} {systemName}` (or the system word alone) when the tenant has wording, else null and the board keeps its old words ("{organisation} urgent care capacity"): a tenant with no wording gets the product's own, never an invented one (H-T15). `Board` and `LiveBoard` take `heading`; the wall page builds it from the profile. The wall board also carries `Showing: Our organisation` in the display size (no switch); the network variant of the wall (a header naming the network) is TEN-072's, on this component.

### DEC-1195 The wall announces status changes politely (KI-56; design-system 5.4 item 4; amends the W06 note "no status-change announcement is built")
Status: accepted. `StatusAnnouncer` (in `LiveBoard`) is a polite, atomic live region that says each status change once as a sentence ("UCR West is now Limited."), in board order, and says nothing for the first board, a change of figure only, a service that appeared, or a board shown as last known (old data is never announced as news). The three `LiveBoard` tests that asserted "no live region at all" now assert the one live region is empty.
