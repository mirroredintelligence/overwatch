# TEN-070: network board UI and unavailable states

Bundle WB10. Tests: `components/board/NetworkBoard.test.tsx`, `lib/board/useNetworkFeed.test.tsx`, `components/scope/NetworkUnavailable.test.tsx`, `components/network/{NetworkScope,NetworkBoardView,NetworkHistoryView}.test.tsx`, `lib/network/{browser,entries,links}.test.ts`, `app/(network)/network/pages.test.tsx`, `test/guards/network-views.test.tsx` (KI-552). ## Decisions

### DEC-1196 The network board is a read-only list of facts in the back end's order, with its state said in words (TEN-070; docs/design/network-ui.md sections 4 and 5)
Status: accepted (bundle WB10, under DEC-133). Affects: `components/board/{NetworkBoard,NetworkTile}.tsx`, `lib/board/useNetworkFeed.ts`, `components/network/NetworkBoardView.tsx`, `lib/network/entries.ts`.
1. **Same look, fewer facts.** A tile is the wall tile's rules for the figure (`figureFor`, `lastKnownFigureFor`, exported from `Tile.tsx`) with the organisation under the name and nothing a network does not share: no comment, no pending chip, no next-due time. A figure it cannot stand behind is "?" and "Phone to confirm". The page keeps the back end's order (category, organisation, service) and never sorts or ranks; the footer says "Sorted by category, then organisation. Not ranked."
2. **The service line is joined from the phones read** by the row reference (the board entry carries none): a link when shared, "No number shared" when the organisation shared none, nothing while it is being read, and one line "Service line numbers could not be loaded. Phone to confirm." when the read failed (never "No number shared" for a read that failed).
3. **A paused listing** is a Not updated tile with "?", the unit "Phone to confirm" and "Not available on the network. Phone to confirm."; no new status word.
4. **Filters work in place**, over the rows the page has: `All organisations`, the viewer's own, then the others alphabetically (`aria-pressed` chips carrying an opaque `data-org-ref`, `org-1`...), and a Tiles/List toggle. A chosen organisation that is no longer on the board says "No services match this filter".
5. **Delayed**: an organisation whose every shown service is Not updated gets a warning notice ("Updates from {name} are delayed. Its services show Not updated."); a paused or out-of-hours service is not a delay. The notices are above the list (rows of one organisation are not together under the back end's category order).
6. **Stopped sharing**: the page compares each board with the one before; an organisation that was on it and is not now is named in an info strip with the day it stopped when the history (`directory?history=true`) has it, and the way to the history. The strip stays until the viewer leaves the page.
7. **The feed** (`useNetworkFeed`) is the wall's rules over the network's stream: an event makes it read the WHOLE board again (never a patch), a refusal (401, 403, 404, including after `scope-ended`) removes every figure ("not available"), a failed or unreadable read keeps the last good board as Last known with the offline banner and a Try again, a board older than 3 minutes is Last known, a board is never replaced by an older one, and a new network id starts again from nothing, so the figures of one network are never shown as another's (last known is per scope).
8. The page opens with the networks list (`NetworkScope`): one network is used; more than one gives a chooser in the page (chips), never an address. Every refusal of the list is the one "Network view not available" panel; a failure is "offline" with Try again.

### DEC-1197 Two of the section-5 states cannot be told apart from "not available" by the front end (TEN-070)
Status: accepted, with a known issue. `NetworkUnavailable` builds all four states (not available, paused, membership ended, offline), but the back end gives every refusal one 404 by design (DEC-134), so a page can only know "not available". The paused and ended panels are built and tested and not reachable until the back end says why (a distinct, non-revealing answer for a member's own former network is a decision for the owner); the history page works for a current member only.

### DEC-1202 Every network view is checked for tenant-shaped values (KI-552; TEN-063 audit D 7.3)
Status: accepted. `test/guards/network-views.test.tsx` renders every network view with answers poisoned at every level (a tenant id, a source tenant id, a grant id, a source service id) and fails if any reaches the page's text or any attribute; a test that the poison really reaches the browser keeps it from being vacuous; the last test fails when a network view file is added without an entry.
