# TEN-076: tenant administration screens (bundle W9D)

Front end, with no back-end change. Number blocks used: decisions DEC-1060 to DEC-1069, hazards H-730 to H-737. Built on the routes of `docs/delivery/fragments/W9C-routes.md` (the `/tenant` door); the exact shapes are the route module's own (`routes_tenant.py`), written out as fixtures in `frontend/test/fixtures/tenantAdmin.ts`.

## Decisions

## DEC-1060 The administration lives at `/admin`, for the role `tenant-admin`, and the staff exchange now gives that role a session (TEN-076, TEN-043)
Status: accepted (W9D, under DEC-133).

1. `/admin/**` is guarded by the sealed tenant session and the role `tenant-admin` (`lib/auth/access.ts`: prefix `admin`, home `/admin`). The staff sign-in's exchange gave `tenant-admin` no session ("no page of this front end is for it yet"); it does now (`STAFF_ROLES`). `network-admin` still gets none.
2. Pages: `/admin` (overview), `/admin/config` and `/admin/config/<n>` (settings, versions, diff, approval), `/admin/users` (directory and role mappings), `/admin/contacts`, `/admin/email`, `/admin/retention`, `/admin/access` (the operator access log), `/admin/support` (the support tickets). One layout: the organisation's own name (the profile), the navigation, the way to sign out.
3. The role mapping offers six staff roles and never the administrator's own (the back end refuses it too, DEC-1007 item 4); the page says the first administrator is invited by the platform operator.

## DEC-1061 The tenant administrator's BFF routes are `/api/bff/tenant/**`, one per back-end route, and each answer is read field by field (TEN-076, TEN-044)
Status: accepted (W9D).

Every route is `withBff` with `roles: ['tenant-admin']` (`idScoped` where it takes an id), calls the root `/tenant/...` route with the person's own token (`root: true`), and answers only what a screen shows: no tenant id, no reference of a channel's secret (only `hasSecret`), no opaque reference of a person (an author or approver becomes `authoredByYou` and `approvedByYou`, from the session's `sub`, which is what the back end compares), no hash. A shape that is not the one expected is a fixed 502, never a half page. Bodies are whitelisted field by field before any call (`lib/tenantAdmin/bodies.ts`): an email channel only (the text channel is the operator's: the screen says so), no secret reference, a retention rule per known class and action, a draft with flat values or lists of codes. A path id is checked by shape (`lib/tenantAdmin/ids.ts`): a malformed one is the one 404, before any call. The access-log window is corrected, not refused (90 days when nothing usable is named, 1 to 400).

## DEC-1062 One idempotency key per submit, new after an edit; a clinical approval is confirmed first (TEN-076, DEC-653)
Status: accepted (W9D).

A write sends one `Idempotency-Key` per submit (`useSubmitKey`): the same for a retry of the same submit (a replay at the back end, not a second change), and a new one as soon as the person edits the form (a key is for one body: the same key with another body is a 422). An approval of a version opens a dialog listing the changed settings first. A draft is made from the version in force the page read (`basedOn`); the back end's 409 on a stale one is said ("The settings changed while you were working. Reload the page and try again.") and nothing is overwritten.

## DEC-1063 The one-time support code is in memory only, once (TEN-076, DEC-1003 item 4)
Status: accepted (W9D).

The administrator's approval answers the code; the page holds it in component state until the administrator says it has been passed on, shows what it does ("It is not shown again. It works for four hours and opens one access to your organisation for one hour."), says what to do if it is lost (take the code back and ask again), and never writes it to storage, a cookie or an address. The ticket list never carries it (the BFF reads the ticket field by field). Test: the code is gone from the DOM, local and session storage and the cookie after "I have given the code".

## Contracts

- Pages: `app/(tenant-admin)/admin/**`; components `components/admin/*` (`AdminOverview`, `ConfigVersions`, `ConfigDiff`, `VersionDetail`, `UsersAndRoles`, `ContactsForm`, `EmailSender`, `RetentionForm`, `AccessLog`, `SupportRequests`, `AdminNav`, `AdminFooter`), `components/session/SignOutButton`.
- BFF: `GET /api/bff/tenant/overview`, `settings`, `config/versions`, `config/versions/<n>`, `access-log?days=`, `support-tickets`; `POST config/drafts`, `config/versions/<n>/approval`, `channels`, `support-tickets/<id>/approval`, `support-tickets/<id>/refusal`; `PUT contacts`, `channels/<id>`, `retention`, `directory`, `role-mappings`; `DELETE support-tickets/<id>/access`. Writes need the CSRF token and an `Idempotency-Key`.
- Library: `lib/tenantAdmin/{views,bodies,ids,call,draft,words,browser,roles}.ts`; `lib/bff/browser.ts` gains `idempotencyKey` and a CSRF channel option.
- Test support: `test/fixtures/tenantAdmin.ts`, `test/msw/handlers/tenantAdmin.ts`.
