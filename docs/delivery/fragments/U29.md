# U29 fragment: approval steps and activation (W3D, partly built)

## Decision
DEC-405: approval rules
- Items: 1. The approver must differ from the requester (DEC-032 default, owner to confirm); an unknown requester is refused. 2. A test answer counts only from the registered phone hash or the registered app device; with neither registered it never counts. 3. A service goes live only from approved, with a test answer; any other state is refused. 4. A send-back or refusal note is required, at most 280 characters, and carries no run of nine or more digits.

DEC-406: activation changes three flags and nothing else
- Items: 1. ServiceRepository.set_active sets HealthcareService.active, the Location.status of each location reference and Organization.active of each providedBy reference, each as a new version, writing back the rest of each resource as read. 2. This closes the U24/U27 loss for activation only; a later profile save still rewrites the service from the profile (known issue kept).
