# Fragment U42: audit replay of what the advisor saw

## Decisions
- DEC-390: the replay is for the lead and audit roles only. The options shown are the last FilterOptions display before the first booking request (or the last display when nothing was requested). The timeline is the case's audit records and its bookings' records, in time order; a record that names both is shown once. Opening a replay appends one audit entry (use_case AuditReplay, action R, entity the case); the replay's own entries are not timeline items.
- DEC-391: service names are the current names (the snapshot holds ids only). The snapshot holds the number as U12 wrote it: for an occupied-patients service that is the used count, so an over-capacity row shows the used count, not the over-capacity figure the prompt's artboard shows ("+2"). The over-by figure is not in U12's snapshot; the fix belongs to U12 (hazard H-190).

## Hazards
- H-190: The replay cannot show the over-capacity figure the advisor saw ("+2"): FilterOptions' snapshot keeps the used count and not over_by. Trigger: any review of an over-capacity option in a replay. Fix belongs to U12 (add over_by to the snapshot as a new record shape).

## Known issues
- U42: service names are current, not as shown (snapshot holds ids). Trigger: a service renamed after the decision.
- U42: "+2" over-capacity figure not shown (see H-190). Trigger: an over-capacity option in a replay.
