# W14 fragment: criteria, I phoned and They declined dialogs

## Decision

DEC-637 The dialog shell (`components/ui/Dialog.tsx`) is an accessible modal, not a native `<dialog>`: `role="dialog"`, `aria-modal`, named by its heading, focus moved in on open and back to the opener on close, Escape closes it, and Tab wraps inside. It draws no close button of its own, so a dialog's own "Close" and "Cancel" never share a name with one in the shell. It is a full-screen sheet at phone width. jsdom has no `showModal`, so the shell does not depend on it.

DEC-638 "I phoned": a "not accepting" answer always sends the value 0 and hides the number. A count must be a whole number (no sign, no decimal). The BFF bounds a count to 0 to 9999 [ASSUMED]. The browser's idempotency key is passed on to the back end, so a double press records once.

DEC-639 The criteria dialog shows what the history gives. The history answer has the version, the status and the review date only, so "Accepts" and "Does not accept" say "Not shown in this view. Phone the service to check." and the reviewed date and owner say "not recorded". Overdue is a review date before today in London (DEC-038); the warning is shown when it is.

DEC-648 "They declined" and "I phoned" are not offered on a network card (network-ui.md section 9). Criteria is.

## Contracts

- Components: `Dialog` (props `title`, `sub?`, `dataEl?`, `onClose`; `components/ui/`), `CriteriaDialog` (props `serviceId`, `serviceName`, `onClose`), `PhonedDialog` (props `caseRef`, `serviceId`, `serviceName`, `onSaved`, `onClose`), `DeclinedDialog` (same props). ids: `ADV-CRIT-DIALOG`, `ADV-PHONED-DIALOG`, `ADV-PHONED-SAVE-BTN`, `ADV-DECLINED-DIALOG`, `ADV-DECLINED-SAVE-BTN`.
- `OptionsList` opens the dialogs from the card. `ServiceCard` gained `onDeclined` and the "They declined" button (`ADV-OPT-DECLINED-BTN`).
- Lib: `lib/advisor/criteria.ts` (`criteriaFromHistory`, `CriteriaView`), `lib/advisor/service-api.ts` (`readCriteriaHistory`, `postAdvisorPhoned`, `postDeclined`, `Said`, `DeclineReason`).
- BFF: `GET /api/bff/services/[id]/criteria` (advisor, lead) answers `{ accepts, excludes, version, reviewedOn, reviewBy, owner, overdue }`, 404 when there is no current version. `POST /api/bff/services/[id]/phoned` (CSRF, key) body `{ caseRef, said, value }` answers 201 `{ recorded }`. `POST /api/bff/services/[id]/declined` body `{ caseRef, reason }` answers 201 `{ recorded }`.
- Back-end calls: `GET /fhir/Basic?subject=HealthcareService/<id>`, `POST /fhir/HealthcareService/<id>/$advisor-phoned` (Parameters: case, status, value), `POST /fhir/HealthcareService/<id>/$declined` (Parameters: case, reason).
