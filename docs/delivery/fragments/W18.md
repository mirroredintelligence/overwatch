# W18 fragment: shift lead add-a-service and change-number forms (pilot)

## Decision

DEC-652 (W18, every lead write) · The BFF forwards only to back-end routes that exist, and converts the browser's JSON to the FHIR Parameters the route takes. It invents no endpoint. `POST /api/bff/lead/services` sends `$setup` with the Idempotency-Key the browser sent (checked against the back end's own rule, 400 when missing or malformed); the answer names the new service and nothing else. Validation runs twice: the form shows the problems before it posts, and `readServiceBody` refuses a body the back end would refuse, before the back end is called.

DEC-653 (W18, every lead write) · Each write carries the CSRF token from the `diucs_csrf` cookie (`X-CSRF-Token`) and one Idempotency-Key per attempt. A failed save that the lead sends again keeps its key, so the back end sees one request, not two (H-332).

DEC-655 (W18) · The "What is counted" choices are the four measures the back end counts: referrals (referrals-acceptable), beds (free-beds), slots (free-slots), packages (packages-free). The canvas's "Virtual beds free" is the same measure as "Beds free" (free-beds): the back end has no virtual-bed measure, and offering both would show two pressed chips for one value. The unit label carries the difference. "Other" is not offered, since no measure stands for it. Hours: the back end takes one time window every day, so the form says "Accepts referrals every day" and has no day choices; a service with different days needs a back-end change first.

## Tenant pending

- None in this bundle. The BFF takes no tenant and forwards the lead's token only. The back-end routes bind the tenant at the edge (TEN-018), as R08 does.

## Assumed

- Mobile: 11 digits starting 07, spaces allowed (the form and the back end agree). Email: one `@` and a dot after it (the form's check; the back end checks again).
- Postcode district: one or two letters, a digit, and an optional letter (`^[A-Z]{1,2}[0-9][0-9A-Z]?$`).
- Review date: must be after today's date in the browser's own calendar (ISO date compare).
- Ages and capacities: whole numbers from 0 (the body reader allows up to 100 000).
- A name, unit label or role is at most 200 characters.
- Needs excluded: "Needs IV therapy" uses the code `iv-therapy`, the same code as "IV therapy" to accept (the canvas gives both labels for the same need).
