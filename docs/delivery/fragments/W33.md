## Decision
Reporter set-up, first half (W33). The browser holds only the invitation token in the address and the masked number; the BFF holds the device cookie and the session.
1. (DEC-660) Reporter session and device model: a reporter session is sealed in the existing session cookie with `role: reporter`; its `backendToken` is the back end's session id, which is not a bearer token (the reporter exchange is TEN-043, not built). The phone's device id is 16 random bytes, base64url, in an http-only `diucs_device` cookie kept for 365 days [ASSUMED]. `GET /api/bff/reporter/start` gives the browser its CSRF token and makes sure the device cookie exists; no tenant, person or device id is ever returned in a body.
2. (DEC-662) Invitation landing: an invitation that is expired, used, unknown or malformed is shown with the one expired text, so an unknown link tells nobody it ever existed. A failed check is shown as "could not check", never as expired.
3. Resend countdown is one one-second interval per set-up step. Wrong-code wording uses "try" when one remains and "tries" otherwise.
4. Exec invitations (role `exec`) skip the channel step and go to `/setup/home-screen`.
5. (DEC-664) Back-end gaps: the four routes that need an invitation or a device-to-number lookup, and the reporter channel route, answer `503 {code:"not-built"}` and do nothing else. See Known issues.

## Known issues
| W33 | invitation lookup `GET /api/bff/invitations/[token]` answers not-built: the back end has no route that resolves an invitation token to its state, masked number and service. Every set-up step is blocked behind it | app/api/bff/invitations | any real invitation in a live tenant |
| W33 | `POST /api/bff/identity/code` and `.../code/verify` answer not-built: the back end's code routes take a mobile number and device id, and the browser only has an invitation token. The back end needs to accept an invitation token (or resolve the number server-side) | app/api/bff/identity | first set-up code request |
| W33 | `POST /api/bff/reporter/channel` answers not-built: no back-end route stores a reporter's channel | app/api/bff/reporter/channel | a reporter picks a channel |
