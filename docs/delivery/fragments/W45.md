# W45 fragment: advisor, ask a clinical advisor, wired (bundle W6G)

## Decision

W45 (build W6G). Numbers: item 1 is DEC-728; item 2 is DEC-729.

1. **The reason is asked, and required.** The back end refuses a clinical-advice request with no `why` (R13 takes `borderline-criteria`, `unsure-of-urgency` or `other`). The prompt's dialog asks only for urgency and posts `{urgency}`, which the back end would refuse. The dialog therefore asks "Why are you asking?" as a required choice (it says "Choose why you are asking." when none is chosen, and sends nothing). The prompt's test 2 body is extended to `{urgency, why}` accordingly.
2. **The advisor's state read is not on the back end.** The poll reads `GET /api/bff/cases/[ref]/clinical-requests/[id]`, which answers 503 because no back-end read lets an advisor see one request. The dialog therefore never sees "taken" or "advised" in this build; it keeps showing "Waiting for a clinical advisor". This is the risk in H-NEW-4 and it is not a working feature until that read exists. The poll, the state changes and the stop-on-advice behaviour are built and tested against the browser contract the prompt names.
