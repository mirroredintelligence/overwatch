# W8E: the reporter app and its sign-in, wired to the real back end

Tasks: W32 (PWA, checked: the service worker holds no tenant data), W33, W34, W35, W36, W37, W38, W55 and the link and booking pages a reporter uses (checked against `capacity_links.py` and `booking_links.py`: no change needed). Back end used: W7C `routes_reporter_setup.py` and `routes_reporter.py`, W7B A2 `routes_registration_session.py` (`POST /identity/session-token`), `routes_identity.py`, `routes_admin.py` (`sign-out-everywhere`), `routes_public.py` (`/public/push-key`). All of these are mounted at the back end's ROOT (not under `/fhir`); every call here uses `root: true` or the host-call seam, and the test handlers use the real paths. No back-end file was changed.

## Decisions

- DEC-940 The reporter's bearer is a 30-minute back-end token, never the PIN session id (replaces F6A). After a right PIN the BFF exchanges the PIN session (`POST /identity/session-token`, host as tenant, no bearer) and seals the TOKEN as `backendToken`, with the PIN session (`pinSession`) and the token's expiry (`tokenExpiresAt`) beside it in the one sealed HTTP-only cookie. `sub` is the person from the token (so the CSRF binding is the person, not the session id). The session still ends eight hours after sign-in (DEC-660) and a renewal never moves that end. A cookie with `pinSession` and no `tokenExpiresAt` (or the reverse) is not a session. The PIN session id is in no answer, header, log or URL; the browser sees `{ok: true}` only.
- DEC-941 What the exchange is believed for (`lib/reporter/exchange.ts`, one place, used by sign-in and renewal). A token is kept only when: the answer is 200 with role `reporter`; the token is `aud diucs-api`, role `reporter`, for the tenant the session was made for, for the phone (the `device` claim must equal the cookie's device, and must be present), on a renewal for the same person (`sub`), unexpired, and neither the token nor the answer's expiry is more than an hour away [ASSUMED]; the kept expiry is the earlier of the two. Every other 200 is `invalid`. A 4xx other than 429 is `refused` (the session has ended). 429, 5xx, an unreachable back end and a non-JSON 200 are `unavailable`. A missing back-end address is a fault, not an answer.
- DEC-942 Renewal (`lib/reporter/renew.ts`, called by `withBff`). The seam renews after the session, role, CSRF and tenant-input checks (a refused request asks the back end for nothing) and before the handler, only for a session that has a PIN session. Due when the token has five minutes or less left, or has run out [ASSUMED 5 min]. The PIN session is the authority: an expired token with a live PIN session is renewed. A refusal or an answer that is not for this tenant, person and phone ends the session at once (401 `session-ended`, session and CSRF cookies cleared, the handler never called). A back end that cannot be asked keeps the old token while it still lasts and asks again on the next call; once the token has run out it ends the session. This reads "a failed renewal ends the session" as: any renewal that does not give a good token ends it once the old token can no longer serve. Calls that find the token due together share one exchange. The renewal rewrites the cookie with the same session end and the same CSRF-binding subject, so tokens issued before stay good. Tenant and host stay bound: the exchange is addressed to the session's own host and the answer must be for the session's tenant.
- DEC-943 The CSRF token a signed-in reporter needs is the session's (TEN-046). `GET /api/bff/reporter/start` now gives a token bound to the session when the request carries a live reporter session on this host, and the phone's pre-session token otherwise (a staff session, another host's session or a damaged cookie count as none). Without this every in-app reporter write was refused 403 (the pre-session token never verifies for a session). The browser helper forgets its cached token after a right PIN (`ok: true`), and already refreshes once on a stale-token 403. `start` is named in the guard table as the one non-`withBff` route that reads a session.
- DEC-944 The BFF does not decide which services a reporter holds. The cookie's `services` was a copy from sign-in; the back end reads them from the graph per request (DEC-814), so a cover that began after sign-in works at once. The BFF checks only the shape of an id (`^[A-Za-z0-9_-]{1,64}$`, a four-digit reference) and leaves ownership to the back end's one 404. `ownService` and `notBuilt` are deleted.
- DEC-945 Reporter routes (all wired; none answers not-built): pre-session (phone CSRF token, host as tenant, no bearer): `GET /api/bff/invitations/[token]`, `POST /api/bff/identity/invitation-code` and `/verify` (body: the link's token and the six digits, never a number; the device is the phone's cookie), `POST /api/bff/identity/device-code` and `/verify` (purpose `reverify` or `pin-reset`), `POST /api/bff/identity/channel` (set-up, locked PIN), `GET /api/bff/push/key`. With a session (reporter token): `GET /api/bff/reporter/services`, `.../services/[id]/prompt`, `.../history?day=today`, `GET .../settings`, `GET .../setup-summary`, `GET .../bookings/[ref]` (four-digit reference, as the back end maps it), `POST .../services/[id]/report`, `.../reports/batch`, `.../cover`, `.../services/[id]/cover`, `.../channel`, `.../services/[id]/accept`, `.../bookings/[ref]/respond`, `POST /api/bff/push/subscriptions`, `POST /api/bff/push/test`, `POST /api/bff/identity/sign-out-everywhere`. The old `/api/bff/identity/code` and `/code/verify` (the registration flow's, W23) are untouched.
- DEC-946 An answer is believed through a parser that keeps only the fields a screen reads (`lib/reporter/answers.ts`); an answer of another shape is a 502 `exception`, never data. The booking read never passes the Task id. `FhirError` carries the back end's non-OperationOutcome JSON (`payload`) and `Retry-After`, so the 409 `{result: sendNumber|confirmLimit}` of a report and `{code: no-subscription}` of the test push reach the screen, and a 429's wait is passed on.
- DEC-947 Writes take their Idempotency-Key from the screen (one per press; report, batch, booking answer) and the BFF refuses one that is missing or malformed before the back end is asked; the push subscription gets a generated key when the screen sends none. A confirm the back end will not take (409 `sendNumber`, `confirmLimit`) hides the confirm and asks for the number; a batch confirm that must send a number is not shown as done. Times from the back end are ISO UTC and are shown as London clock time (`lib/reporter/times.ts`); the thanks address carries the instants, not formatted text.
- DEC-948 Push (DEC-661 kept): the subscription is saved on All-set after sign-in. The page reads the public key from `GET /api/bff/push/key`, subscribes the browser with it, and posts the subscription; the device in the saved record is the session's, a body that names a device is refused, the subscription is never answered or logged, and the service worker is unchanged and holds none of it (it keeps title, body and a same-origin path). Test push messages: 409 "no notification saved", 429 "a few test notifications".
- DEC-949 Screens that can be reached with or without a session. Set-up and the locked PIN have no session: they record the channel for the phone's device (`/api/bff/identity/channel`; a 403 means the text code has timed out and the screen says to check the number again). The notifications-off page tries the session's route and falls back to the device's. The 30-day check no longer reads settings (there is no session when it is shown). Settings gains the channel form and the cover "until" choice (tonight, this week, a date; this week by default, the back end's default) and its cover number is never kept in the page after it is sent. "Sign out of every phone" ends this phone's session in the BFF, so the page no longer asks the session route a second time. The lost-phone wait shows the tenant's coordination number (a link) or says to phone the team with no number. `/app` for a reporter with no live post goes to the services list, not back to the PIN screen.

## Contracts

- `lib/reporter/exchange.ts`: `exchangeSessionToken(input, now)` returns `issued | refused | unavailable | invalid`; `MAX_TOKEN_MS`.
- `lib/reporter/renew.ts`: `renewIfDue(session, now)` returns `current | renewed | ended`; `RENEW_BEFORE_MS`.
- `Session` (`lib/auth/session.ts`): optional `pinSession` and `tokenExpiresAt`, both or neither; `PIN_SESSION_PATTERN`.
- `lib/reporter/session.ts`: `startReporterSession(input)` returns `started | unavailable`.
- `lib/reporter/answers.ts` (parsers and the id, reference and key shapes), `lib/reporter/backend.ts` (`reporterCall`, `keyOf`, `onlyFields`, `badAnswer`), `lib/reporter/identity.ts` (`codeRequested`, `codeChecked`), `lib/reporter/cover.ts`, `lib/reporter/channel.ts`, `lib/reporter/times.ts` (`clock`, `inDays`), `components/reporter/CoverUntil.tsx`.
- `FhirError.payload` and `FhirError.retryAfter`; `toBffError` passes `Retry-After` on a 429 or 503.
- BFF routes as in DEC-945. Test support: `test/fixtures/reporter.ts`, `test/preSessionCalls.ts`, `test/reporterCalls.ts`; the leak canary treats `/identity/channel` as a pre-session call. e2e stand-in routes: `e2e/support/reporter.ts`.
