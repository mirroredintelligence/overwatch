# WB11 merge: one network options filter

Merge of `task/build-WB11` into `integration/build` (3a6bcd8), branch `task/merge-WB11`. WB6 and WB11 each built the network variant of the advisor's options filter. This fragment records which design survived, what was ported, what was dropped, and what WB11's own fragments (`WB11.md`, `WB11-routes.md`) say that is now different. Where this fragment and `WB11.md` disagree, this one is right.

## What survived, per conflicted file

| file | survivor | why |
|---|---|---|
| `backend/src/diucs/application/use_cases/filter_network_options.py` | WB6's `FilterNetworkOptions` (constructor `uow_factory, network_uow_factory, access, clock, postcodes, travel_time`; one read-only network unit; the case read first and closed; travel awaited with no unit open; audit as a separate unit). WB11's `NetworkOption`, `NetworkNotSuitable`, `FilterNetworkOptionsResult`, `NetworkCaseInputs`, `classify_network_row`, `network_reason_code` are kept as thin types and a pure function on top of it, not as a second filter. | WB6's is the one in use (the `$filter-options` `network` part, the BFF's appended rows, `network: "unavailable"`, own services first, `?only=own`) and holds no unit across the travel estimate (KI-350). WB11's read through the three existing network reads (projector, directory, criteria) would have read the network three times and kept the case's unit open while it awaited travel. |
| `backend/src/diucs/adapters/inbound/fhir_rest/routes_network.py` | Both routes stay; only the imports and the `options` field comment conflicted. `GET /network/{id}/options?case=` now calls `FilterNetworkOptions.view`; `options_to_dict` builds the same JSON as before from the surviving result types. | The route is the back end of WB11's network options page and map. Its JSON contract is unchanged, so the BFF route, the parser and the pages did not change. |
| `backend/tests/unit/application/use_cases/test_filter_network_options_rules.py` | Both files kept: WB6's three `criteria_of` tests, and all of WB11's 22 rule tests rewritten onto `classify_network_row` (inputs are now a board entry, a `NetworkServiceInput` and a `CriteriaProjection` instead of WB11's directory and criteria entries). 31 tests. | Both describe real behaviour; the second set only changed shape. |
| `frontend/components/advisor/OptionsMap.tsx` | Both: WB6's `ServicePhone` for the viewer's own service and WB11's `NetworkServiceLine` for another organisation's; WB6's rule that a network row's Criteria button must not call the own-criteria route, WB11's dialog for another organisation's criteria. | See "Front end" below. |

## One filter, two answers

`FilterNetworkOptions.execute` is WB6's: the options only (DEC-1176), appended after the viewer's own services. It is byte for byte the answer it was: `notSuitable` empty, `outOfArea` false, the audit snapshot with the options only.

`FilterNetworkOptions.view` is the same read and the same classification, answering the network options page: the options and, as `not_suitable`, the rows that are not options with their reason, `out_of_area`, and the network's `system_name`, `pathway_name`, `time_zone`. The command did not change (it still has no case value in it, `test_the_use_case_is_never_given_a_case_value_to_pass_on`).

## Ported from WB11 into the surviving filter (each with a test)

1. **A paused listing is named, with nothing else read of it** (`PAUSED_REASON`, "not available on the network. Phone to confirm."), on the page view; the options list still drops it. Order of the board's own rule: hidden shows nothing, paused shows its name only, then the grants and the service decide. Tests: `test_a_paused_listing_is_not_suitable_and_nothing_else_is_read_of_it`, `test_a_hidden_listing_or_a_missing_directory_or_capacity_grant_shows_nothing_at_all`, `test_a_closed_service_shows_nothing_at_all` (unit); `test_the_page_view_names_a_paused_listing_with_nothing_else_of_it` (integration, a real suspended listing).
2. **Criteria not shared is named, and criteria that cannot be built fail closed per row.** WB6 dropped such a row, and `criteria_of` raising `ValidationFailed` for one member's row would have failed the whole list (a 500 for the advisor). Now the row is "criteria not shared. Phone to confirm." on the page view and dropped in the options list, and never an error. Tests: `test_a_service_that_shared_no_criteria_cannot_be_checked_and_fails_closed`, `test_a_criteria_grant_that_is_not_in_force_fails_closed_even_with_a_row_held`, `test_criteria_that_cannot_be_built_fail_closed` (unit); `test_the_page_view_names_a_service_whose_criteria_were_not_shared_and_the_list_drops_it` (integration).
3. **The reason of a status that cannot take the case, and "outside criteria", with no case value in it** (page view). Tests: the parametrised `..._no_case_value_is_in_the_reason` (unit) and `test_the_page_view_gives_the_reason_for_a_case_outside_the_criteria_and_no_case_value` (integration).
4. **`out_of_area`** (no shared criteria cover the case's district), page view only. Test: `test_the_page_view_says_when_no_service_covers_the_district`.
5. **The audit entry of a page view** holds the codes of the reasons (`network_reason_code`: `paused`, `criteria-not-shared`, `not-accepting`, `outside-criteria`, ...) and never a name, an id, an age or a case value; it uses WB6's keys (`row_ref`, `status`, `number`, `over_by`, `data_age_seconds`, `criteria_version`, `shown_as`) plus `reason`. Test: `test_the_audit_of_a_page_view_holds_the_codes_of_the_reasons_and_no_name_or_id`.
6. **The roles, the case, the registry.** WB6's checks are the same as WB11's (advisor and clinical only; one NotFound for a non-member; closed case 409; incomplete case 400). The page view has its role test: `test_the_page_view_refuses_the_roles_that_never_work_a_case`.
7. **The no-upper-age-limit change (`dc89b51`)** is front end only (`age_max: null` read as "18 and over") and came in unchanged with its tests (`entries.test.ts`, `parse.test.ts`, `NetworkCriteriaDialog.test.tsx`). The back end already carried `age_max=None` through `criteria_of` (the unit tests use a projection with no upper age).
8. **The wiring.** `build_network_services` did not wire `options` on `integration/build` (only the tests did), so the real API answered `$filter-options` with a `network` part, and the new route, with a 500 (`no network options are configured`). It now wires `FilterNetworkOptions` with the read-only network unit factory.

## Dropped, and why

- WB11's second implementation of the filter (its `FilterNetworkOptions.__init__` with a projector, a directory query and a criteria query; `classify_network_row(entry, criteria_entry, directory_entry, ...)`; `NetworkBoardProjector.get_board` read inside the options use case). Replaced by the above; nothing it tested is lost (items 1 to 6).
- WB11's audit keys `ref` and `scope: "network"`: WB6's `row_ref` is kept (no replay reads the key; a network entry is already known by `use_case=FilterNetworkOptions`).
- WB11's order of options (organisation, then service name): WB6's `option_order_key` (travel low end first, none last, then name, then reference) is kept, so the own list and the network list sort alike. The tests that depended on the organisation tie-break pass unchanged (the world's names sort the same way).
- WB11's `unit_label` fallback "Phone to confirm" for a row with no unit: WB6's empty string is kept (the cards already say "Phone to confirm" for a missing figure).
- Tests deleted: none for behaviour. The only WB11 tests that changed are the ones that built the old constructor (`test_network_options.py`, the `app` fixture) or the old classifier (the unit file above).
- Front end: WB6's `ServiceCard.test.tsx` "a network service has its phone as the one thing to do with it" asserted a link named `Phone 01305 900300` (the own `ServicePhone` button) and the advice "Find it in your service directory" for a network row with no number. A network row now carries the service line once (WB11's `NetworkServiceLine`, "Phone UCR West on 01305 900300", `NET-BOARD-PHONE-LINK`, "No number shared"), because another organisation's service is not in the viewer's own directory and the two controls side by side were the same number twice. The test was changed to say that (one link, the service-line name, no own-directory advice), not deleted.

## Tests that the merge itself broke, and how they were fixed

- `test_network_roles.py::test_every_network_route_the_app_serves_is_in_the_table` and `test_projection_privacy.py::test_every_network_route_is_in_the_scan`: `GET /network/{network_id}/options` was missing from `tests/support/network_routes.py` (WB11 added the route without adding it to the table). It is in the table now, with its roles (advisor, clinical) and a new `needs_case` flag. The generic checks that need a 200 skip it (a 200 needs the viewer's own case; its 13-role matrix, two-tenant tests, audit and privacy checks are in `test_network_options.py`); the generic 404, edge-401 and cross-network isolation checks do run over it (with a `case` parameter). The shared `net_app` fixture (`tests/support/network_fixtures.py`) now wires `FilterNetworkOptions` as production does, so the route's 404 for another network is reached before any case read.
- `lib/board/useBoardFeed.scope.test.tsx` "opens the stream again for the new scope and closes the old one": the test let the own stream stay silent for 60 s, and the integration branch's KI-54 watchdog (an own stream that is silent for three beats is closed and opened again) then opened it a second time, so three opens were counted. The test now sends the 15-second heartbeat the real stream sends; the behaviour under test (the new scope opens its own stream and closes the old one) is unchanged.

## Front end

- `ServiceCard` and `OptionsMap` take a new `onNetworkCriteria`. A network row shows the Criteria button only when it is given (the network options page and map give it, with WB11's read-only dialog). The own options page and the own map pass `onCriteria` to every card, and that must never reach a network row (the own-criteria read does not find it, KI-794): a test says so (`ServiceCard.test.tsx`, `OptionsMap.test.tsx`).
- `ServicePhone` is for the viewer's own services only; a network row has `NetworkServiceLine`.
- The map's "Travel details" button is shown for the viewer's own services and for a network row that has travel legs (the options list's rows have them; the network page's rows are a range only, as WB11 built them).
- The advisor's own options page (WB6: network rows after the own ones, `network: "unavailable"` on failure, the outcome form's `?only=own`) and WB11's network options page and map are both kept. They share the one back-end filter; the second is reached from the scope header's switch.

## Privacy and tenancy, after the merge

- The case is read in the advisor's tenant and closed before any network read; the network read takes no parameter from it (`execute` and `view` read the network with no case value; `FilterNetworkOptionsCommand` has no case field but the case id, which the network unit never receives).
- The advisor's own organisation's rows are skipped before the registry lookup in both answers (`test_the_advisors_own_services_are_not_among_the_network_options`, `test_each_member_sees_the_others_and_never_its_own`).
- Another organisation's service is never an outcome destination: the outcome form asks `?only=own` (WB6, untouched; `OutcomeForm.destination.test.tsx` passes).
- No statement was added or changed: `FilterNetworkOptions` composes registered reads (the case read, the network view reads, the audit append), so `NamedQuery`, the `Marked(...)` scenarios and `tests/integration/graph_store/test_tenant_isolation.py` are unaffected by the merge (WB11's own TEN-072 changes add none either; `PreviewPairing` uses the existing link-token and device reads). The file is part of the integration run recorded below.
- The network scope holds nothing of the case after either answer (`test_the_network_scope_holds_nothing_of_the_case`, `test_the_page_view_does_not_write_the_case_into_the_network_scope`, `test_the_case_is_never_written_to_the_network_or_another_tenant`).
- Roles and tenants: `GET /network/{id}/options` keeps its 13-role matrix (`test_role_matrix`) and its two-tenant tests (`test_another_tenants_case_is_a_404_...`, the non-member and foreign-claim 404); `$filter-options`' network part keeps WB6's.
