What each role holds

Three separate things, today folded into one role: the data class you may see, the intents the chat may open for you, and what you may write. The chat can only open an intent the role lists, and it is checked on the server.

The contract, in two lines
Role = { dataClass, intents[], writes[] } Intent = { id, inputsSchema, widgets[], layoutPreset, requiredDataClass }
A dialog step, a button or, later, a language model can only choose an entry from the role's list. None can add one. That is the guardrail that keeps a later model safe.
A layout is not a security boundary
A no-code layout could place any widget anywhere. So every widget fetches its data through the BFF with the viewer's own session, and the tenant and role checks stay at the data. Whoever authors a layout cannot give anyone data their role does not hold.
Who builds layouts and intents
Only Admin, and only when the no-code builder exists. Until then the intents are fixed in code and the roles above are the whole picture.
