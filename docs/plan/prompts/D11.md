**Goal.** Decide what happens to a capacity reply: record it, record it as a correction, refuse it as late, refuse a third Y, or ask the reporter to send an unusual number again. This is a pure decision; the use case acts on it later.

**Read first.**
- `backend/src/diucs/domain/rules/reply_parser.py` (D09): `Confirm`, `Number`.
- `backend/src/diucs/domain/rules/schedule.py` (D04): `REPLY_WINDOW`.
- `backend/src/diucs/domain/codes.py` (F07): `ReportFlagReason`.
- `docs/spec/domain-rules.md`, section 2.2. `docs/spec/ui-screens.md`, artboards "Reporter2" and "ReporterFirst".

**Rules you need.**
- A prompt is **open** from when it was sent until its reply-by, inclusive (a reply at exactly the reply-by is on time).
- **Late** (no open prompt): the value is not used; reply "Too late" with a fresh question whose new reply-by is `now + 30 minutes`. Canvas example: prompt 12:00, reply-by 12:30, reply "5" at 12:41 → refused, new reply-by 13:11.
- **Correction**: a number sent within 15 minutes [ASSUMED] (inclusive) of an accepted report replaces it, even if the prompt has since closed. Example: 4 accepted at 14:10, "3" at 14:14 → recorded as a correction ("Replaces 4").
- **Y limit**: `Y` is recorded as a confirmation. At most 2 confirmations in a row; a third `Y` is refused ("Y was used twice already. Please send the number for UCR West."). A `Y` when no figure has ever been recorded cannot confirm anything: answer that a number is needed.
- **Range check** (applies to new figures and corrections): a number outside the usual range is not recorded the first time; ask for it again [ASSUMED]. If the same number arrives again (it is in `pending_out_of_range`) inside an open prompt or the correction window, record it with flag `out-of-range-twice`.
- The policy only decides. It does not change `PromptState`.

**Build.** `backend/src/diucs/domain/rules/reply_policy.py`:
- `CORRECTION_WINDOW = timedelta(minutes=15)`, `MAX_CONSECUTIVE_CONFIRMS = 2`.
- `PromptState(service_id: str, reply_by: datetime | None, recorded_value: int | None, consecutive_confirms: int, last_accepted_at: datetime | None, last_accepted_value: int | None, pending_out_of_range: int | None, usual_range: tuple[int, int])`.
- Decisions: `RecordNumber(value: int, is_correction: bool, flag: ReportFlagReason | None)`, `RecordConfirm()`, `RejectLate(new_reply_by: datetime)`, `RejectConfirmLimit()`, `AskRecheck(value: int)`, and the extra `NeedNumber()`. `Decision = RecordNumber | RecordConfirm | RejectLate | RejectConfirmLimit | AskRecheck | NeedNumber`.
- `decide_capacity_reply(reply: Confirm | Number, state: PromptState, now: datetime) -> Decision`.

**Tests to write first.** UCR West, range (0, 8), recorded value 3.
1. Prompt reply-by 10:30, "4" at 10:12 → `RecordNumber(4, False, None)`.
2. "Y" at 10:12, 0 confirms so far → `RecordConfirm()`; with 1 so far → `RecordConfirm()`; with 2 → `RejectConfirmLimit()`.
3. "Y" with `recorded_value=None` → `NeedNumber()`.
4. "5" at 12:41 after reply-by 12:30, last accepted 08:15 → `RejectLate(13:11)`. "Y" at 12:41 → `RejectLate(13:11)`.
5. Reply exactly at 12:30 → treated as on time.
6. Correction: last accepted 4 at 14:10, no open prompt, "3" at 14:14 → `RecordNumber(3, True, None)`; at 14:25 (exactly 15 min) → correction; at 14:26 → `RejectLate(14:56)`.
7. Inside an open prompt with a report accepted 5 minutes ago, "2" → `RecordNumber(2, True, None)`.
8. "40" in an open prompt → `AskRecheck(40)`; again with `pending_out_of_range=40` → `RecordNumber(40, False, OUT_OF_RANGE_TWICE)`; "41" with pending 40 → `AskRecheck(41)`.
9. "0" → `RecordNumber(0, False, None)` (closed is in range).
10. Out-of-range correction "40" at 14:14 → `AskRecheck(40)`.
