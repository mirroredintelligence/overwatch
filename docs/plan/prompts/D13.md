**Goal.** Encode the booking life cycle as a strict state machine and map each state to the FHIR Task fields, so no code can move a booking into an impossible state.

**Read first.**
- `backend/src/diucs/domain/codes.py` (F07): `BookingStatus`.
- `backend/src/diucs/domain/errors.py` (F01): `InvalidTransition`, `ValidationFailed`.
- `docs/spec/domain-rules.md`, section 3.1. `docs/spec/architecture.md`, "Booking as a Task".

**Rules you need.**

| Domain state | Task.status | Task.businessStatus | statusReason |
|---|---|---|---|
| requested | requested | requested | – |
| confirmed | accepted | confirmed | – |
| declined | rejected | declined | – |
| expired | cancelled | expired | expired |
| cancelled-before | cancelled | cancelled-before | – |
| cancelled-after | cancelled | cancelled-after | – |
| withdrawn | cancelled | withdrawn | withdrawn |
| not-reached | failed | not-reached | – |
| completed | completed | completed | – |

- Allowed transitions: requested → confirmed, declined, expired, cancelled-before. confirmed → cancelled-after, withdrawn, not-reached, completed. Every other move, including to the same state, is refused.
- `requested` is the only open state. declined, expired, cancelled-before, cancelled-after, withdrawn, not-reached and completed are terminal.

**Build.** `backend/src/diucs/domain/rules/booking_state.py`:
- `ALLOWED: Mapping[BookingStatus, frozenset[BookingStatus]]`.
- `transition(current: BookingStatus, target: BookingStatus) -> BookingStatus` raising `InvalidTransition` with a message naming both states.
- Extra public names: `allowed_targets(current) -> frozenset[BookingStatus]`, `is_open(status) -> bool`, `is_terminal(status) -> bool`.
- `FhirTaskStatus(status: str, business_status: str, status_reason: str | None)`; `to_fhir(status) -> FhirTaskStatus`; `from_fhir(business_status: str) -> BookingStatus` raising `ValidationFailed("businessStatus", ...)` for an unknown code.

**Tests to write first.**
1. Parametrised over all 8 allowed transitions → returns the target.
2. Parametrised over every other pair of states (81 pairs minus the allowed 8) → `InvalidTransition`; the message contains both state codes.
3. `to_fhir` for each row of the table returns exactly that row.
4. `from_fhir(to_fhir(s).business_status) == s` for every state.
5. `from_fhir("booked")` → `ValidationFailed` with field `businessStatus`.
6. `is_open` true only for requested; `is_terminal` true for the seven terminal states, false for requested and confirmed.
7. Every `Task.status` value used is a valid FHIR R4B Task status code (assert membership in the R4B list: draft, requested, received, accepted, rejected, ready, cancelled, in-progress, on-hold, failed, completed, entered-in-error).
