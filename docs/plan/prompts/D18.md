**Goal.** Model an advisor's case, the referrer's scores and the call outcome as validated value objects, including closing a case, which clears the postcode and needs.

**Read first.**
- `backend/src/diucs/domain/codes.py` (F07): `AgeBand`, `NeedCategory`, `Urgency`, `ReferrerType`, `Outcome`, `BestFitNotUsedReason`.
- `backend/src/diucs/domain/errors.py`: `ValidationFailed`, `InvalidTransition`.
- `docs/spec/domain-rules.md` section 4.

**Rules you need.**
- A case holds: referrer type, age band, postcode, needs, urgency, optional scores. No name, no NHS number, no free text.
- Scores are recorded as given; never calculated. Allowed: NEWS2 0–20; Clinical Frailty Scale 1–9; ambulance category 1–4; Manchester triage `immediate`, `very-urgent`, `urgent`, `standard`, `non-urgent`; NHS Pathways Dx code chosen from a list (validate only: 2–10 characters, upper-case letters and digits) [ASSUMED format check].
- At most one score per method on a case.
- Urgency to `ServiceRequest.priority`: `within-2-hrs` → `"urgent"`; `today` and `planned` → `"routine"`.
- On close: postcode and needs are cleared. Kept for audit: need categories, age band, urgency, scores, destination, outcome, times. So the audit summary must be taken before clearing.
- `accepted-and-booked` requires a destination service. Closing an already closed case is refused.

**Build.**
- `domain/model/scores.py`: `News2(value: int)`, `ClinicalFrailty(value: int)`, `AmbulanceCategory(value: int)`, `ManchesterTriage(level: str)`, `PathwaysDx(code: str)`, each validating in `__post_init__` and raising `ValidationFailed`; `Score = News2 | ClinicalFrailty | AmbulanceCategory | ManchesterTriage | PathwaysDx`; `method_of(score) -> AcuityMethod`.
- `domain/model/case.py`: `Case` exactly as in contracts.md; `Case.close(outcome, at, destination_service_id=None, best_fit_not_used=None) -> Case`; `priority_for(urgency: Urgency) -> str`; `CaseAuditSummary(reference, referrer_type, age_band, needs, urgency, scores, outcome, best_fit_not_used, destination_service_id, opened_at, closed_at)` and `audit_summary(case: Case, outcome, at, destination_service_id=None, best_fit_not_used=None) -> CaseAuditSummary` (call before `close`).
- `Case.__post_init__` rejects two scores with the same method.

**Tests to write first.**
1. `News2(21)`, `News2(-1)`, `ClinicalFrailty(0)`, `ClinicalFrailty(10)`, `AmbulanceCategory(5)`, `ManchesterTriage("high")` each raise `ValidationFailed`; boundary values 0, 20, 1, 9, 1, 4 are accepted.
2. `PathwaysDx("Dx0121")` fails (lower case); `"DX0121"` passes.
3. A case with two `News2` scores raises.
4. Close a case (age 80+, postcode "DT4 8XX", needs fall-no-injury and frailty, within-2-hrs, News2(2), ClinicalFrailty(6)) with `accepted-and-booked` and destination "svc-ucr-west": returned case has `postcode is None`, `needs == ()`, outcome set, `closed_at` set, scores and age band kept.
5. `accepted-and-booked` without destination raises `ValidationFailed`.
6. Closing twice raises `InvalidTransition`.
7. `audit_summary` taken before close keeps both needs.
8. `priority_for` for the three urgencies.
