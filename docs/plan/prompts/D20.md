**Goal.** Model a service's criteria version and the hard criteria filter that decides whether a case may be offered to a service. It is a filter, never a ranking.

**Read first.**
- `backend/src/diucs/domain/model/case.py` (D18) and `domain/codes.py` (F07): `AgeBand`, `NeedCategory`, `CriteriaStatus`.
- `backend/src/diucs/domain/rules/postcode.py` (D19): districts are normalised outward codes.
- `docs/spec/domain-rules.md` sections 4.1 and 4.2.

**Rules you need.**
- A service passes when: criteria status is `current`; the case district is in the criteria districts; no case need is in `excludes`; every case need is in `accepts`; and the age band fits.
- Age band bounds: `0-15` = 0–15, `16-64` = 16–64, `65-79` = 65–79, `80+` = 80–no limit. `age_max = None` means no limit.
- Band fully inside `[age_min, age_max]` → pass. Overlaps partly → pass with warning `Check age: band overlaps the service's age limits` [ASSUMED]. No overlap → fail.
- Reasons (one per failed check, in this order): `Criteria not current`; `Does not cover {district}`; `Does not accept {need}` (excluded need); `Does not take {need}` (need not in accepts); `Age {band} outside {age_min} to {age_max or "no limit"}`. `{need}` is the code value.
- Example, UCR West v3: accepts fall-no-injury, frailty; excludes suspected-fracture, head-injury-anticoagulants, iv-therapy; age 18+; districts DT1–DT4.

**Build.**
- `domain/model/criteria.py`: `ServiceCriteria` as in contracts.md. `__post_init__` validates: `version >= 1`, `age_min >= 0`, `age_max is None or age_max >= age_min`, `accepts` and `excludes` disjoint, districts upper-case.
- `domain/rules/criteria_filter.py`: `FilterResult(passes, reasons, warnings)`, `check_hard_criteria(criteria, age_band, district, needs) -> FilterResult`; `AGE_BAND_BOUNDS: dict[AgeBand, tuple[int, int | None]]`.

**Tests to write first.** (use UCR West v3 above)
1. 80+, DT4, [fall-no-injury, frailty] → passes, no reasons, no warnings.
2. 16-64, DT4, [frailty] → passes with the age warning (16–17 outside 18+).
3. 0-15, DT4, [frailty] → fails with `Age 0-15 outside 18 to no limit`.
4. 80+, DT5, [frailty] → fails `Does not cover DT5`.
5. 80+, DT4, [frailty, suspected-fracture] → fails `Does not accept suspected-fracture`.
6. 80+, DT4, [wound-care] → fails `Does not take wound-care`.
7. Status `pending-approval` → fails `Criteria not current`.
8. Two failures give two reasons in the stated order.
9. Empty needs pass the need checks.
10. Constructing criteria with a need in both lists raises `ValidationFailed`.
