**Goal.** Encode the clinical advice queue: taking a request locks it, an idle request returns to the queue after 10 minutes, and presence counts.

**Read first.**
- `backend/src/diucs/domain/errors.py`: `Conflict`, `InvalidTransition`, `NotAllowed`, `ValidationFailed`.
- `docs/spec/domain-rules.md` section 5; `docs/spec/ui-screens.md` artboard "ClinicalAdvisor".

**Rules you need.**
- Presence: `available`, `busy`, `away`. Advisors see only the count of available clinical advisors.
- Urgency of a request: `now` or `within-15-min`. Queue order: `now` first, then `within-15-min`; oldest first within each.
- Taking a request locks it to one clinical advisor. Nobody else can take it while locked.
- If the taker has not given advice within 10 minutes of taking, it returns to the queue (taken fields cleared).
- Only the taker can give advice. Advice can be given once.
- Going away returns that person's unadvised requests to the queue.
- An optional note is at most 280 characters.

**Build.** `domain/rules/clinical_queue.py`:
- `TAKE_TIMEOUT = timedelta(minutes=10)`, `NOTE_MAX = 280`
- `Presence` StrEnum; `ClinicalRequest` as in contracts.md (`urgency` is `"now"` or `"within-15-min"`, validated)
- `take(request, clinician_id, now) -> ClinicalRequest` (raises `Conflict` if locked by someone else and not idle; `InvalidTransition` if already advised)
- `return_if_idle(request, now) -> ClinicalRequest`
- `give_advice(request, clinician_id, now) -> ClinicalRequest` (raises `NotAllowed` if not the taker, `InvalidTransition` if advised)
- `release_for_away(requests, clinician_id) -> list[ClinicalRequest]` (returns the released copies)
- `available_count(presences: Iterable[Presence]) -> int`
- `queue_order(requests) -> list[ClinicalRequest]` (only unadvised, untaken)
- `validate_note(note: str) -> None`

**Tests to write first.**
1. `take` at 14:13 by "c1" sets `taken_by="c1"`, `taken_at=14:13`.
2. Second `take` by "c2" at 14:15 raises `Conflict`; at 14:23 (10 min idle) succeeds for "c2".
3. `return_if_idle` at 14:22:59 keeps the lock; at 14:23:00 clears it.
4. `give_advice` by "c2" on c1's request raises `NotAllowed`; by "c1" sets `advised_at`; again raises `InvalidTransition`.
5. `release_for_away` returns c1's two unadvised requests cleared and ignores advised ones.
6. `queue_order`: within-15-min at 14:00, now at 14:05, now at 14:01 → [now 14:01, now 14:05, within-15 14:00].
7. `available_count([available, busy, available, away]) == 2`.
8. 281-character note raises `ValidationFailed`.
