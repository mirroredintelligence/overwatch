**Goal.** Encode the identity rules for reporters and COO or ICB users: text codes, PIN attempts and locking, and when to re-verify by text code.

**Read first.**
- `backend/src/diucs/domain/errors.py`; `backend/src/diucs/domain/rules/london_time.py` (F06) for time handling style.
- `docs/spec/domain-rules.md` section 7.

**Rules you need.**
- Text code: 6 digits, valid 10 minutes, 5 wrong tries then a new code is needed. A new code can be requested 60 seconds after the last was sent [ASSUMED].
- PIN: exactly 6 digits. 5 wrong tries lock it. A text code resets it (clears the counter and the lock). The PIN itself is never in this module.
- Re-verify by text code every 30 days and on any new device.

**Build.** `domain/rules/identity_policy.py`:
- Constants `CODE_VALID_FOR = timedelta(minutes=10)`, `CODE_MAX_TRIES = 5`, `CODE_RESEND_AFTER = timedelta(seconds=60)`, `PIN_MAX_TRIES = 5`, `REVERIFY_EVERY = timedelta(days=30)`.
- `CodeOutcome` StrEnum: `verified`, `wrong`, `expired`, `too-many-tries`.
- `CodeState(issued_at: datetime, failed_tries: int = 0, verified: bool = False, last_outcome: CodeOutcome | None = None)`.
- `code_attempt(state, entered_ok: bool, now) -> CodeState`: expired if `now >= issued_at + 10 min` (tries unchanged); too-many-tries if `failed_tries >= 5` already; ok → verified; wrong → `failed_tries + 1`, and when that reaches 5 the outcome is `too-many-tries`. A verified code cannot be used again (outcome `expired`).
- `can_resend(last_sent_at, now) -> bool`.
- `PinOutcome` StrEnum: `ok`, `wrong`, `locked`. `PinState(failed_tries: int = 0, locked: bool = False, last_outcome: PinOutcome | None = None)`.
- `pin_attempt(state, ok: bool, now) -> PinState`: locked stays locked (outcome locked); ok resets tries; wrong adds 1 and locks at 5.
- `reset_pin_state() -> PinState`.
- `validate_pin_format(pin: str) -> None` (raises `ValidationFailed` unless exactly 6 ASCII digits).
- `needs_reverification(last_verified_at: datetime | None, now, device_known: bool) -> bool`.

**Tests to write first.**
1. Code issued 09:00: correct at 09:09:59 → verified; at 09:10:00 → expired.
2. Four wrong then right → verified with `failed_tries == 4`; five wrong → fifth outcome `too-many-tries`; a sixth correct attempt → `too-many-tries`.
3. Using a verified code again → `expired`.
4. `can_resend(09:00:00, 09:00:59)` False; `09:01:00` True.
5. PIN: 4 wrong then ok → tries 0, outcome ok; 5 wrong → locked; ok while locked → locked; `reset_pin_state()` → unlocked, 0.
6. `validate_pin_format`: "123456" ok; "12345", "1234567", "12a456", "１２３４５６" (full-width) raise.
7. `needs_reverification`: unknown device → True; last None → True; 29 days 23 h → False; exactly 30 days → True.
