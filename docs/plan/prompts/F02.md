You are a software engineer picking up one task in the `overwatch` repository (product name: DIUCS capacity). You have no memory of any earlier work. Everything you need is in this prompt and in the repository.

**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Back-end conventions.**
- Python 3.14, managed with `uv`. Start the databases first, from the repo root: `docker compose -f infra/docker-compose.yml up -d`. Then run from `backend/`: `uv run pytest`, `uv run ruff check . && uv run ruff format --check .`, `uv run mypy src` (strict), `uv run lint-imports`. `uv run pytest tests/unit` runs only the pure tests, without Docker.
- **Neo4j connections follow DEC-012**: one driver per process from the composition root, sessions per unit of work always closed, bounded lifetimes and liveness checks, idempotent retried writes, and workers that resume after an outage without losing work. A back-end task that opens a connection must follow it and prove recovery where the task says so.
- **Neo4j in Docker is the only store in tests.** Anything Neo4j stores (repositories, unit of work, audit, outbox, idempotency, tokens, scheduled work, communications, credentials) has no in-memory fake: tests use the real `Neo4j<Port>` adapters through the harness in `backend/tests/support/` (`neo4j_driver`, `clean_graph`, `write_tx`, `read_tx`, `assert_round_trip`, `count_nodes`, `node_props`, `uow_factory`). Use-case and repository tests live in `backend/tests/integration/` and assert on what was really stored, read back in a fresh session. Fakes exist only for external providers and non-record stores: `FixedClock`, `SequentialIds`, `Recording*Sender`, `ManualEventBus`, `InMemoryCache`, `InMemoryCodeStore`, `FixedSecretStore`, `Fixed*` geo and terminology, `PassThroughValidator`. - Value objects are `@dataclass(frozen=True, slots=True)`. Codes are `enum.StrEnum` from `diucs.domain.codes`. Datetimes are timezone-aware UTC; domain functions take `now` as an argument and never read the clock.

- Pure tests mirror the source path under `backend/tests/unit/`; tests that need Neo4j, Redis or Service Bus mirror it under `backend/tests/integration/`. Use `pytest` with `asyncio_mode = "auto"`; prefer plain asserts and parametrised cases.

**Goal.** Make the build fail when code crosses the hexagonal boundaries, so the layering cannot rot as dozens of people add code.

**Read first.**
- `backend/pyproject.toml` (F01): add `import-linter` config there or in `backend/.importlinter`.
- `docs/spec/architecture.md`, "Rules the codebase enforces" and "Dependency injection and testing".

**Rules you need.**
- The domain imports nothing outside the standard library, `diucs.domain` and `fhir.resources` (which pulls in pydantic; that is allowed only through `fhir.resources`).
- The application layer imports only the domain and itself. It never imports `diucs.adapters` or `diucs.bootstrap`.
- An adapter never imports another adapter: each package under `diucs.adapters.inbound.*` and `diucs.adapters.outbound.*` is independent of the others. `diucs.adapters.testing` may import application and domain, never real adapters.
- Only `diucs.bootstrap` may import adapters to wire them.

**Build.**
- `backend/.importlinter` (and `include_external_packages = True`) with these contracts:
  1. `layers`: `diucs.bootstrap` > `diucs.adapters` > `diucs.application` > `diucs.domain`.
  2. `forbidden`: source `diucs.domain`, forbidden `fastapi`, `neo4j`, `redis`, `azure`, `httpx`, `twilio`, `pydantic_settings`, `diucs.application`, `diucs.adapters`, `diucs.bootstrap`.
  3. `forbidden`: source `diucs.application`, forbidden the same third-party list plus `diucs.adapters`, `diucs.bootstrap`.
  4. `independence`: `diucs.adapters.inbound.*`, `diucs.adapters.outbound.*`, `diucs.adapters.testing` (use import-linter wildcards; check the installed version supports them, otherwise list the packages that exist and add a comment telling later tasks to append theirs).
- `backend/tests/architecture/test_import_rules.py`.
- A `make lint` step that runs `uv run lint-imports`.
