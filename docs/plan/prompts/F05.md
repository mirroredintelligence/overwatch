You are a software engineer picking up one task in the `overwatch` repository (product name: DIUCS capacity). You have no memory of any earlier work. Everything you need is in this prompt and in the repository.

**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Back-end conventions.**
- Python 3.14, managed with `uv`. Start the databases first, from the repo root: `docker compose -f infra/docker-compose.yml up -d`. Then run from `backend/`: `uv run pytest`, `uv run ruff check . && uv run ruff format --check .`, `uv run mypy src` (strict), `uv run lint-imports`. `uv run pytest tests/unit` runs only the pure tests, without Docker.
- **Neo4j connections follow DEC-012**: one driver per process from the composition root, sessions per unit of work always closed, bounded lifetimes and liveness checks, idempotent retried writes, and workers that resume after an outage without losing work. A back-end task that opens a connection must follow it and prove recovery where the task says so.
- **Neo4j in Docker is the only store in tests.** Anything Neo4j stores (repositories, unit of work, audit, outbox, idempotency, tokens, scheduled work, communications, credentials) has no in-memory fake: tests use the real `Neo4j<Port>` adapters through the harness in `backend/tests/support/` (`neo4j_driver`, `clean_graph`, `write_tx`, `read_tx`, `assert_round_trip`, `count_nodes`, `node_props`, `uow_factory`). Use-case and repository tests live in `backend/tests/integration/` and assert on what was really stored, read back in a fresh session. Fakes exist only for external providers and non-record stores: `FixedClock`, `SequentialIds`, `Recording*Sender`, `ManualEventBus`, `InMemoryCache`, `InMemoryCodeStore`, `FixedSecretStore`, `Fixed*` geo and terminology, `PassThroughValidator`. Never write an `InMemory*Repository`. Details: the "Testing and persistence" section of `docs/spec/contracts.md`.
- Value objects are `@dataclass(frozen=True, slots=True)`. Codes are `enum.StrEnum` from `diucs.domain.codes`. Datetimes are timezone-aware UTC; domain functions take `now` as an argument and never read the clock.
- Domain code imports only the standard library, `diucs.domain` and `fhir.resources`. Use cases receive every port through the constructor and expose `async def execute(self, command)`.
- Errors subclass `diucs.domain.errors.DomainError`.
- Pure tests mirror the source path under `backend/tests/unit/`; tests that need Neo4j, Redis or Service Bus mirror it under `backend/tests/integration/`. Use `pytest` with `asyncio_mode = "auto"`; prefer plain asserts and parametrised cases.
- Shared conventions that win over anything in the task text below (each applies once the named task's file exists; see the "Additions" section of `docs/spec/contracts.md`):

**Goal.** Add a GitHub Actions pipeline that runs every check on each push and pull request. Because all repository and use-case tests run against Neo4j in Docker, the main back-end job starts the Docker services before running pytest.

**Read first.**
- `backend/Makefile`, `backend/pyproject.toml` (F01) and `backend/.importlinter` (F02).
- `frontend/package.json` (F03).
- `infra/docker-compose.yml` (F04).
- `docs/spec/architecture.md`, "Technology choices and versions": run Python 3.15 alongside 3.14.

**Rules you need.**
- Triggers: `push` to any branch and `pull_request`. `concurrency` group per ref, cancelling superseded runs. Top-level `permissions: contents: read`.
- Jobs:
  1. `backend-static`: matrix Python `3.14` and `3.15` (3.15 may fail: `continue-on-error` on that leg only). Steps: checkout, `astral-sh/setup-uv`, `uv sync --frozen`, ruff check, ruff format `--check`, mypy, lint-imports, `pytest tests/unit`.
  2. `backend`: Python 3.14. `docker compose -f infra/docker-compose.yml up -d --wait`, then `uv run pytest` (the whole suite, including integration), then `docker compose ... logs neo4j` on failure, and `docker compose ... down -v` with `if: always()`.
  3. `frontend`: Node 22, pnpm via `pnpm/action-setup`, `pnpm install --frozen-lockfile`, lint, typecheck, test, build.
  4. `e2e`: `needs: frontend`; installs Playwright browsers, runs `pnpm e2e`, uploads the report on failure.
- Pin every action to a major version tag you have checked exists.

**Build.**
