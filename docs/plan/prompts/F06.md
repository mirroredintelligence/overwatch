**Goal.** Give the code one way to ask the time and one way to make ids, plus London-time helpers, so rules can be tested with a fixed clock and schedules work across clock changes.

**Read first.**
- `backend/src/diucs/domain/errors.py` (F01).
- `docs/spec/domain-rules.md`, the opening paragraph: domain times are UTC; schedules are computed in Europe/London.
- `docs/spec/contracts.md`, `rules/london_time.py`.

**Rules you need.**
- All datetimes are timezone-aware UTC. A naive datetime passed in is a bug: raise `ValueError`.
- Across a clock change the local time is kept: 10:00 stays 10:00 local, so the UTC time moves by an hour.
- Nonexistent local time (spring gap, 2026-03-29 01:00–02:00): shift forward. Ambiguous local time (autumn fold, 2026-10-25 01:00–02:00): use the first occurrence (still BST).

**Build.**
- `application/ports/outbound/clock.py`: `class Clock(Protocol): def now(self) -> datetime`.
- `application/ports/outbound/ids.py`: `class IdGenerator(Protocol): def new_id(self) -> str`.
- `adapters/outbound/clock_system/system_clock.py`: `SystemClock` (UTC now). `adapters/outbound/ids_uuid/uuid_ids.py`: `UuidGenerator` (uuid4 string).
- `adapters/testing/fixed_clock.py`: `FixedClock(at: datetime)` with `now()`, `set(at)`, `advance(delta)`; rejects naive datetimes. `adapters/testing/fixed_ids.py`: `SequentialIds(prefix="id")` giving `id-1`, `id-2`, …
- `domain/rules/london_time.py`: `LONDON = ZoneInfo("Europe/London")`; `to_london(dt) -> datetime`; `london_to_utc(d: date, t: time) -> datetime`; `format_hhmm(dt) -> str`.

**Tests to write first.**
1. `london_to_utc(date(2026, 1, 15), time(10, 0))` → `2026-01-15T10:00Z`.
2. `london_to_utc(date(2026, 7, 1), time(10, 0))` → `2026-07-01T09:00Z`.
3. Gap: `london_to_utc(date(2026, 3, 29), time(1, 30))` → `2026-03-29T01:30Z` (that is 02:30 BST).
4. Fold: `london_to_utc(date(2026, 10, 25), time(1, 30))` → `2026-10-25T00:30Z` (first occurrence, BST).
5. Same local time either side of the change: 10:00 on 2026-10-24 → 09:00Z; 10:00 on 2026-10-26 → 10:00Z.
6. `format_hhmm(datetime(2026, 10, 23, 13, 19, tzinfo=UTC))` → `"14:19"`; in January `13:19Z` → `"13:19"`.
7. `to_london` and `format_hhmm` with a naive datetime raise `ValueError`.
8. `FixedClock`: `now()` returns the set time; `advance(timedelta(minutes=5))` moves it; constructing with a naive datetime raises.
9. `SystemClock().now().tzinfo` is UTC. `UuidGenerator().new_id()` parses as a UUID4 and two calls differ. `SequentialIds()` yields `id-1`, `id-2`.
