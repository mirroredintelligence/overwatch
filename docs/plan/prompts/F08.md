You are a software engineer picking up one task in the `overwatch` repository (product name: DIUCS capacity). You have no memory of any earlier work. Everything you need is in this prompt and in the repository.

**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Rules you need.**
- Settings come from environment variables prefixed `DIUCS_`. A settings value swaps an adapter without a code change.
- Profiles: `test` and `production`. Both use Neo4j for everything Neo4j stores; there is no in-memory store profile. They differ only in external providers: `test` wires recording or fixed fakes for SMS, email, push, geocoder, travel time and terminology; `production` wires the real adapters (added by later tasks). Default `test`. Both use the system clock and UUIDs; tests that need fixed time use `build_for_tests`.
- Secrets are `SecretStr` and never appear in `repr`.

**Build.**
- `bootstrap/settings.py`: `class Settings(BaseSettings)` (`env_prefix="DIUCS_"`) with `profile: Literal["test", "production"] = "test"`, `base_url: str = "https://diucs.example/"`, `neo4j_uri: str = "bolt://localhost:7687"`, `neo4j_user: str = "neo4j"`, `neo4j_password: SecretStr = SecretStr("diucs-test-password")`, `redis_url: str = "redis://localhost:6379/0"`, `servicebus_connection: SecretStr | None = None`, `sms_provider: Literal["twilio", "govuk-notify", "none"] = "none"`.
- `bootstrap/container.py`: `@dataclass(frozen=True) class Container` with `clock: Clock`, `ids: IdGenerator`, and a comment that each later task adds one field. `def build(settings: Settings) -> Container`. `def build_for_tests(clock: Clock | None = None, ids: IdGenerator | None = None) -> Container` (defaults `FixedClock(2026-10-23T13:00Z)` and `SequentialIds()`).
