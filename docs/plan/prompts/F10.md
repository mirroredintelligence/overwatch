**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build the shared Neo4j test harness every repository, use-case and API test uses. Tests run against the real Neo4j in Docker, start from an empty graph, and prove persistence by reading back in a fresh session.

**Read first.**
- `backend/tests/conftest.py`, `backend/pyproject.toml` (F01).
- `infra/docker-compose.yml`, `infra/README.md` (F04).
- `backend/src/diucs/adapters/outbound/graph_store/driver.py`, `migrations.py` (G01): `create_driver`, `apply_migrations`.
- `docs/spec/contracts.md`, section "Testing and persistence": the exact fixture and helper names.

**Rules you need.**
- Connection from env with defaults: `NEO4J_URI=bolt://localhost:7687`, `NEO4J_USER=neo4j`, `NEO4J_PASSWORD=diucs-test-password`.
- If Neo4j cannot be reached within 5 seconds, fail the session at once with exactly: `Neo4j is not running. Start it with: docker compose -f infra/docker-compose.yml up -d neo4j`. Never skip silently.
- One Community database, so tests run serially. Do not add pytest-xdist.
- The driver and its event loop are session-scoped. Set `asyncio_default_fixture_loop_scope = "session"` and the test loop scope to session as well, using the option names of the installed pytest-asyncio version (check its docs).
- Cleaning: before each integration test delete all nodes and relationships in batches of 10,000 (`MATCH (n) WHERE NOT n:Migration WITH n LIMIT 10000 DETACH DELETE n RETURN count(n)`, repeated until 0). Keep constraints, indexes and `:Migration` nodes.
- Round trip means two separate transactions in two separate sessions: commit the write, then read in a new session.

**Build.**
- `backend/tests/support/__init__.py`, `backend/tests/support/neo4j.py`: `connect_or_fail(uri, user, password, timeout_s=5) -> AsyncDriver`; `async write_tx(driver, fn)` and `async read_tx(driver, fn)` (fresh session, managed transaction, return `fn(tx)`'s result); `async count_nodes(driver, label) -> int`; `async node_props(driver, label, **match) -> dict` (exactly one match, else `AssertionError` naming the count); `async wipe(driver)`.
- `backend/tests/support/round_trip.py`: `async assert_round_trip(driver, save, load, expected)`: `save(tx)` in a committed write transaction, `load(tx)` in a new read session, then `assert loaded == expected`; also asserts every `datetime` in the loaded value (walking dataclasses, dicts, lists, tuples) is timezone-aware UTC.
- `backend/tests/conftest.py`: session fixture `neo4j_driver` (connects, runs `apply_migrations` once, closes at the end); autouse fixture `clean_graph` active only for items under `tests/integration/`.

**Tests to write first** (in `tests/integration/support/`).
