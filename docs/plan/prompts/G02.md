**Goal.** Start the pure mapper that turns a FHIR R4B resource (a JSON dict) into a property-graph fragment and back. This task covers resources, primitive elements and references. The mapper does no I/O; G05 writes its output to Neo4j and proves it in the database.

**Read first.**
- `docs/spec/fhir-data-model.md`, sections "Approach", "Mapping rules" (R1–R3) and "Relationship catalogue".
- `backend/src/diucs/domain/codes.py` (F07): `BASE_URL`.

**Rules you need.**
- R1 Resource → node with labels `Resource` and the resource type. Properties `id`, `versionId`, `lastUpdated`, `iri`, `json`. `iri = f"{BASE_URL}fhir/{type}/{id}"`. `json` is canonical: `json.dumps(resource, sort_keys=True, separators=(",", ":"))`.
- R2 Primitive → property with the FHIR element name. Dates stay ISO 8601 strings with zone. Repeating primitives become lists.
- R3 Reference → relationship named after the element in UPPER_SNAKE_CASE (`providedBy` → `PROVIDED_BY`) with `fhirPath` (`"HealthcareService.providedBy"`), `order` (only when the element repeats, 0-based) and `display` (when given). The target is keyed by type and id and may not exist yet.
- Every relationship carries `fhirPath`. Labels are resource names, properties lower camel case, relationship types upper snake case.

**Build.** In `adapters/outbound/graph_store/mapper.py`:
- `NodeSpec(key, labels: tuple[str, ...], properties: dict)`, `RelSpec(type, start, end, properties: dict)`, `GraphFragment(root_key, nodes, rels)`. A resource node key is `"Type/id"`.
- `to_graph(resource: dict) -> GraphFragment`; `from_graph(fragment) -> dict` (rebuilds from the decomposed properties and relationships, not from `json`); `upper_snake(name) -> str`.
- Elements not mapped yet (CodeableConcept, Identifier, backbone elements, extensions) raise `UnsupportedElement(path)`; G03 and G04 remove those cases.

**Tests to write first** (pure, in `tests/unit/adapters/graph_store/`).
1. `upper_snake("providedBy") == "PROVIDED_BY"`, `upper_snake("partOf") == "PART_OF"`.
2. An `Organization` with `id`, `active: true`, `name: "Dorset HealthCare"`, `alias: ["DHC", "Dorset HC"]` gives one node with labels `("Resource", "Organization")`, `alias` as a list, `iri` ending `fhir/Organization/<id>`.
3. A `Location` with `partOf: {"reference": "Location/l0", "display": "Site"}` gives `PART_OF` to `Location/l0` with `fhirPath "Location.partOf"` and `display "Site"`.
4. `HealthcareService.location` with two items gives two rels, `order` 0 and 1.
5. `from_graph(to_graph(r)) == r` for the Organization and Location.
6. Two dicts with different key order give the same `json`.
7. A CodeableConcept raises `UnsupportedElement("Organization.type")`.
