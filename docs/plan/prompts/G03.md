**Goal.** Extend the mapper so coded values become shared concept nodes, identifiers become shared identifier nodes, and periods, quantities and ranges are flattened onto their owner. This makes "all services that accept falls" a relationship walk.

**Read first.**
- `backend/src/diucs/adapters/outbound/graph_store/mapper.py` (G02): fragment types and `UnsupportedElement`.
- `docs/spec/fhir-data-model.md`: rules R5, R6, R7, R11 and the "Capacity report (Observation)" table.

**Rules you need.**
- R5 CodeableConcept and Coding → shared node `(:Concept {system, code, display, version})` keyed `"Concept|<system>|<code>"`. The relationship from the resource is named after the element (`CATEGORY`, `CODE`, `METHOD`, `INTERPRETATION`, `TYPE`, `SPECIALTY`, `REFERRAL_METHOD`, ...) and carries `fhirPath`, `text` (the CodeableConcept's text, if any) and `userSelected`. Each concept also gets `-[:IN_SYSTEM]->(:CodeSystem {url})` keyed `"CodeSystem|<url>"`. Two codings in one CodeableConcept give two relationships with `order`.
- R6 Identifier → `(:Identifier {system, value, use})` keyed `"Identifier|<system>|<value>"`, linked by `IDENTIFIED_BY` (`fhirPath`, `use`). An ODS organisation identifier is also copied to `odsCode` on the resource node. **Open decision:** the ODS system URIs are unverified. Use `ODS_ORG_SYSTEM = "https://fhir.nhs.uk/Id/ods-organization-code"` and `ODS_SITE_SYSTEM = "https://fhir.nhs.uk/Id/ods-site-code"` with a `# VERIFY against NHS England FHIR docs` comment.
- R7 Period, Quantity, Range → flattened with a prefix: `periodStart`, `periodEnd`, `valueQuantity_value`, `valueQuantity_unit`, `valueQuantity_system`, `valueQuantity_code`.
- R11 Frequently filtered code → also `<element>Code`: `FILTER_CODE_PROPERTIES = {("Observation", "code"): "measureCode"}`.
- Copied properties (`odsCode`, `measureCode`) never leak back into the rebuilt JSON.

**Build.** Extend `to_graph` and `from_graph` in `mapper.py`. Shared nodes appear once per fragment even if used twice.

**Tests to write first** (pure, `tests/unit/adapters/graph_store/`).
1. Observation with `code.coding[0] = {system: "https://diucs.example/CodeSystem/capacity-measure", code: "referrals-acceptable"}` → `CODE` rel to the concept, an `IN_SYSTEM` rel, and `measureCode == "referrals-acceptable"`.
2. `valueQuantity {value: 3, unit: "referral", system: "http://unitsofmeasure.org", code: "{referral}"}` flattens to four `valueQuantity_*` properties.
3. A HealthcareService with two `category` codings in one CodeableConcept → two `CATEGORY` rels, `order` 0 and 1, `text` on both.
4. An Organization with an ODS identifier → `Identifier` node, `IDENTIFIED_BY`, and `odsCode`.
5. Two resources using the same concept produce the same concept key.
6. `from_graph(to_graph(r)) == r` for an Observation capacity report and an Organization with type and identifier.
