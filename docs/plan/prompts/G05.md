**Goal.** Persist mapper fragments in Neo4j and read resources back, with optimistic versioning and history. **Rules you need.**
- The store is created per transaction: `ResourceStore(tx, clock)`. The unit of work (P06) creates one on its transaction and hands it to every repository.
- FHIR JSON is canonical: `get` returns the parsed `json` property, not a rebuild. The decomposed properties and relationships exist for queries.
- Shared nodes (`Concept`, `CodeSystem`, `Identifier`) are `MERGE`d. A reference to a resource that does not exist yet `MERGE`s `(:Resource:<Type> {id, placeholder: true})`; writing that resource later removes `placeholder`.
- R10 Versions: each update stores the previous state as `(:ResourceVersion {versionId, lastUpdated, json})` linked by `HAS_VERSION {versionId}`. `versionId` starts at "1". An update states the version it replaces; a mismatch raises `Conflict` (this backs `If-Match`). A create (`expected_version=None`) on an existing id raises `Conflict`.
- Observations are never updated: a second `put` of an existing Observation raises `NotAllowed`.
- Privacy: `NO_HISTORY_TYPES = {"Patient", "ServiceRequest"}` keep no `ResourceVersion`, so a cleared postcode is gone everywhere.
- On update, delete the resource's own child element nodes and outgoing relationships, then recreate them. Never delete incoming relationships or shared nodes. Extra labels or local relationships a repository adds after `put` (for example `ServiceCriteria`, `CURRENT_CRITERIA`) are the repository's job to rewrite in the same transaction.
- `position = point({latitude, longitude})` on Locations with both coordinates.
- `meta.versionId` and `meta.lastUpdated` (UTC ISO 8601 with `Z`) are set from the clock (system clock when omitted).

**Build.** `adapters/outbound/graph_store/resource_store.py`: `ResourceStore(tx, clock: Clock | None = None)` with `async put(resource: dict, expected_version: str | None) -> str`, `async get(type: str, id: str) -> dict | None`, `async history(type, id) -> list[dict]`, `async exists(type, id) -> bool`. Named queries `Q-RES-GET`, `Q-RES-UPSERT-ROOT`, `Q-RES-CLEAR-OWNED`, `Q-RES-SNAPSHOT`, `Q-RES-HISTORY`, `Q-RES-MERGE-NODES`, `Q-RES-MERGE-RELS` (use `UNWIND` batches).

**Tests to write first** (`tests/integration/graph_store/test_resource_store.py`, against the Docker Neo4j through F10's harness).
1. `assert_round_trip`: `put` a new Organization in one transaction, `get` it in a fresh session → same JSON plus `meta.versionId "1"` and the fixed `lastUpdated`.
2. `put` with `expected_version="1"` returns "2"; `count_nodes(driver, "ResourceVersion") == 1`; `history` returns version 1.
3. A stale `expected_version` raises `Conflict`, and the stored version is unchanged.
4. A second `put` of an Observation raises `NotAllowed`.
5. Updating a HealthcareService from two `availableTime` entries to one leaves one child node; shared `Concept` nodes remain.

7. Updating a Patient stub to remove `address`: no `ResourceVersion`, and a Cypher search for the old postcode on any node property finds nothing.
8. A Location with a position has a `position` point (`node_props`).
9. The UCR West HealthcareService from G04 round-trips through Neo4j exactly, and `from_graph` of the stored decomposed form equals the stored `json`.
