**Rules you need.**
- Do not create `GraphCriteriaRepository` or `GraphFlagRepository`. Criteria storage belongs to P04; flags belong to P14 (`FlagRepository`). Suspension comes from active `ServiceFlag` nodes with code `suspended`, not from a property on the service.
- Band bounds: `0-15` = 0–15, `16-64` = 16–64, `65-79` = 65–79, `80+` = 80 to no limit.
- The database pre-filter checks age overlap; the domain then decides pass or "Check age" warning. Register `Q-CRIT-FILTER`:
```
MATCH (s:HealthcareService {active: true})-[:CURRENT_CRITERIA]->(c:ServiceCriteria {status: 'current'})
WHERE c.ageMin <= coalesce($bandMax, 999) AND (c.ageMax IS NULL OR $bandMin <= c.ageMax)
  AND $district IN c.postcodeDistricts
  AND NOT EXISTS { MATCH (c)-[:EXCLUDES_NEED]->(x:Concept) WHERE x.code IN $needs }
  AND ALL(n IN $needs WHERE EXISTS { MATCH (c)-[:ACCEPTS_NEED]->(a:Concept) WHERE a.code = n })
  AND NOT EXISTS { MATCH (f:ServiceFlag {code: 'suspended', status: 'active'})-[:SUBJECT]->(s) }
RETURN s.id AS serviceId, c.json AS criteria
```
  Adjust labels and property names only to match what P04 and P14 actually store, and say so in your summary.
- `Q-CRIT-HISTORY` (query #6): `MATCH (c:ServiceCriteria {status:'current'})-[:SUBJECT]->(:HealthcareService {id:$id}) MATCH (c)-[:SUPERSEDES*0..]->(old:ServiceCriteria) RETURN old.json ORDER BY old.version DESC`.
