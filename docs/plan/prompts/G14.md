**Goal.** Make every Neo4j connection owned, bounded, health-checked and recoverable, as DEC-012 requires. G01 provides the driver; G14 adds the lifecycle around it: one driver per process, managed sessions, staleness prevention, a health check, and proof that the system recovers when Neo4j restarts. Everything later (the unit of work, the workers, the API) depends on this.

**Read first.**

- `backend/src/diucs/adapters/outbound/graph_store/driver.py` (G01): the driver factory and named-query registry you extend.

**Build.**
- `connection.py`: `Neo4jConnection`, which owns the `AsyncDriver`. It exposes `async open()` (creates the driver with the DEC-012 options and calls `verify_connectivity()`), `async close()` (closes the driver; idempotent), `session()` (a managed session as an async context manager, always closed), and `async run_read(fn)` / `run_write(fn)` wrapping the driver's managed transactions.
- Settings for the four DEC-012 values, with the defaults stated in the decision. Read them from `DIUCS_NEO4J_*` environment variables.
- `health.py`: `async neo4j_health(conn, timeout) -> Health` returning `ok` or `degraded` with a reason. It never raises.
- Wire `open()` and `close()` into the container's startup and shutdown.

**Tests to write first.** Integration tests in `backend/tests/integration/graph_store/test_connection_recovery.py`, using the harness.
1. Opening with a bad password fails at startup with a message that names the host and port but not the password.
2. After `close()`, a second `close()` is a no-op, and using the connection raises a clear error.
3. A session is closed after a successful operation and after an exception (count open sessions before and after).
4. A write that raises mid-transaction leaves no node behind (rollback).
5. Stop the Neo4j container during a read, then start it again. The in-flight call fails with a retryable error. Within 60 seconds of restart, a new call succeeds, and `neo4j_health` reports `ok`.
6. Health reports `degraded` while Neo4j is stopped, and never raises.
7. Closing the connection leaves zero open connections (check the driver's pool metrics or the connection count the driver exposes).
8. The log output for all of the above contains no password and no patient data.
