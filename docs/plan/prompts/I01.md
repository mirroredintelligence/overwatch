**Rules you need.**
- Redis is a cache only. Losing it means people sign in again and pages refetch; nothing of record lives here (records live in Neo4j).
- Key families, always prefixed `diucs:`: `diucs:cache:<name>`, `diucs:lock:<name>`, `diucs:fence:<name>`, `diucs:chan:<channel>`. Telemetry may record the key family but never the full key (a key can contain an id).
- Values are stored as JSON strings unless the Protocol says bytes.
- Locks: `acquire_lock(name, ttl)` does `INCR diucs:fence:<name>` for a fencing token, then `SET diucs:lock:<name> <token> NX PX <ttl_ms>`. If the `SET` fails, return `None`. `release_lock(lock)` deletes the key only if its value is still that token (Lua compare-and-delete), so a holder whose lock expired cannot release a newer holder's lock. Tokens strictly increase.
- Publish/subscribe: `publish(channel, message)` on `diucs:chan:<channel>`; `subscribe(channel)` returns an async iterator of decoded messages and unsubscribes when the iterator is closed. A missed message is harmless because pages refetch.
- **Open decision:** Azure Cache for Redis versus Azure Managed Redis. Use plain `redis.asyncio` with TLS and password from settings so either works; no vendor-specific modules.

**Build.** `backend/src/diucs/adapters/outbound/cache_redis/redis_cache.py`: `RedisCache(client: redis.asyncio.Redis)` implementing `Cache`; `RedisCache.from_url(url)`. Setting `redis_url` (default `redis://localhost:6379/0`). Add a `redis` factory to the cache contract suite next to the `InMemoryCache` one; the Redis run lives under the integration marker and flushes only `diucs:*` keys between tests.

**Tests to write first.**
1. Contract (both factories): `set("a", {"x": 1}, ttl=timedelta(seconds=1))` then `get("a")` returns the value; after expiry (`sleep` 1.2 s on Redis, manual clock on the fake) it returns `None`.
2. Contract: `delete` removes the value.
3. Contract: `acquire_lock("outbox-relay", ttl)` returns a lock; a second acquire returns `None`; after release a third acquire succeeds with a larger fencing token.
4. Contract: an expired lock's holder calling `release_lock` does not remove the new holder's lock.
5. Contract: a subscriber receives two messages published on `board.updates` in order.
6. Redis only: closing the subscription iterator unsubscribes (`PUBSUB NUMSUB` drops to 0).
7. Unit: every key passed to the client starts with `diucs:` (recording stub client, no Docker).
