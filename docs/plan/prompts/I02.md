**Goal.** Implement the `EventBus` port on Azure Service Bus: publish domain events and outbound messages, schedule work for a future time, and cancel scheduled work. Service Bus is infrastructure we do not own, so `ManualEventBus` stays as the fake for use-case tests; this adapter must pass the same event-bus contract suite against the Service Bus emulator.

**Rules you need.**
- Entities: queues `inbound.replies`, `inbound.receipts`, `scheduled.work`; topics `capacity.events`, `booking.events`, `registration.events`, `criteria.events`, `alerts.events`, `messages.outbound`. `publish(message)` sends to the entity named by `message.topic`; an unknown name raises `ValueError`.
- Every Service Bus message sets `message_id = BusMessage.id` (duplicate detection), `session_id = BusMessage.session_id` when given (capacity events use the service id so one service's events stay in order), `subject = event_type`, `application_properties = {"event_type": ..., "channel": ...}` (channel only when the payload has one, so `messages.outbound` subscriptions can filter on it), body = JSON payload, `content_type = "application/json"`.
- `schedule(queue, message, enqueue_at)` uses `ServiceBusSender.schedule_messages(msg, enqueue_at)` and returns the sequence number. `cancel(queue, sequence_number)` uses `cancel_scheduled_messages`; cancelling something already delivered is not an error. Use cases never call these: the outbox relay (I03) does, and stores the number on the Neo4j `ScheduledWork` node (P08).
- `enqueue_at` is timezone-aware UTC.
- **Open decision: emulator limits.** The emulator does not support every cloud feature. Check the current emulator docs for scheduled messages, sessions and duplicate detection. Where one is unsupported, mark only that contract test `skipif(EMULATOR)` with a reason and list it in your summary so it is tested in a cloud test namespace. Do not depend on messages over 256 KB.
- Use the async `azure-servicebus` client; connection string from settings (`servicebus_connection`).

**Build.** `backend/src/diucs/adapters/outbound/bus_servicebus/service_bus.py`: `ServiceBusEventBus(client: ServiceBusClient)` implementing `EventBus`, one cached sender per entity, `close()`. Pure helper `to_service_bus_message(message) -> ServiceBusMessage`. Add a `servicebus` factory to the event-bus contract suite.

**Tests to write first.**
1. Unit: `to_service_bus_message` sets `message_id`, `session_id`, `subject`, `application_properties["event_type"]` and the JSON body.
2. Unit: a payload with `"channel": "text"` gets `application_properties["channel"] == "text"`.
3. Unit: publishing to `"no.such.topic"` raises `ValueError`.
4. Emulator: publish to `inbound.replies`; a receiver gets it with the same `message_id`.
5. Emulator: `schedule` 3 s ahead returns an int; the message is not receivable at 1 s and is at 5 s.
6. Emulator: `schedule` then `cancel`; nothing arrives after 5 s.
7. Contract: the shared event-bus suite passes on both factories (skips only as allowed above).
