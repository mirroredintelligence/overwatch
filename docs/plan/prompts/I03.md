**Goal.** Build the outbox relay worker: it reads pending outbox messages from Neo4j, publishes them to Service Bus, and marks them published. It also turns `ScheduleWork` and `CancelWork` outbox messages into scheduled Service Bus messages and stores the sequence number on the Neo4j `ScheduledWork` node. Only one relay runs at a time, enforced by a cache lock.

**Rules you need.**
- At least once: publish first, then mark published in a new unit of work. A crash in between republishes the same message id; Service Bus duplicate detection and idempotent consumers absorb it. Never mark published before the publish call returns.
- The `BusMessage` keeps the outbox message's `id`, `topic`, `event_type`, `payload` and `session_id`.
- Single flight: hold cache lock `outbox-relay` (TTL 30 s) per batch. No lock → do nothing this round.
- Batch size 100, oldest first. Publish error → `mark_failed` (increments attempts), continue, back off before the next round (1 s doubling to 60 s). Messages reaching `dead` are logged by id and topic only, never payload.
- `ScheduleWork` (payload `work_id`, `kind`, `about_id`, `enqueue_at`) → `bus.schedule("scheduled.work", BusMessage(id=<outbox id>, topic="scheduled.work", event_type="ScheduledWorkDue", payload={"work_id", "kind", "about_id"}), enqueue_at)`; in the same unit of work that marks the outbox message published, save the returned sequence number on the `ScheduledWork` node. If that node is already `cancelled`, cancel straight away.
- `CancelWork` (payload `work_id`) → if the node has a sequence number, `bus.cancel("scheduled.work", n)`; if not yet relayed, do nothing (the rule above cancels it later). Everything else → `bus.publish`.
- This worker is an inbound adapter: it receives ports in its constructor and imports no outbound adapter module.

**Build.** `backend/src/diucs/adapters/inbound/workers/outbox_relay.py`: `OutboxRelay(uow_factory, bus: EventBus, cache: Cache, clock: Clock, batch_size=100)`, `async run_once() -> RelayResult(published: int, failed: int, skipped_no_lock: bool)`, `async run_forever(stop: asyncio.Event)`, and a thin `python -m` entry that builds ports from the container (F08).

**Tests to write first.** Real Neo4j through `uow_factory`, with `ManualEventBus`, `InMemoryCache` and `FixedClock` at 14:16 London. Seed pending messages by writing them through a unit of work, and assert by reading the graph back with `node_props` / a fresh unit of work.
1. Three pending messages → `run_once` publishes them in creation order; in Neo4j all three now have status `published` and a `publishedAt`.
2. The bus fake fails on the second message → `published=2, failed=1`; the stored node has `attempts == 1` and status `pending`.
3. Lock held by another holder → `skipped_no_lock=True`, nothing published, nodes unchanged.
4. Crash: publish succeeds, then marking published raises → the next `run_once` publishes the same id again (the bus saw it twice) and the node ends `published`.
5. A message failing ten times is stored as `dead` and not retried.
6. `session_id` and `event_type` pass through unchanged.
7. `ScheduleWork` for work `w1` due 14:26 → `ManualEventBus` holds one scheduled message at 14:26; the `ScheduledWork` node for `w1` has `sequenceNumber` set; nothing published to a topic.
8. `CancelWork` after relay → the manual bus no longer delivers at 14:26. `CancelWork` relayed before its `ScheduleWork` (node already `cancelled`) → scheduled and cancelled at once; nothing delivered.
9. One end-to-end case with the Service Bus emulator: a message ends `published` in Neo4j and is received.
