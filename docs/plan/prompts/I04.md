**Goal.** Build the shared consumer framework every Service Bus subscriber uses: receive a message, skip it if this consumer already processed that message id, run the handler and record the message id in the same Neo4j transaction, and dead-letter messages that can never succeed.

**Read first.**
- `backend/src/diucs/application/ports/outbound/event_bus.py` (P08): `BusMessage`.
- `backend/src/diucs/application/ports/outbound/unit_of_work.py` (P06) and `backend/src/diucs/adapters/outbound/graph_store/unit_of_work.py` (P06): `Neo4jUnitOfWork`; `backend/tests/support/uow.py` for `uow_factory`.
- `backend/src/diucs/application/ports/outbound/idempotency.py` and `backend/src/diucs/adapters/outbound/graph_store/idempotency_store.py` (P15): `ProcessedMessages` and how it is reached from the unit of work.
- `backend/tests/support/neo4j.py` (F10): `count_nodes`, `node_props`.
- `docs/spec/architecture.md`: Service Bus table and the idempotency rows; `docs/spec/observability.md`, span `servicebus.process {topic}/{subscription}`.

**Rules you need.**
- Every consumer is idempotent on the message id. Inside one unit of work: if `ProcessedMessages.mark_if_new(message.id, consumer_name)` says it was already processed, complete and return; else run the handler with the same unit of work, commit, then complete the Service Bus message. The `Processed` node and the handler's writes commit together or not at all.
- Outcomes: success → complete. `PermanentError` (bad payload, unknown kind, validation) → dead-letter at once with a reason (no payload text in the description). Any other exception → abandon so Service Bus redelivers; after max delivery count Service Bus dead-letters it.
- A dead-lettered message raises an alert (O04/ops); here log the id, entity and reason only.
- Session-enabled entities (`capacity.events` subscriptions) use a session receiver so one service's events are processed in order.
- Keep the core free of the Azure SDK; only the runner imports `azure.servicebus`.

**Build.**
- `backend/src/diucs/adapters/inbound/workers/consumer.py`: `PermanentError`; `Handler = Callable[[BusMessage, UnitOfWork], Awaitable[None]]`; `IdempotentConsumer(name: str, handler: Handler, uow_factory)` with `async handle(message) -> Outcome` (`"completed" | "duplicate" | "dead-letter" | "retry"` plus a reason).
- `backend/src/diucs/adapters/inbound/workers/servicebus_runner.py`: `ServiceBusRunner(client, entity, subscription, consumer, sessions=False, max_concurrency=4)` that converts received messages to `BusMessage`, calls `handle`, and completes, abandons or dead-letters; `run(stop)`.

**Tests to write first.** Core tests run on real Neo4j via `uow_factory`; test handlers write a small `:TestMark {messageId}` node through the unit of work's transaction so commits are visible.
1. New message → handler called once → `completed`; Neo4j has one `Processed` node for (id, consumer) and one `TestMark`.
2. Same id again → handler not called → `duplicate`; still one `Processed` node.
3. Same id, different consumer name → handler called; two `Processed` nodes.
4. Handler raises `PermanentError("unknown kind")` → `dead-letter`; no `Processed` node and no `TestMark` in the graph.
5. Handler raises `RuntimeError` → `retry`; nothing committed; a second delivery runs the handler and commits.
6. Handler writes a `TestMark`, then raises → `count_nodes("TestMark") == 0`.
7. Unit (stub receiver, no Docker): `completed` → `complete_message`; `retry` → `abandon_message`; `dead-letter` → `dead_letter_message(reason=...)`.
8. Emulator: a message sent twice with the same id on `inbound.receipts` is processed once.
