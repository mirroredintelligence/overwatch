**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. **The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Implement `SmsSender` with Twilio: send a text and turn Twilio's status callbacks into delivery updates. Twilio is an external provider, so it is tested with mocked HTTP; nothing Twilio-specific may leak out of this adapter, because GOV.UK Notify comes later behind the same port.

**Rules you need.**
- **Open decision: Twilio or GOV.UK Notify.** Build Twilio now. The choice stays a configuration change (`sms_provider = "twilio" | "notify"`). Ask the product owner to confirm the UK sender number, data region and sub-processors before go-live.
- Send: `POST https://api.twilio.com/2010-04-01/Accounts/{AccountSid}/Messages.json`, form fields `To` (E.164), `From` or `MessagingServiceSid`, `Body`, `StatusCallback` (our public status URL). Basic auth `AccountSid:AuthToken`. 201 JSON has `sid` → `SendReceipt(provider_message_id=sid, accepted=True)`. 4xx with codes 21211, 21614, 21610 → `accepted=False` (permanent). 5xx or timeout → raise `TransientSendError` (the consumer retries).
- Normalise UK numbers to E.164: `07700 900123` → `+447700900123`; anything else → `ValueError`.
- Never log the number or the body; log the message id and Twilio `sid` only.
- Status callback form fields: `MessageSid`, `MessageStatus` (`queued`, `sending`, `sent`, `delivered`, `undelivered`, `failed`), `ErrorCode`. Map to `queued | sent | delivered | failed`.
- Use an injected `httpx.AsyncClient`; no Twilio SDK.

**Build.** `backend/src/diucs/adapters/outbound/sms_twilio/twilio_sms.py`: `TwilioSms(client, account_sid, auth_token, from_number, status_callback_url)` implementing `SmsSender`; `to_e164_uk(number) -> str`; `parse_status_callback(form) -> DeliveryUpdate(provider_message_id, status, error_code)` (add `DeliveryUpdate` to `messaging.py` if P07 did not); `TransientSendError` in `messaging.py` so other senders share it. Settings `twilio_account_sid`, `twilio_auth_token`, `twilio_from`, `public_base_url`.
