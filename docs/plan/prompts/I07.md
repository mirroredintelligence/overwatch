**Goal.** Receive inbound text replies and delivery receipts from Twilio safely and quickly: check the signature, drop unknown senders silently, stop replays, put the reply on a queue, and answer Twilio at once. The allow-list lookup reads the real Neo4j person data.

**Rules you need.**
- Signature: `X-Twilio-Signature` = base64(HMAC-SHA1(auth_token, full_url + each POST param name and value, sorted by name)). `full_url` is the public URL from settings, not the URL seen behind the proxy. Constant-time compare. Bad or missing → 403, nothing queued.
- Allow-list: hash `From` with `PhoneHasher`; if the person repository finds nobody, respond 200 with empty TwiML and queue nothing. Never reply to unknown numbers.
- Replay: `SET diucs:idem:sms:<MessageSid> 1 NX EX 86400` through the `Cache` port. Already present → 200, nothing queued. The durable check (`ProcessedMessages`, P15) happens in the consumer (I04).
- Queue: publish `BusMessage(id=MessageSid, topic="inbound.replies", event_type="SmsReceived", payload={"phone_hash", "text", "received_at", "provider_message_id"})`. The raw number is never queued.
- Respond within the request: 200, `Content-Type: text/xml`, body `<?xml version="1.0" encoding="UTF-8"?><Response/>`. Replies go later through the outbox, never in TwiML.
- `POST /webhooks/sms/twilio/status`: same signature check, publish to `inbound.receipts` with id `MessageSid + ":" + MessageStatus`.
- No logging of numbers or message text. The route reads the person repository through a short read-only unit of work from the container.
