**Rules you need.**
- VAPID keys from the secret store; subject `mailto:` the operations inbox from settings. `pywebpush` run in a thread, or an async equivalent.
- Payload JSON `{"title", "body", "url"}`, TTL 600 s, urgency `high` for booking requests and alerts, `normal` otherwise. Never patient data: title and body come from templates (B3, K3, the C1 push variant).
- 404 or 410 → `SendReceipt(accepted=False)` with reason `gone`; the handler deletes the stored subscription. 429 or 5xx → `TransientSendError`.
- Consent: the app asks for permission only after the consent screen. P19 stores only the subscription; this task records the consent itself, in the same unit of work: a FHIR resource written through the G05 resource store (status `active`, `dateTime`, wording version, performer the Practitioner, category notification, a reference to the Device). **Open decision:** R4B `Consent` is patient-centred; use `Consent` with `performer` if `fhir.resources.R4B` accepts it without a patient, otherwise `Basic` with code `notification-consent`. Write the choice in your summary and keep it behind a small `NotificationConsentStore` (`record(practitioner_id, device_id, wording_version, at)`, `withdraw(...)`) in `push_subscription.py`'s module or a graph_store file, so it can change.
- `PushSubscriptionRepository`, `PushSubscription` and `Neo4jPushSubscriptionRepository` come from P19. Do not define them again and do not write a fake.
