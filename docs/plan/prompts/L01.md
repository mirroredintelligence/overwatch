**Goal.** Build the back-end API behind the one-tap capacity link: show what is recorded without changing anything, record a confirm, a new number or "closed" on a button press, and let a person ask for a new link when theirs has expired. Tests read results back from Neo4j.

**Rules you need.**
- Tokens: at least 128 bits, single use, tied to one prompt and one phone, expiring at the prompt's reply-by time. Only the hash is stored.
- `GET /links/{token}` changes nothing: no burn, no report, no audit write. It returns JSON `{state, purpose, serviceName, unitLabel, recordedValue, asOf, usualMin, usualMax, replyBy, nextDue, csrfToken}`; `state` is `ok`, `expired` or `used`. Expired or used → 410 with `{state}` only. An unknown token gets the same 410 `expired` body.
- `csrfToken` = HMAC-SHA256 of the token hash with secret `link-csrf`. `POST /links/{token}` must send it in `X-CSRF-Token`; missing or wrong → 403.
- `POST /links/{token}` body `{"action": "confirm" | "number" | "closed", "value"?: int}`. `confirm` → `ConfirmCapacity` (source `link`); `number` → `ReportCapacity`; `closed` → value 0. The token is burned in the same unit of work. A second POST → 410 `used`.
- Values are whole numbers 0 to 999. A value outside the usual range needs `"confirmOutOfRange": true`; otherwise 422 `{state: "out-of-range", usualMin, usualMax}`.
- The confirm limit (two Y in a row) → 409 "Please send the number".
- Success returns `{serviceName, value, unitLabel, recordedAt, nextDue}`.
- `POST /links/{token}/renew` → always 202. If the token belonged to the service's current prompt and that window has closed, queue a fresh prompt (C1 with a new link) through the outbox.
- Times are ISO 8601 UTC.
