**Goal.** Extend the link API to bookings: a service opens the request link, sees the reference, age band, need and urgency, and confirms or declines on a button press. After confirming, it can still say it cannot take the patient or could not reach them.

**Read first.**
- `adapters/inbound/link_pages/capacity_links.py` and `application/use_cases/link_access.py` (L01): the purpose registry, CSRF and burn logic. Reuse them.
- `application/use_cases/respond_to_booking.py` (U18), `withdraw_booking.py` (U21); `graph_store/booking_repository.py` (P02): `Neo4jBookingRepository`.
- `docs/spec/ui-screens.md`, artboards "BookingEmail", "BookingExceptions"; `docs/spec/domain-rules.md`, section 3.

**Rules you need.**
- Purpose `booking-request`. `GET /links/{token}` changes nothing and returns `{state, purpose, reference, serviceName, ageBand, need, urgency, replyBy, bookingStatus, csrfToken}`. Opening the link books nothing.
- `POST /links/{token}` with `{"action": "confirm"}` or `{"action": "decline", "reason"?: "full" | "outside-criteria" | "staffing-or-transport" | "other"}` and the CSRF header → `RespondToBooking`. The token is burned.
- If the booking is no longer `requested`, GET returns `state` with the booking status (`expired` "This request has expired", `cancelled` "Cancelled by the SPOA", and so on). A POST then → 409.
- On confirm, the response includes a `changeToken`: a new single-use token with purpose `booking-change`, valid 24 hours **[ASSUMED]**, tied to the same booking and phone. Returned once; only its hash is stored.
- `POST /links/{changeToken}` with `{"action": "withdraw", "reason": now-full|staffing|cannot-reach-patient|other}` → `WithdrawBooking`; or `{"action": "not-reached", "reason": not-at-address|no-answer|gone-to-hospital|other}` → `ReportNotReached`.
- The GET for a booking link never includes a postcode, a name or the case id.

**Build.** `backend/src/diucs/adapters/inbound/link_pages/booking_links.py` registering handlers for `booking-request` and `booking-change` with the L01 registry, plus small additions in `link_access.py`.

**Tests to write first.** `api_client`, Docker running; a requested booking 4821 for UCR West (case "case-1", reply-by 14:26).
1. GET → reference 4821, UCR West, 80+, fall and frailty, within 2 hrs, reply by 14:26; the booking is still `requested` in Neo4j.
2. POST confirm → booking stored `confirmed`; response has a `changeToken`; original token used.
3. POST decline with reason `outside-criteria` → stored decline with that reason.
4. GET after the booking expired → `state: expired`; POST → 409.
5. POST withdraw with the change token and reason `staffing` → booking withdrawn in Neo4j.
6. Change token used twice → 410.
7. The GET body contains no `ServiceRequest`, `Patient` or postcode string.
