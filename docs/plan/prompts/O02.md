**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. **The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build the browser telemetry module: `ui.*` events tied to stable element ids, a W3C `traceparent` on every BFF request, and batched sending. It records what was used and what happened next, never what was typed.

**Read first.**
- `frontend/lib/fhir/client.ts` (W01) and any `fetch` helpers under `frontend/lib/bff/`.
- `docs/spec/observability.md`: "Attributes on every event and span", "UI events", "The rule that governs the rest", "Privacy and governance".
- `docs/spec/contracts.md`, the `data-el` convention.

**Rules you need.**
- Common attributes: `session.id` (random per browser session, kept in `sessionStorage`, never linked to a person here), `user.role`, `service.id` when relevant, `page.route` (the route template such as `/case/[ref]`, never the real URL), `element.id` (from the nearest `data-el`), `release`, `device.type` (phone, tablet, desktop by width), `app.mode` (browser or installed, from `display-mode: standalone`), `net.effective_type` where available, `trace_id`.
- Events in scope here: `ui.page_view` (`from.route`, `load.type`), `ui.click` (`element.id`, `dwell_ms`, `result` = navigation, network, dom or none within 1 second), `ui.input` (`element.id`, `valid`, `length_bucket` of `0`, `1-5`, `6-20`, `21+`; never the value), `ui.toggle` and `ui.chip` (`state`), `ui.submit` (`form.id`, `error_count`, `time_to_submit_ms`), `ui.error_shown` (`error.code`, `element.id`).
- Never capture field values, page text, screenshots or DOM.
- Every request to `/api/bff/*` carries `traceparent: 00-<32 hex>-<16 hex>-01`.
- Send in batches with `navigator.sendBeacon('/api/bff/telemetry', ...)`: every 5 seconds, at 20 events, or when the page is hidden.

**Build.**
- `frontend/lib/telemetry/trace.ts`: `newTraceparent()`, `withTraceparent(init: RequestInit): RequestInit`; use it inside the BFF fetch helper.
- `frontend/lib/telemetry/events.ts`: `initTelemetry({ role, release })`, `track(name, attrs)`, `routeTemplate(pathname, params)`, a delegated click listener that reads `data-el`, and the result classifier (navigation via route change, network via the fetch wrapper, dom via `MutationObserver`).
- `frontend/app/api/bff/telemetry/route.ts`: accepts a batch, drops keys not on the allow-list, forwards to `process.env.OTEL_HTTP_ENDPOINT` if set, else discards. Returns 204.

**Tests to write first.** Vitest, jsdom, fake timers.
1. `newTraceparent()` matches `^00-[0-9a-f]{32}-[0-9a-f]{16}-01$`.
2. A click on `<button data-el="ADV-OPT-REQUEST-BTN">` followed by a DOM change within 1 s records `ui.click` with `result: "dom"`.
3. A click with nothing happening for 1 s records `result: "none"`.
4. Typing "DT4 8XX" into an input records `ui.input` with `length_bucket: "6-20"` and no attribute containing "DT4".
5. `routeTemplate("/case/4821/options", {ref: "4821"})` → `/case/[ref]/options`.
6. 20 events trigger one `sendBeacon`; 3 events flush after 5 s.
7. The BFF route drops an attribute `field.value`.
