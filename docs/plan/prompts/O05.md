**Goal.** Make it impossible to add a telemetry event that could carry free text: every `ui.*` event gets a schema, `track` drops events that break it, and a test fails the build if any schema field could hold free text.

**Read first.**
- `frontend/lib/telemetry/events.ts` (O02) and `friction.ts` (O03).
- `docs/spec/observability.md`, "UI events" and the "Patient data" row in "Privacy and governance".

**Rules you need.**
- Every attribute is one of: a number; a boolean; an enum of fixed strings; an id matching a fixed pattern. Patterns: element id `^[A-Z0-9]+(-[A-Z0-9]+)*$`; route template `^/[a-z0-9\-/\[\]]*$`; session id `^[a-f0-9]{16,32}$`; trace id `^[a-f0-9]{32}$`; release `^\d+\.\d+\.\d+$`; error code `^[A-Z0-9_\-]{1,40}$`; service id `^[A-Za-z0-9\-]{1,64}$`.
- A plain `string` attribute with no enum and no pattern is free text and is not allowed.
- In development, `track` throws on an invalid event so the mistake is seen; in production it drops the event silently and counts the drop.

**Build.** `frontend/lib/telemetry/schema.ts`: `EVENT_SCHEMAS: Record<UiEventName, Record<string, AttrSpec>>` with `AttrSpec` = `{type: "number"} | {type: "boolean"} | {type: "enum", values: string[]} | {type: "id", pattern: RegExp}`; `validateEvent(name, attrs): string[]` (problems); `isFreeText(spec): boolean`. Use it in `track`.

**Tests to write first.** `frontend/lib/telemetry/schema.test.ts`.
1. Every event name used in `events.ts` and `friction.ts` has a schema (import the name list).
2. No attribute spec in any schema is free text (`isFreeText` false for all). This is the build-failing test.
3. `validateEvent("ui.input", { "element.id": "ADV-NEEDS-POSTCODE", valid: true, length_bucket: "6-20" })` → `[]`.
4. `validateEvent("ui.input", { ..., value: "DT4 8XX" })` → a problem naming `value`.
5. `element.id` of `"adv opt"` → a problem.
6. In development mode `track` throws on an invalid event; in production mode it drops it and increments `droppedEvents`.
