**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. **The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build consent-based support access: a person creates a support code to share their session, support opens a session only with that code (or an approved ticket), every open is audited and shown to the person, and sharing can be stopped. All records are Neo4j platform nodes, tested against Neo4j.

**Read first.**
- `domain/rules/tokens.py` (D26): `new_support_code`, `hash_token`.
- `adapters/outbound/graph_store/driver.py` and `queries.py` (G01): named queries.
- `application/ports/outbound/audit.py` (P05); `unit_of_work.py` and `backend/tests/support/uow.py` (P06); `FixedSecretStore` (P10).
- `docs/spec/fhir-data-model.md` "Platform nodes" (`UiSession`, `SupportCode`, `SupportAccess`); `docs/spec/observability.md` "Access" and "Privacy and governance".

**Rules you need.**
- `UiSession` is pseudonymous: no link to a person. The only link is a `SupportCode` the person creates: `(:UiSession)-[:SHARED_VIA]->(:SupportCode {codeHash, createdAt, expiresAt})-[:SHARED_BY]->(:Practitioner)`.
- Code format `XXXX-XXXX` (from D26); valid for `SUPPORT_CODE_VALID_FOR = 4 hours` [ASSUMED]; only the hash is stored.
- Opening a session needs either a valid code, or a ticket reference plus a lead's approval (`approved_by` practitioner with role lead). Each open writes `(:SupportAccess {id, openedAt, reason, expiresAt})` with `OPENED_BY` and `OPENED`, and an audit entry, in one unit of work. Access lasts `SUPPORT_ACCESS_VALID_FOR = 1 hour` [ASSUMED].
- The person sees every open of their sessions ("14:02 by [Support role]") with the role, never the support person's name.
- "Stop sharing now" expires the code at once; opens already in progress end.
- Role `support` only. Others are refused (`NotAllowed`).

**Build.** `application/ports/outbound/support.py`: `SupportRepository` Protocol. `adapters/outbound/graph_store/support_repository.py`: `Neo4jSupportRepository(tx)` with named queries `Q-SUPPORT-*`, added to the unit of work as `uow.support`. `application/use_cases/support_access.py`: `CreateSupportCode`, `StopSharing`, `OpenSessionForSupport`, `ListMyAccesses`. No in-memory repository.

**Tests to write first.** Repository round trips in `tests/integration/adapters/test_support_repository.py`; use cases in `tests/integration/application/test_support_access.py`:
1. `UiSession`, `SupportCode` and `SupportAccess` each round-trip with `assert_round_trip`.
2. Creating a code returns `XXXX-XXXX`; the stored `SupportCode` holds only `codeHash` (search its properties for the code: absent).
3. Support opens with the code → a `SupportAccess` node with `expiresAt` 1 hour later and one audit node.
4. An expired code, or a wrong code, is refused with the same error.
5. A ticket with no lead approval is refused; with an approval from a lead it is allowed.
6. An advisor trying to open → `NotAllowed`.
7. `ListMyAccesses` shows the open with the role and time, no name.
8. After `StopSharing`, the code no longer opens anything.
