**Goal.** Run a daily job that turns raw telemetry into the aggregate nodes the insight pages read, and enforce "groups under 10 are hidden" at read time. Aggregates are stored in Neo4j and tested there.

**Read first.**
- `application/ports/outbound/telemetry_query.py` and `FixtureTelemetryQuery` (O07).
- `adapters/outbound/graph_store/driver.py`, `queries.py` (G01); `backend/tests/support/neo4j.py` (F10).
- `application/work.py` (P08) and `application/scheduling.py` (U03) if you schedule it as work.
- `docs/spec/fhir-data-model.md` "Platform nodes" (`FunnelDaily`, `FrictionDaily`, `ElementUsageDaily`, `RouteDaily`, `QueryStatDaily`); `docs/spec/observability.md` "Funnels by role", "Rolling friction into a score", "Performance and responsiveness".

**Rules you need.**
- Funnels are fixed step lists from "Funnels by role" (reporter set-up, daily capacity loop, booking service side, advisor call, registration, criteria review, COO and ICB adoption). Store them as `FUNNELS: dict[str, list[str]]` with each step's defining event.
- `FunnelDaily {funnel, step, date, role, channel, device, entered, completed, medianMs}`; `FrictionDaily {date, elementId, kind, role, device, interactions, events}`; `ElementUsageDaily {date, elementId, role, device, interactions}`; `RouteDaily {date, route, role, device, p50, p75, p95, lcp75, inp75, cls75, errors}`; `QueryStatDaily {date, queryId, calls, p50, p95, errors}`. No person, no session id, no free text.
- Re-running a day replaces that day's rows (MERGE on the key fields), so the job is idempotent.
- Read side: any group with fewer than 10 sessions is returned as suppressed, never as a number.
- Friction rate = events / interactions over the last 7 days by role and device; an element over 5% [ASSUMED] is "for review".

**Build.** `application/ports/outbound/aggregates.py`: `AggregateRepository` Protocol. `adapters/outbound/graph_store/aggregate_repository.py`: `Neo4jAggregateRepository` with named queries `Q-AGG-*`. `application/use_cases/telemetry_aggregates.py`: `BuildDailyAggregates.execute(day)` (reads through `TelemetryQuery`, writes through the repository) and `ReadInsights` (funnel, friction, routes, queries, with suppression). Add aggregate query methods to the `TelemetryQuery` port and its fixture fake. Schedule it as a `WorkKind` if one fits, otherwise document a daily cron entry in your summary.

**Tests to write first.** In `tests/integration/application/test_telemetry_aggregates.py`, with `FixtureTelemetryQuery` and real Neo4j:
1. A fixture day → `FunnelDaily` nodes for reporter set-up with `entered` and `completed` per step, read back with `node_props`.
2. Running the same day twice leaves the same node count.
3. A funnel step with 7 sessions reads back as `suppressed`.
4. Friction rate 41/312 for `ADV-OPT-REQUEST-BTN` → 13%, flagged for review; 3% → not flagged.
5. `QueryStatDaily` for `Q-BOARD` holds p95 and no Cypher text.
6. Every aggregate node type round-trips with `assert_round_trip`.
