**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. **The architecture.** Hexagonal. Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Define the service and capacity-report ports and implement them on Neo4j, so services and their reports persist as FHIR HealthcareService and Observation resources and load back unchanged. This is the first repository; it sets the pattern every later repository follows.

**Read first.**

**Rules you need.**
- There is no in-memory fake. Tests run against the Docker Neo4j. There is no unit of work yet (P06), so tests drive the repositories with `write_tx` / `read_tx`.
- Repositories are built per transaction: `Neo4jServiceRepository(tx, store)` and `Neo4jCapacityRepository(tx, store)`, where `store` is the G05 `ResourceStore`.
- `ServiceProfile` ↔ HealthcareService: `name`, `active`, `comment`, `category` (service-category concept), `availableTime` (one entry per `AvailableTime`: `daysOfWeek` mon..sun, `allDay`, `availableStartTime`, `availableEndTime`), extensions `establishedCapacity`, `canExceedEstablished`, `usualRangeMin`, `usualRangeMax`, `reportCadence`, `limitedLevelPercent`, plus `measure`, `unitLabel`, `channel` (add these three to the G04 registry if missing). `suspended` is not stored on the service (service flags hold it, P14): `save` ignores it and `get` returns `suspended=False`.
- `CapacityReport` ↔ Observation: `status "final"`, `focus` the service, `code` from capacity-measure, `method` from report-source, `effectiveDateTime`, `valueQuantity` (whole number, UCUM `{referral}`, `{bed}`, `{slot}`, `{patient}`, `{package}` by measure), `performer` the PractitionerRole if any, `derivedFrom` for a confirmation, extension `reportType`. Reports are never updated: a second `add` with the same id raises `Conflict`.
- Datetimes are stored as UTC ISO 8601 strings ending `Z`, so string order is time order. Loaded datetimes are timezone-aware UTC.
- Latest report = greatest `effectiveDateTime`; ties go to the later `issued`.

**Build.**
- `application/ports/outbound/repositories.py`: `ServiceRepository` (`get(id) -> ServiceProfile | None`, `list_active() -> list[ServiceProfile]` sorted by name, `save(profile)` insert or replace) and `CapacityRepository` (`add(report)`, `latest(service_id)`, `latest_for_services(ids) -> dict[str, CapacityReport]` omitting services with none, `reports_since(service_id, since)` oldest first, `last_report_times() -> dict[str, datetime | None]` for every active service). All async. No update or delete on reports.
- `graph_store/service_repository.py`: `Neo4jServiceRepository`, pure `profile_to_fhir` / `profile_from_fhir`.
- `graph_store/capacity_repository.py`: `Neo4jCapacityRepository`, pure `report_to_fhir` / `report_from_fhir`. Named queries `Q-SVC-LIST-ACTIVE`, `Q-CAP-LATEST` (query #1, using `CALL { ... ORDER BY o.effectiveDateTime DESC LIMIT 1 }`), `Q-CAP-LATEST-FOR`, `Q-CAP-SINCE`, `Q-SVC-LAST-REPORT` (query #5).
