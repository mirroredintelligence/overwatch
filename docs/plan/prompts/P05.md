**Goal.** Define the append-only audit log port with a tamper-evident hash chain, the `Actor` type it records, and its only implementation: Neo4j audit nodes chained by hash, with Provenance records on the same chain. Tests run against the Docker Neo4j; there is no in-memory audit log.

**Rules you need.**
- Every command writes an audit entry with actor, role, channel and the ids of what was shown or touched. Append-only: no update, no delete.
- `chain_hash = sha256((previous_hash + canonical_json(entry)).encode()).hexdigest()`. Genesis `previous_hash` is 64 zeros. Canonical JSON: `sort_keys=True`, `separators=(",", ":")`, `ensure_ascii=False`; datetimes ISO 8601 UTC ending `Z`; enums as values; sets as sorted lists; tuples as lists.
- A snapshot holds ids, statuses, numbers, data ages and criteria versions, never patient values.
- Graph: `(:AuditEvent {id, action, recorded, outcome, useCase, chainHash, previousHash, entryJson})`, `-[:AGENT {role, requestor: true}]->` the practitioner or device (MERGE a placeholder by id), `-[:ENTITY {role}]->` each touched resource (MERGE placeholders), `-[:SNAPSHOT]->(:Snapshot {hash, json})`. Provenance: `(:Provenance {id, recorded, chainHash, previousHash})` with `TARGET`, `AGENT {type, role}`, `ENTITY {role: "source"}` to a Communication, `ACTIVITY` to a Concept (create, confirm, approve, call-back), plus extra properties such as `numberCalled`, `roleSpokenTo`.
- Chain head: `(:AuditHead {id: "audit"})` holds `lastHash`. Appending, in the caller's transaction: lock the head (`SET h._lock = coalesce(h._lock, 0) + 1`), read `lastHash`, compute, create, set `h.lastHash`. Concurrent appends serialise here by design; comment that it is a write hot spot to measure under load.
- The log works on the transaction it is given, so it commits or rolls back with the caller's change. Built as `Neo4jAuditLog(tx)`; the unit of work (P06) passes its transaction.
- **Open decision:** Community cannot deny `SET`/`DELETE` by role; add a TODO for Enterprise role-based write restrictions.

**Tests to write first.**
1. Unit: `chain_hash_for` equals a hash computed by hand; canonical JSON ignores dict insertion order; `frozenset({"svc-ucr-west"})` serialises as `["svc-ucr-west"]`.
2. Integration: three appends in separate committed transactions; `records()` read in a fresh session returns them in order, each `previous_hash` equal to the prior `chain_hash`, the first equal to genesis.
3. Integration: `verify_chain()` is true; after raw Cypher edits one event's `entryJson`, it is false.
4. Integration: an append in a transaction that is rolled back leaves no `AuditEvent` and does not move `AuditHead.lastHash`.
5. Integration: an entry with a snapshot stores a `Snapshot` whose `hash` is the SHA-256 of its canonical JSON.
6. Integration: two concurrent appends (`asyncio.gather`, two transactions) both succeed and the chain verifies.
7. Integration: `append_provenance` for a call-back stores `numberCalled` and `roleSpokenTo`.
8. Unit: no registered `Q-AUDIT-*` or `Q-PROV-*` query contains `DELETE`, and `Neo4jAuditLog` has no `update`, `delete` or `remove`.
