Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Rules you need.**
- Each suite is parametrised over adapter factories. Fakes run in the normal run. Real adapters are added later as extra params with `pytest.mark.integration`.
- Time-dependent behaviour (TTL, lock expiry, scheduled delivery) must work for fakes (advance a manual clock) and real adapters (wait in real time with short durations). The harness hides the difference.

**Build.**
- `tests/contract/harness.py`: `Harness[T]` dataclass with `subject: T`, `advance: Callable[[timedelta], Awaitable[None]]`, `receive: Callable[[str, timedelta], Awaitable[BusMessage | None]] | None = None` (event bus only), `close: Callable[[], Awaitable[None]]`.
- `tests/contract/factories.py`: `CACHE_FACTORIES` and `EVENT_BUS_FACTORIES`, each a list of `pytest.param(factory, id="memory")`. Later tasks append e.g. `pytest.param(make_redis_cache, id="redis", marks=pytest.mark.integration)`. Document this at the top of the file.
- `tests/contract/conftest.py`: fixtures `cache_harness` and `bus_harness`, parametrised from those lists and closed after each test.
- `test_cache_contract.py`: get/set/delete; TTL with `advance`; publish/subscribe; lock fencing.
- `test_event_bus_contract.py`: `schedule` returns increasing ints; after `advance` past `enqueue_at` the message is receivable; a cancelled one is not; `publish` to a topic is receivable.
