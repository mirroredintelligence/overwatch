**Goal.** Make commands and message consumers safe to repeat, stored in Neo4j: `IdempotencyStore` keeps the first result of each command key, and `ProcessedMessages` marks a message as handled per consumer. Both join the unit of work so the marker commits with the change it protects.

**Rules you need.**
- Every command carries an idempotency key. A replay returns the stored result and writes nothing new.
- Providers and Service Bus deliver at least once, so each consumer records `(messageId, consumer)` and skips a repeat.
- Results are stored as JSON: `(:IdempotencyRecord {key, resultType, resultJson, createdAt})`, unique on `key`. `resultType` is `"<module>:<qualname>"`. Decoding only imports types from modules under `diucs.application`; anything else raises `ValueError`. The codec handles nested dataclasses, UTC datetimes (ISO), enums, tuples, frozensets and `None`.
- `(:Processed {messageId, consumer, processedAt})`, unique on `(messageId, consumer)` (composite uniqueness works on Community). `mark_if_new` uses `MERGE ... ON CREATE` and returns whether it created the node.
- The marker commits with the work: use cases call `uow.idempotency.get(key)` first and `uow.idempotency.put(key, result)` before `commit()`; consumers call `uow.processed.mark_if_new(...)` first inside theirs. A use case may also receive an `IdempotencyStore` in its constructor for a cheap early check; that instance opens its own short read transaction.

**Build.**
- `application/idempotency.py`: `IdempotencyStore(Protocol)`: `async get(key) -> object | None`, `async put(key, result) -> None`; `encode_result(result) -> tuple[str, str]`; `decode_result(type_name, json_text) -> object`.
- `application/ports/outbound/idempotency.py`: `ProcessedMessages(Protocol)`: `async mark_if_new(message_id: str, consumer: str) -> bool`.
- `adapters/outbound/graph_store/idempotency_store.py`: `Neo4jIdempotencyStore(tx)`, `Neo4jProcessedMessages(tx)`, and `DriverIdempotencyStore(driver)` (each call in its own transaction, for constructor injection). Queries `Q-IDEM-GET`, `Q-IDEM-PUT`, `Q-PROCESSED-MARK`; migrations for both constraints.
- Register `idempotency` and `processed` in `DEFAULT_FACTORIES`; add both to the `UnitOfWork` Protocol.

**Tests to write first.**
1. Unit: `decode_result(*encode_result(r)) == r` for a frozen dataclass with a datetime, an enum, a tuple and a nested dataclass.
2. Unit: decoding type `"os:system"` raises `ValueError`.
3. Integration: `uow.idempotency.put` then commit; `get` in a fresh unit of work returns an equal object.
4. Integration: `put` without commit → `get` returns `None`.

6. Integration: two concurrent `mark_if_new("m2", "c")` in separate transactions: exactly one returns true.
7. Integration: `put` of the same key twice keeps the first result.
