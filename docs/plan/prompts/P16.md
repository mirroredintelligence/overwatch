**Goal.** Store the protected contact details, the text-code state and the PIN credentials in Neo4j, so a restart keeps every registered phone, device and PIN lock state. The short-lived text-code store is an in-memory fake because it is Redis in production (I13), and its state is not a record of truth.

**Rules you need.**
- Phone numbers and role emails live only in the protected contact store: a separate `(:ProtectedContact {roleId, kind, value, updatedAt})` node, not in any FHIR resource. Only `ContactStore` reads it.
- PINs are stored only as keyed hashes, bound to a device: `(:Credential {deviceId, pinHash, failed, lockedUntil, updatedAt})` `<-[:HAS_CREDENTIAL]-` the practitioner. The `PinState` (failure count, lock) is stored with the hash.
- `DeviceRegistry` records a device per practitioner: `(:Device {id, status, practitionerId, registeredAt, revokedAt})`. `revoke_all` sets `revokedAt` on every device of that practitioner, so `known` is false afterwards.
- Text codes are short-lived (10 minutes, D27), so `CodeStore` is an in-memory fake; Redis backs it in production (I13).
- A text code is never stored in plain text: store `codeHash` only.
