**Goal.** Store Web Push subscriptions in Neo4j, linked to the device and the person, so notifications reach installed apps after restarts.

**Read first.**
- `application/ports/outbound/messaging.py` (P07): add the port here. `unit_of_work.py` (P06): add attribute `push_subscriptions`.
- `backend/tests/support/` (F10, P06). `docs/spec/fhir-data-model.md`: "People, devices and consent" (Device), the `USED_BY` local relationship. `docs/spec/architecture.md`: "Push".

**Rules you need.**
- A subscription belongs to one installed app on one device: `(:Device {id, status, deviceName, pushSubscriptionJson, pushSavedAt})-[:USED_BY]->(:Practitioner)` plus `-[:TYPE]->(:Concept {code:"mobile-app"})`. Platform data written with named queries; the Device node gets labels `Resource:Device` so later FHIR reads find it.
- The subscription JSON (`endpoint`, `keys.p256dh`, `keys.auth`) is a capability secret: never log it or put it in audit or telemetry.
- One practitioner can have several devices; saving for a device replaces that device's subscription. Deleting removes the subscription properties, not the Device.
- Consent records are written by I14, not here.

**Build.**
- `PushSubscription(device_id, practitioner_id, subscription: dict, saved_at)` and Protocol `PushSubscriptionRepository` (`save`, `for_practitioner(practitioner_id) -> list[PushSubscription]`, `delete(device_id)`) in `messaging.py`.
- `graph_store/push_subscription_repository.py`: `Neo4jPushSubscriptionRepository(tx)`, queries `Q-PUSH-SAVE`, `Q-PUSH-FOR`, `Q-PUSH-DELETE`. Register in the unit of work.

**Tests to write first.**
1. `assert_round_trip` for a subscription on device "dev-1" for practitioner "p1" (endpoint `https://push.example/abc`, keys "k1"/"a1").
2. Saving again for "dev-1" with a new endpoint leaves one Device node with the new endpoint.
3. Two devices for "p1" → `for_practitioner("p1")` returns both, newest first.
4. `delete("dev-1")` → not returned; the Device node still exists with `pushSubscriptionJson` null.
5. Unknown practitioner → empty list.
