**Goal.** Add two small stores on Neo4j: service moves between phones (U38) and the protected text store that holds free text from safety concerns, problem reports and clinical notes away from the readable graph (U40, U41).

**Read first.**
- `application/ports/outbound/repositories.py`, `unit_of_work.py` (P06): add attributes `service_moves` and `protected_text`.
- `application/ports/outbound/identity.py` and `graph_store/contact_store.py` (P16): the same access-controlled label pattern.
- `backend/tests/support/` (F10, P06). `docs/spec/observability.md`: "Privacy and governance". `docs/spec/fhir-data-model.md`: "Safety concern".

**Rules you need.**
- Service move: platform node `(:ServiceMove {id, serviceId, fromPractitionerId, toPhoneHash, until, codeVerifiedAt, callbackAt, completedAt, cancelledAt})-[:FOR]->(:HealthcareService)` and `-[:FROM]->(:Practitioner)`. Only the phone hash, never the number. At most one open move (not completed, not cancelled) per service: a second `add` raises `Conflict`.
- Protected text: node `(:Protected:ProtectedText {handle, kind, aboutId, text, createdAt})` with no relationships to anything. `kind` is `safety-concern`, `problem-report` or `clinical-note`. The handle is a random URL-safe token of at least 128 bits. Limit 280 characters (callers validate too; the store rejects longer with `ValidationFailed`).
- Neo4j Community has no role-based access control, so protection is by code: only queries named `Q-PROT-*` may touch the `Protected` label. **Open decision:** on an Enterprise edition, deny the label to the application's read role; and IG to decide whether the text is also encrypted at rest.

**Build.**
- `domain/model/service_move.py`: `ServiceMove(id, service_id, from_practitioner_id, to_phone_hash, until: datetime | None, code_verified_at=None, callback_at=None, completed_at=None, cancelled_at=None)`.
- Ports: `ServiceMoveRepository` (`add`, `get`, `save`, `open_for_service`) in `repositories.py`; `application/ports/outbound/protected_text.py`: `ProtectedTextStore` (`put(kind, about_id, text) -> str`, `get(handle) -> str | None`).
- `graph_store/service_move_repository.py` (`Neo4jServiceMoveRepository(tx)`) and `graph_store/protected_text_store.py` (`Neo4jProtectedTextStore(tx)`). Register both in the unit of work.

**Tests to write first.**
1. `assert_round_trip` for a move of UCR East to hash "h9" until 19:00Z.
2. A second open move for UCR East raises `Conflict`; after saving the first completed, a new one is allowed; `open_for_service` returns only the open one.
3. `put("safety-concern", "task-1", "Board showed accepting but they were closed")` returns a handle of at least 22 characters; `get(handle)` returns the text; `get("nope")` is `None`.
4. 281 characters raises `ValidationFailed`.
5. The `ProtectedText` node has no relationships, and no other node in the graph contains the text (`MATCH (n) WHERE NOT n:Protected AND any(k IN keys(n) WHERE toString(n[k]) CONTAINS 'they were closed') RETURN count(n)` is 0).
6. A test over the G01 query registry: no query outside `Q-PROT-*` mentions `Protected`.
