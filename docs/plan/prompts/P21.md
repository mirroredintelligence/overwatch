**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Add the case port and its Neo4j implementation: a pseudonymous Patient stub, a ServiceRequest and the referrer's score Observations. A closed case must leave no postcode or needs anywhere in the graph.

**Read first.**
- `application/ports/outbound/repositories.py`, `graph_store/service_repository.py` (P01): the pattern to follow.
- `domain/model/case.py`, `domain/model/scores.py` (D18): `Case`, `Case.close`, `priority_for`, the score types.
- `graph_store/resource_store.py` (G05): `NO_HISTORY_TYPES` (Patient and ServiceRequest keep no `ResourceVersion` history).
- `backend/tests/support/` (F10). `docs/spec/fhir-data-model.md`: "Cases and bookings" (Patient stub, Case, Referrer score).

**Rules you need.**
- Tests use `write_tx` / `read_tx`. No fakes.
- Patient stub: `active true`, age band as an extension, `address.postalCode` only while the case is open, `meta.tag` pseudonymised-case-stub, `meta.security` restricted. Never `name`, `identifier`, `birthDate`, `telecom`.
- ServiceRequest: `status` (`active`, `completed` once closed), `intent "plan"`, `priority` (`urgent` for within 2 hrs, `routine` for today or planned), `authoredOn`, `identifier` for the case reference (system `https://diucs.example/case-reference`, also copied to property `reference`), extension `referrerType`, `subject` the Patient, `reasonCode` one per need (need-category concepts), `performer` the destination service once chosen, extensions `outcome` and `bestFitNotUsed`, `supportingInfo` the score Observations.
- Score Observation: `status "final"`, `subject` the Patient, `code` from acuity-method, `valueInteger` (NEWS2, CFS, ambulance category) or `valueCodeableConcept` (Manchester level, Pathways Dx code). Recorded as given; kept after close.
- Saving a closed case removes `postalCode` and every `reasonCode` (and their `REASON_CODE` relationships). Need categories kept for audit live in the audit snapshot, not here. Because these types keep no history, no old copy survives.

**Build.**
- Port `CaseRepository` (async): `add`, `get`, `get_by_reference`, `save`. `add` of an existing id raises `Conflict`; `save` of an unknown id raises `NotFound`.
- `graph_store/case_repository.py`: `Neo4jCaseRepository(tx, store)`, pure `case_to_fhir(case) -> tuple[dict, dict, list[dict]]` (Patient, ServiceRequest, score Observations) and `case_from_fhir(...)`, query `Q-CASE-BY-REF`. Patient id is `pt-<case id>`; score ids are `sc-<case id>-<n>`.

**Tests to write first.**
1. Unit: `case_to_fhir` for an open case (ambulance crew, 80+, DT4 8XX, fall-no-injury + frailty, within 2 hrs, NEWS2 2, CFS 6) gives `priority "urgent"`, two `reasonCode`s and a Patient with none of `name`, `identifier`, `birthDate`, `telecom`.
2. Unit: `case_from_fhir(*case_to_fhir(c)) == c` for that case and for one with a Manchester and a Pathways Dx score.
3. `assert_round_trip` for the open case; `node_props("Patient", id="pt-case-1")["postalCode"] == "DT4 8XX"`.
4. `get_by_reference("4821")` finds it; unknown → `None`.
5. Close the case (`accepted-and-booked`, destination UCR West) and save: `MATCH (n) WHERE n.postalCode IS NOT NULL OR n.json CONTAINS 'DT4 8XX' RETURN count(n)` is 0; `MATCH ()-[r:REASON_CODE]->() RETURN count(r)` is 0; `count_nodes("ResourceVersion")` did not grow.
6. After close, `get` returns the closed case with `postcode None`, empty needs, the outcome, the destination and both scores; the ServiceRequest has `PERFORMER` to UCR West.
7. `add` twice raises `Conflict`; `save` of an unknown case raises `NotFound`.
