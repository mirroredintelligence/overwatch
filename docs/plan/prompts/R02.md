**Goal.** Authenticate every FHIR call, turn the token into an `Actor`, and give routes three helpers: require a role, require the caller can act for a service, and project a resource for the caller's role. Refusals never reveal whether something exists.

**Read first.**

- `backend/src/diucs/application/actor.py` (P05): `Actor`.
- `backend/src/diucs/application/ports/outbound/tokens.py` and `backend/src/diucs/adapters/testing/fixed_secrets.py` (P10): `SecretStore`, `FixedSecretStore`.
- `docs/spec/architecture.md`, "Authorisation" and "Security, IG and operations".

**Rules you need.**
- The BFF sends `Authorization: Bearer <JWT>`, HS256, secret `SecretStore.get("bff-jwt")`. Claims: `sub`, `role` (a `Role` value), `services` (list, may be empty), `device` (optional), `exp`. Missing, expired or badly signed → 401 OperationOutcome `login` with `WWW-Authenticate: Bearer`.
- Patient-level resources (Patient, ServiceRequest, score Observations) are visible to `advisor` and `clinical` only.
- When a caller may not see a record, answer as if it does not exist (raise `NotAllowed` → R01's 404 body).
- Projection: when fields are removed by role, add `meta.security` `{"system": "http://terminology.hl7.org/CodeSystem/v3-ObservationValue", "code": "REDACTED"}`. First rule: for `reporter`, a booking Task loses `focus` and `for`.
- Tokens hold no secrets of record; nothing about them is stored, so this task needs no repository.

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/auth.py`:
- `current_actor` dependency → `Actor(role, practitioner_id, device_id, channel="api", service_ids=frozenset(services))`; for role `wall`, `sub` is the `device_id`.
- `require_role(*roles)` dependency factory → `NotAllowed` for other roles.
- `ensure_can_act_for(actor, service_id)` → `NotAllowed` unless the id is in `actor.service_ids` or the role is `lead`, `advisor`, `clinical` or `audit`.
- `PATIENT_ROLES = {Role.ADVISOR, Role.CLINICAL}`, `ensure_patient_access(actor)`.
- `ProjectionRegistry.register(resource_type, role, fn)` / `project(resource, actor)`; register the booking rule.
- `issue_test_token(role, services, sub)` in `backend/src/diucs/adapters/testing/tokens.py`, used by later route tests with `api_client`.

**Tests to write first.** Pure helpers as unit tests; the HTTP cases through R01's `api_client` with throwaway test routes.
1. No header → 401 `login`; expired token → 401; wrong signature → 401.
2. A valid reporter token yields an `Actor` with `service_ids == {"svc-1"}`.
3. `require_role(Role.LEAD)` with an advisor token → 404 body identical to a missing record.
4. `ensure_can_act_for` passes for a reporter on `svc-1`, refuses on `svc-2`, passes for a lead anywhere.
5. `ensure_patient_access` refuses `exec`, `wall`, `reporter`.
6. Projecting a booking Task for `reporter` removes `focus` and `for` and adds the REDACTED label; for `advisor` it is unchanged with no label.
7. A wall token sets `device_id`, not `practitioner_id`.
