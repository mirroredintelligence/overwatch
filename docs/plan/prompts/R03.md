**Goal.** Add optimistic concurrency and idempotent creates to the FHIR API: ETags on reads, `If-Match` required on updates, and `Idempotency-Key` required on every create with a fast replay guard. Version numbers come from the real resources in Neo4j.

**Read first.**

- `backend/src/diucs/application/idempotency.py` (P15): the durable `IdempotencyStore` in Neo4j that use cases use. Do not duplicate it.

**Rules you need.**
- Reads of a versioned resource return `ETag: W/"<versionId>"` and set `meta.versionId`.
- Every PUT sends `If-Match: W/"<versionId>"`. Missing → 428 `required` ("A write without a version is refused"). Mismatch with the stored version → 412 `conflict`.
- Every state-changing POST sends `Idempotency-Key` (1 to 200 visible ASCII characters). Missing → 400 `required`.
- Fast replay: the first response (status, key headers, body) is cached 24 hours under `idem:<actor sub>:<key>` with a SHA-256 of the request body. Same key and body → stored response with `Idempotent-Replay: true`, use case not called. Same key, different body → 422 `conflict` ("This key was used for a different request").
- This cache guard is cheap and short-lived. The durable guard is the Neo4j `IdempotencyStore` inside the use case; pass the key into the command as `idempotency_key` so it still holds after the cache entry expires or Redis restarts.

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/concurrency.py`: `etag_for`, `parse_if_match`, `require_if_match` dependency (428), `check_version(expected, current)` → `PreconditionFailed` (412), and an `idempotency_key` dependency plus `ReplayCache(cache)` with `lookup(actor, key, body_hash)` / `save(...)`. Register the 428 and 412 handlers in R01's error module.

**Tests to write first.** `api_client` with a throwaway test router whose handler runs a real use-case-style write through the unit of work (store a `:TestThing` node with `versionId`) and counts calls.
1. GET on a stored resource with `versionId` 3 → `ETag: W/"3"`.
2. PUT without `If-Match` → 428; with `W/"2"` when the stored version is 3 → 412 and the node is unchanged; with `W/"3"` → handler runs and the stored version is 4.
3. POST without `Idempotency-Key` → 400.
4. Two POSTs with the same key and body → handler runs once; one `:TestThing` node in Neo4j; second response equal with `Idempotent-Replay: true`.
5. Same key, different body → 422; still one node.
6. Same key from two different `sub`s → both run.
7. After the 24-hour TTL (manual clock on `InMemoryCache`) the request reaches the handler again, and the durable `IdempotencyStore` check in the handler stops a second node.
