**Rules you need.**
- `GET /fhir/HealthcareService` supports `active`, `service-category`, `organization`; returns a `searchset` Bundle. `GET /fhir/HealthcareService/{id}` returns one with an ETag. Any authenticated role may read services.
- `POST /fhir/Observation` creates a capacity report. Required: `status: final`, `code` from `code_system_url("capacity-measure")`, `focus` = `HealthcareService/{id}`, `valueQuantity` with an integer `value`, `system: http://unitsofmeasure.org`, a UCUM annotation `code` (`{referral}`, `{bed}`, `{slot}`, `{patient}`), `method` from `report-source`, `effectiveDateTime`. Needs `Idempotency-Key`. Roles `reporter` (own services only) or `lead`. 201 with `Location` and the created resource.
- Reports are never edited: PUT, PATCH, DELETE on Observation → 405 `not-supported` ("Reports are not edited. Send a new report.").
- `GET /fhir/Observation?focus=HealthcareService/{id}&_sort=-date&_count=1` → latest report in a Bundle (empty Bundle if none).

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/mapping.py`: `service_to_fhir`, `report_to_fhir`, `report_command_from_fhir(resource, actor, key)`; validate outbound resources with `fhir.resources.R4B`. `backend/src/diucs/adapters/inbound/fhir_rest/routes_services.py`: thin routes; register them in the CapabilityStatement.
