**Rules you need.**
- `GET /fhir/HealthcareService/$board` returns `Parameters`: one `entry` parameter per service whose `part`s are the `BoardEntry` fields in camelCase (`serviceId`, `name`, `category`, `status`, `effectiveAvailable`, `overBy`, `used`, `established`, `pending`, `unitLabel`, `comment`, `reportedAt`, `nextDueAt`, `wasDueAt`), typed `valueString`, `valueInteger`, `valueCode` or `valueDateTime`; omit null parts. Top-level `pressure` (valueCode), `allLimitedOrWorse` (valueBoolean), `generatedAt` (valueDateTime). `Cache-Control: no-store`.
- Roles for `$board`: `wall`, `advisor`, `clinical`, `lead`, `exec`, `owner`. Never patient data.
- `POST /fhir/HealthcareService/{id}/$confirm-capacity`: roles `reporter` (own service) or `lead`; needs `Idempotency-Key`. Two confirms in a row already → 409 `business-rule` "Send the number for <service name>." Success → the new Observation (`confirmed`, `derivedFrom` the previous one).
