**Goal.** Stream live changes to open pages as server-sent events, so the wall board and the advisor screen refetch when a capacity figure, a status or a pending booking changes. The stream relays the cache's pub/sub channel; it stores nothing.

**Read first.**
- `backend/src/diucs/application/use_cases/board_projector.py` (U09): what it publishes on `board.updates`.
- `backend/src/diucs/application/ports/outbound/cache.py` and `adapters/testing/memory_cache.py` (P09): `Cache.subscribe`. Redis is not a store of record, so `InMemoryCache` is the right fake here.
- `backend/src/diucs/adapters/inbound/fhir_rest/auth.py` (R02), `backend/tests/support/api.py` (R01).
- `docs/spec/architecture.md`, "Live updates".

**Rules you need.**
- `GET /events` → `Content-Type: text/event-stream`, `Cache-Control: no-store`, connection kept open.
- Each `board.updates` message becomes `event: board` and a `data:` line of compact JSON with only `serviceId`, `kind` (`capacity`, `status`, `booking`) and `changedAt`. Anything else is dropped.
- `: keep-alive` comment every 15 seconds.
- A missed event is harmless; no replay, no `Last-Event-ID`.
- Roles `wall`, `advisor`, `clinical`, `lead`, `exec`; others → 404.
- On disconnect, unsubscribe and end the generator.

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/routes_events.py`: `GET /events` with `StreamingResponse`; pure `to_sse(message) -> str | None`; keep-alive interval as a module constant.

**Tests to write first.**
1. Unit: `to_sse({"serviceId": "svc-1", "kind": "capacity", "changedAt": "2026-10-23T13:12:00Z", "extra": "x"})` → `"event: board\ndata: {\"serviceId\":\"svc-1\",\"kind\":\"capacity\",\"changedAt\":\"2026-10-23T13:12:00Z\"}\n\n"`.
2. Unit: unknown `kind` or no `serviceId` → `None`.
3. `api_client` (test container with `InMemoryCache`): open the stream with a wall token, publish one message, read the first event.
4. Keep-alive set to 0.05 s and nothing published → `: keep-alive`.
5. Reporter token → 404.
6. Closing the client leaves zero subscribers on the fake cache.
7. End to end (Docker): posting a capacity Observation through R04's route, with the U09 projector wired in the test container, produces one `event: board` for that service.
