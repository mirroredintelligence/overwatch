**Goal.** Expose registration, the scope list and criteria over FHIR as thin routes over the S6 use cases. One happy path and one refusal per route is enough. Tests read results back from Neo4j.

**Rules you need.**
- Scope list (role `lead`): `GET /fhir/List/scope-list`; `POST /fhir/List/scope-list/$entry` (parts `service`, `flag`, `reason`).
- Invite (role `lead`): `POST /fhir/Task/$invite-reporter` (parts `service`, `role`, `mobile`, `suggestedChannel`). Only `in-pilot` entries can be invited; others → 409 `business-rule`. The response shows only the number's last 4 digits.
- Applicant (role `reporter`, scoped to the registration through the invitation): `PUT /fhir/Task/{id}/$draft` (errors as one OperationOutcome with an issue per field, each with `expression`), `POST /fhir/Task/{id}/$submit`.
- Reviewer (role `lead`): `POST /fhir/Task/{id}/$callback` (`result`, `spokeToRole`), `$scope-decision` (`flag`, `reason`), `$approve`, `$send-back` (`note`), `$not-approve` (`note`), `$set-live`. `$approve` before every check is done → 409 `business-rule` listing `missing_for_approval` items.
- Criteria: `POST /fhir/Basic` creates a draft version (role `owner` for the service); `POST /fhir/Basic/{id}/$submit-for-approval` (part `reason`); `$approve` and `$send-back` (role `lead` as clinical lead; the owner cannot approve their own change → 404); `POST /fhir/HealthcareService/{id}/$confirm-criteria` (part `reviewInMonths` 3, 6 or 12); `GET /fhir/Basic?subject=HealthcareService/{id}` lists all versions, newest first.
- All POSTs need `Idempotency-Key`. Notes are short, carry no patient information, and notes over 280 characters are rejected.

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/routes_registration.py` and `routes_criteria.py`, with mapping helpers.

**Tests to write first.**
1. Lead adds a scope entry `in-pilot`; GET shows it; the stored `ENTRY` relationship has that flag.
2. Invite for a `later` entry → 409; for `in-pilot` → 201, body has `numberEnding` only.
3. `$draft` organisation step with no ODS code → 400 with an issue whose `expression` is `["odsCode"]`.
4. `$approve` with the call-back not done → 409 listing "Call-back done".
5. Full happy path: callback confirmed, scope pilot, criteria approved, `$approve` → `businessStatus: approved` (read back from Neo4j).
6. Owner creates v4 and submits; the same owner's `$approve` → 404; a lead approves → v4 current, v3 superseded in the GET list.
7. `$confirm-criteria reviewInMonths=5` → 400.
