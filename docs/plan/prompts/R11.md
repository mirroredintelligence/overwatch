**Goal.** Give the reporter app its identity routes (text code, PIN) and the route that stores a push subscription with its consent. The routes map JSON to use cases; the code store is Redis (I13) and PIN credentials are in Neo4j (P16).

**Rules you need.**
- `POST /identity/code` (`{"mobile"}`): always 202 with the same body, whether or not the number is known. A resend before 60 seconds is still 202 and sends no second code.
- `POST /identity/code/verify` (`{"mobile", "code", "deviceId"}`): 200 `{"verified": true}` on success; a wrong code → 400 `invalid` "That code is not right"; 5 wrong tries or an expired code → 400 "Ask for a new code".
- `POST /identity/pin` sets a 6-digit PIN for the verified device; it needs a verification from the last 10 minutes. `POST /identity/pin/verify` checks it; 5 wrong tries lock it → 423 `lock-error` "Your PIN is locked. Get a code by text to set a new PIN."
- `GET /identity/status` → `{"reverifyDue": bool, "daysLeft": n}` for the 30-day text-code check.
- `POST /identity/push-subscription` (role `reporter` or `exec`): subscription JSON, `wordingVersion`, `deviceId`; uses I14's `SavePushSubscription`. `DELETE /identity/push-subscription` removes it.
- Never log mobile numbers, codes or PINs; responses never echo them. These routes return plain JSON, with OperationOutcome for errors.

**Build.** `backend/src/diucs/adapters/inbound/fhir_rest/routes_identity.py`. The routes only map JSON to commands.

**Tests to write first.** `api_client`, Docker running; a reporter seeded through `Neo4jPersonRepository` with the contact in `Neo4jContactStore`.
1. Known and unknown numbers both get 202 with identical bodies; only the known one causes a recorded code send.
2. Verify with the right code → 200; wrong code five times → the fifth answer says "Ask for a new code".
3. Setting a PIN without a recent verification → refused.
4. PIN verify wrong five times → 423 `lock-error`; the stored credential shows the lock.
5. `GET /identity/status` 31 days after verification → `reverifyDue: true`.
6. Push subscription saved → `Neo4jPushSubscriptionRepository` returns it; the stored consent has the wording version and device id.
7. No response body contains the mobile number or the code.
