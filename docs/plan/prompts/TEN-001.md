*2. The registration-time check: `queries.py`.*
- `NamedQuery` gains `scope: Literal["tenant", "global"] = "tenant"` (fourth field, default keeps every existing construction valid). An invalid scope raises `ValueError` in `__post_init__`, like an invalid mode.
- `class TenantRule(StrEnum)`: `NO_TENANT_PARAMETER = "no-tenant-parameter"`, `UNSTAMPED_PATTERN = "unstamped-pattern"`, `MERGE_UNSTAMPED = "merge-pattern-unstamped"`, `SET_WITHOUT_RESTAMP = "set-without-restamp"`, `FOREIGN_TENANT_PARAMETER = "foreign-tenant-parameter"`.
- `check_tenant_scoping(cypher: str) -> tuple[TenantRule, ...]` is a pure function: it returns the rules the statement breaks, each at most once, in the declaration order above, or `()`. Algorithm (a guard, not a proof: a regular expression cannot parse Cypher, and the generated test of TEN-004 is the proof). First blank out string literals (`'...'`, `"..."`) and `//` comments so text inside them is never scanned. Then:
  1. `NO_TENANT_PARAMETER` unless the text matches `\$tenant\b` (so `$tenantId` does not count).
  2. Find node patterns with the regular expression `(?<![\w.$])\(\s*(?P<var>[A-Za-z_]\w*)?\s*(?P<labels>(?::\s*[A-Za-z_]\w*)+)?\s*(?P<props>\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\})?\s*\)`. The look-behind means a parenthesis directly after an identifier or a dot is a function call (`count(n)`, `coalesce(h._lock, 0)`, `point({latitude: ...})`, `datetime($at)`) and is skipped. A pattern whose variable is a keyword literal (`true`, `false`, `null`) is skipped. Process the patterns in text order and keep a set of variables seen so far. A pattern with a label or a property map, or an anonymous `()`, or a bare `(v)` whose variable has not been seen before, must be stamped. A bare `(v)` whose variable was seen earlier in a pattern (or in a `WITH`, `UNWIND ... AS v`, or `CALL { WITH v` list) is a reuse of a bound node and is skipped.
  3. A pattern is stamped when its property map contains `tenantId\s*:\s*\$tenant\b`, or when the same variable is stamped anywhere in the statement by another pattern or by the text `v.tenantId = $tenant` (spacing tolerant). A pattern with no variable (an anonymous node) must carry the stamp in its own map. A pattern that fails is `UNSTAMPED_PATTERN`.
  4. A pattern that is the first token after `MERGE` must carry the stamp in its own map, because a later `SET n.tenantId = $tenant` does not make the MERGE match on the tenant. If it is stamped only by a `WHERE` or `SET` it is `MERGE_UNSTAMPED` (and not also `UNSTAMPED_PATTERN`).
  5. `SET_WITHOUT_RESTAMP`: for every `SET v = ...` or `SET v += ...` (including later items of a comma list, and `ON CREATE SET` / `ON MATCH SET`) where `v` is a node variable (it appeared in a node pattern), the statement must also contain `v.tenantId = $tenant`. `SET n = map` replaces every property and would drop the stamp. A variable that only appears inside `[...]` is a relationship and is exempt. The SET clause ends at the next clause keyword (`RETURN`, `WITH`, `MATCH`, `MERGE`, `CREATE`, `DELETE`, `REMOVE`, `UNWIND`, `WHERE`, `ON`, `CALL`, `FOREACH`, `SET`).
  6. `FOREIGN_TENANT_PARAMETER`: the text contains `tenantId\s*:\s*\$` followed by anything other than `tenant\b`, or `tenantId = $` followed by anything other than `tenant\b`. `sourceTenantId` is not matched (it is a different name and is TEN-037's).
- `GLOBAL_QUERY_IDS: Final[frozenset[str]] = frozenset({"Q-NEO4J-PING"})`. This is the pinned allowlist of DEC-134 item 9. Do not add any other id; TEN-007 (tenant lookups), TEN-013 (link-token hash lookup) and TEN-051 (network registry) add theirs and edit the pinning test in the same commit.
- `class TenantPredicateMissing(ValueError)`.
- `QueryRegistry(mode: TenancyMode | None = None)`. `None` means "read the process mode at each `register` call". `register(query)` keeps its duplicate-id check and then: (a) a statement with `scope="global"` must have its id in `GLOBAL_QUERY_IDS` and must not contain `$tenant`; otherwise `ValueError` naming the id, in both modes (the allowlist is new, nothing existing uses it, so refusing is safe); it is registered with no tenant check. (b) A statement with `scope="tenant"` is checked with `check_tenant_scoping`. If the result is empty it is registered. If not: in `warn` mode it is registered and recorded; in `enforce` mode it is not registered and `TenantPredicateMissing` is raised, the message naming the query id and the rule codes and never the Cypher text. New methods: `violations() -> dict[str, tuple[TenantRule, ...]]` (a copy: the ids that failed the check and their rules), `unscoped_ids() -> list[str]` (sorted), `is_unscoped(query_id: str) -> bool`. Registering a flagged statement in warn mode logs one `DEBUG` line (logger `diucs.adapters.outbound.graph_store.queries`) with the id and the rule codes only. The existing duplicate and unknown-id errors keep their messages.
