**Goal.** After this task a unit of work binds exactly one scope and keeps it. `Neo4jUnitOfWork` reads the bound scope once when it is entered, wraps its transaction in a `ScopedTx` that carries that scope, and every repository and the resource store run on the `ScopedTx`; rebinding the context afterwards changes nothing for that unit. Opening a second unit of work while one is still open in the same context is refused. The other code paths that open a transaction outside a unit of work (`DriverIdempotencyStore`, `ensure_audit_head`, `Neo4jConnection` scoped helpers) take the same snapshot, the health ping and the migration runner stay on the global path, and the composition root sets the process `TenancyMode` from the settings. Everything still works with the mode at `warn` and nothing bound, so the existing repositories, use cases and tests keep passing; in `enforce` an unbound unit of work is refused before a session is opened.

**Why.**
- Audit A section 7.1 items 3, 4 and 7: a bare context variable read inside `run_query` fails open in three ways: a background task created with `asyncio.create_task` copies the context at creation and keeps a stale tenant; a variable changed inside an open unit of work would change the tenant mid-transaction; and `DriverIdempotencyStore`, `ensure_audit_head` and `neo4j_health` open their own sessions outside a unit of work. The fix is to read the context once, at the moment the unit opens, and carry the scope on the transaction. DEC-132 item 4: a unit of work binds exactly one scope, and the projector's two units (tenant scope, then network scope) are sequential, never nested.
- DEC-130 item 2 (the binding is fail closed) and DEC-134 item 12 (warn first, enforce later): this task makes the unit of work the place where the scope is fixed, in both modes. Audit B section 2 item 3: `UnitOfWork.__aenter__` snapshots the tenant so a mid-flight rebind cannot change what the unit writes.
- DEC-134 item 9 and audit A section 7.1: the health ping and the migrations run on the global path, not on a scoped transaction.
- DEC-012 and DEC-083 item 9 stay true: one session per unit, closed on every path; a write that raised `Conflict` is never committed. This task must not weaken either.
- Plan section 4.2 ("Cross-cutting edits make merges collide"): the transaction type is widened with an alias (`Tx`) so the roughly twenty repository classes need no edit here; each repository task re-annotates its own constructor.

*1. The scoped transaction: `driver.py`.* (This file belongs to TEN-001; this task adds to it. See Coordination.)
- `@dataclass(frozen=True, slots=True) class ScopedTx` with two fields: `tx: AsyncManagedTransaction | AsyncTransaction` and `scope: ScopeId | None`. It has no `run` method and no other way to execute Cypher: the only way to run a statement on it is `run_query`, so a repository cannot bypass the tenant parameter. `scope` is `None` only for a unit opened unbound in `warn` mode.
- `type Tx = AsyncManagedTransaction | AsyncTransaction | ScopedTx` (the transitional alias; TEN-030 narrows it to `ScopedTx`).
- `run_query` and `run_global_query` accept a `Tx` (a `ScopedTx` is unwrapped to its `tx` to send the Cypher). Scope resolution in `run_query` (the order of TEN-001 is kept; only step 4 changes): if `tx` is a `ScopedTx`, the scope is `tx.scope` and the ambient context variable is ignored (a unit opened under `a1` keeps `a1` however the context changes; a unit opened unbound stays unbound); if `tx` is a raw transaction, the scope is `current_scope_or_none()` as in TEN-001 and, in `enforce` mode, `run_query` raises the new `RawTransactionRefused` before any Cypher is sent. `run_global_query` accepts raw and scoped transactions and ignores the scope.
