*5. The runner: `run_isolation(...)` in `tests/support/query_probes.py`.* `async run_isolation(driver, *, registry, query_ids, probes, parts, tenant_a, tenant_b) -> list[Finding]`; `Finding` is a frozen dataclass of `query_id`, `phase`, `kind: FindingKind`, `detail` (counts and names only, never values) and `FindingKind` is a `StrEnum`: `rows-differ`, `own-state-differs`, `other-tenant-changed`, `unstamped-node`, `cross-scope-relationship`, `foreign-id-effect`, `no-rows`, `no-effect`, `probe-error`. It runs two phases, `(first, second) in ((tenant_a, tenant_b), (tenant_b, tenant_a))`, so the check holds in both directions:
1. Wipe the database (the harness wipe, whole database in this task). Seed `first` alone. For each id, run its probe as `first`, and record the baseline: the rows, normalised (canonical JSON of each row with datetimes as ISO text, sorted, as a multiset), and the digest of `first`'s own subgraph after the statement.
2. Seed `second` on top, with its extras. For each id run the probe as `first` again and compare: the rows must equal the baseline (`rows-differ`), `first`'s own subgraph digest after the statement must equal the baseline digest (`own-state-differs`), `second`'s subgraph digest must be the same before and after the statement inside the same transaction (`other-tenant-changed`), and after the statement no node anywhere lacks `tenantId` except `Migration`, `Tenant`, `TenantNumber`, `Network`, `NetworkMembership` and `Grant` registry nodes (`unstamped-node`) and no relationship joins nodes with different non-null `tenantId`s (`cross-scope-relationship`): the invariant queries of audit A 3.3. If the baseline of a probe with `expects_rows=True` is empty, report `no-rows` ("the seed no longer matches the statement"); if `changes == "own"` and the baseline digest equals the digest before the statement, report `no-effect`.
3. Foreign ids (first phase only, where `second` is the tenant that owns the extras): for a probe with `foreign` parameters, run the statement as `first` with them. It must return no rows, change nothing in `first`'s subgraph, and change nothing in `second`'s (`foreign-id-effect`). A statement that raises reports `probe-error` with the exception class name only.
Every probe runs inside an explicit transaction opened on a session of the driver, wrapped in `ScopedTx(tx, ScopeId.tenant(first))` (TEN-002) and run through `run_query(..., registry=registry)`; the transaction is rolled back after the checks, so no cleanup or reseed is needed between probes. The digest of a tenant is the SHA-256 of the canonical JSON of its sorted nodes (labels sorted, properties with datetimes as ISO text) and the relationships among its nodes, read with test Cypher that carries `$tenant`.
