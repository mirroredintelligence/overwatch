**The product.** DIUCS capacity helps NHS urgent-care coordination services see, in real time, which community services, wards and virtual wards can take a patient. Services report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. - `transition_tenant(current: TenantStatus, target: TenantStatus) -> TenantStatus`.
- `suspend_tenant(tenant: Tenant, mode: SuspendMode, reason: SuspendReason, now: datetime) -> Tenant` and `resume_tenant(tenant, now) -> Tenant`, `start_offboarding(tenant, now) -> Tenant`, `complete_offboarding(tenant, now) -> Tenant`, `purge_tenant(tenant, now) -> Tenant` return a new `Tenant` with the status moved, the timestamps set, `epoch` incremented on suspend and resume (audit F section 2.3: sessions carry the epoch), `suspend_mode` and `suspend_reason` set and cleared as the invariants require. They call `transition_tenant` first. `purge_tenant` also refuses (`NotAllowed`) while `retention_hold_until` is in the future.
- Constants (named, in `tenant_lifecycle.py`): `OFFBOARDING_NOTICE = timedelta(days=30)` (DEC-136 item 10), `NUMBER_QUARANTINE = timedelta(days=90)` (DEC-136 item 10; audit C proposed 7 days earlier and DEC-136 is later and wins), `PURGE_OPERATORS_REQUIRED = 2`.
- `offboarding_may_complete_at(tenant) -> datetime` (`offboarding_started_at + OFFBOARDING_NOTICE`); `complete_offboarding` refuses (`NotAllowed`) before that instant unless `waived=True` is passed (the tenant waives the notice in writing: a boolean the use case sets, never read from a request here).
- `number_quarantine_until(retired_at: datetime) -> datetime`, `number_assignable(status: NumberStatus, quarantine_until: datetime | None, now: datetime) -> bool`. `NumberStatus` (StrEnum, `active`, `retired`, `quarantined`) is defined in `tenant.py`. A number is assignable only when it has never been assigned, or `quarantine_until` is set and `now >= quarantine_until`; `retired` and `quarantined` before that instant are not assignable. An aware-datetime check applies to every instant (naive: `ValueError`, as F06's helpers).
- `purge_blockers(tenant: Tenant, now: datetime, operator_refs: Sequence[str], typed_slug: str) -> list[str]`: fixed wording, fixed order: `"Tenant is offboarded"`, `"Retention hold has not passed"`, `"Two different operators are needed"`, `"The tenant id was not typed correctly"`. Empty means the purge may proceed.

*9. Activation blockers* (`rules/tenant_lifecycle.py`): `ActivationFacts` (frozen dataclass, all fields required, no defaults): `config_approved: bool`, `time_zone: str | None`, `active_numbers_tested: int`, `email_in_use: bool`, `email_sender_verified: bool`, `first_admin_invited: bool`, `entra_binding_verified: bool`, `role_mappings: int`, `contact_kinds: frozenset[ContactKind]`, `retention_classes_set: frozenset[RetentionClass]`, `references_recorded: frozenset[str]` (a subset of `{"dsa", "dpia", "dcb0160"}`), `wording_complete: bool`, `registers_services: bool`, `area_districts_set: bool`, `network_member: bool`, `agreement_accepted: bool`. `activation_blockers(facts: ActivationFacts) -> list[str]`: a list of fixed-wording sentences in this order (audit F section 2.4, the style of `missing_for_approval`), one per failing check, each test written as `is not True` or an exact membership so that anything other than the passing value counts as missing (fail closed): `"Configuration version approved"`, `"Time zone set"`, `"At least one sender number active with a test text delivered"`, `"Email sender verified"` (only when `email_in_use`), `"First tenant administrator invited"`, `"Sign-in directory bound and verified"`, `"At least one role mapping"`, `"Support contacts set: coordination phone and clinical safety officer"` (needs both of those kinds), `"Retention set for every data class"`, `"Data sharing, data protection and clinical safety references recorded"` (all three), `"System, referral system and coordination team names set"`, `"Area districts set"` (only when `registers_services`), `"Network agreement accepted"` (only when `network_member`). The references are strings the operator records; the system records that they were asserted, not that they are true (DEC-133 item 2): the wording above never says "approved" or "certified". `transition_tenant(PROVISIONING, ACTIVE)` itself does not know the facts: the activating use case (TEN-028) calls `activation_blockers` first and refuses on a non-empty list.

*10. `check_tenant_text(field, value)`* (rules 4 and 6): returns `value` unchanged when all of: it is exactly `str`; its length is 1 to the field's maximum (60 for `system_name` and `coordination_team_name`, 40 for `referral_system_name`); it has no leading or trailing space and no doubled space; it fullmatches `[A-Za-z0-9][A-Za-z0-9 .,'&()+-]*`; `find_patient_data(value) == []`. Otherwise `ValidationFailed(field, ...)` with a fixed message that never echoes the value. So no `/`, `:`, `@`, `{`, `}`, `<`, `>` or quote other than the apostrophe can appear (no link, address or markup can be smuggled into a text message through a name). The sample values used in tests: `"Dorset urgent care capacity"`, `"SystmOne"`, `"The SPOA shift lead"` (these are the original deployment's wording, kept in test fixtures only; no source file may contain them).

*11. Fail-closed summary.* An unknown setting key, an out-of-bounds value, a wrong type, a bad id, a naive datetime, a time zone outside the allow-list, an illegal status move, an enum of the wrong type, or a missing required fact never falls back to a default: it raises or lists a blocker. There is no default tenant id, no default organisation, no default wording in source.

*12. Where tenant data may live.* Nothing here stores or logs anything. No error message contains a tenant id, a name, a reference, a number or an address.
