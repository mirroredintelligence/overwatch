**Goal.** Make it impossible for any cache key, pub/sub channel, lock name or fencing counter to exist without a tenant. One function builds every name from the bound scope (a tenant, or a network scope), both the Redis adapter and the in-memory fake use it, and a missing scope is an error, never a default. Today the board cache key `board:v1` and the channel `board.updates` are global: the moment two tenants exist, tenant B's wall board would serve tenant A's cached board and its live stream would receive tenant A's service ids. The contract suite gains two-tenant cases that run against both the fake and Redis.

**Rules you need.**

*1. Name shapes, exactly.* The port callers keep passing logical names (`"board:v1"`, `"board.updates"`, `"relay"`, `"idem:<sub>:<key>"`). The cache qualifies every one with the bound scope:
- A tenant scope with id `<t>`: `diucs:<t>:<family>:<name>`. Example: `diucs:acme-icb:cache:board:v1`, `diucs:acme-icb:chan:board.updates`, `diucs:acme-icb:lock:relay`, `diucs:acme-icb:fence:relay`.
- A network scope: the segment is `_net-<id>` where `net-<id>` is the network scope id that TEN-001 defines (if TEN-001 already spells the id with the leading underscore, use it unchanged). Example: `diucs:_net-nw1:cache:board:v1`, `diucs:_net-nw1:chan:board.updates`. The leading underscore marks a scope that is not a tenant: a tenant id never starts with `_` (TEN-001's validator), so a network segment can never equal a tenant segment and `SCAN MATCH diucs:<segment>:*` stays exact.
- The four families are `cache`, `lock`, `fence`, `chan` (DEC-089 item 7, unchanged). The segment holds no colon, so a key parses uniquely into (segment, family, name) by splitting on the first three colons.
- Redis keys are `"diucs:" + <scoped name>`. The in-memory fake stores and exposes the same scoped name without the `"diucs:"` root, so a test can compare the two. The platform namespace `diucs:_:...` (pairing codes, source-address limiter; audit C 4.2) is **not** built here and is refused: nothing in this task may produce a segment `_`. TEN-040 and TEN-041 add that explicit path.

*2. One builder, in the port module.* In `application/ports/outbound/cache.py`:

- `scope_segment(scope: ScopeId) -> str`: the segment of rule 1.
- `ScopedNames` (frozen, slots): `segment: str`; methods `key(name) -> str`, `lock(name) -> str`, `fence(name) -> str`, `channel(name) -> str`, each returning `f"{segment}:{family}:{name}"`.
