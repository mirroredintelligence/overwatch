**Goal.** Every bus message carries the tenant it belongs to, in a property that the receiver checks before it does anything. The tenant is a required field of `BusMessage`; the Service Bus adapter writes it as `application_properties['tenantId']` and makes the message id and the session id tenant-qualified (`<tenant>:<local id>`); one pure reader turns the wire view back into a `BusMessage` and refuses a missing, malformed or mismatched tenant with a fixed reason; the in-memory bus applies the same rules, so the contract suite proves both behave the same. This task also fixes the shared names that the consumer framework (TEN-025) uses to bind the tenant and dead-letter a message with no usable tenant.

**Rules you need.**

*1. The names, exactly.*
- Application property key: `tenantId` (camel case, as the node property of DEC-130 item 1). Audit B calls it `tenant_id` and audit C calls it `tenant`; `tenantId` is the name fixed for this task and by the tenancy amendments to the I03 to I10 prompts. - `BusMessage.id` and `BusMessage.session_id` keep their meaning at the port: they are the **local** values. Only the wire form is qualified.

*2. `BusMessage` (in `event_bus.py`).* Add `tenant_id: str = field(kw_only=True)`, required, no default; the existing fields and their order do not change. `__post_init__` refuses (`ValidationFailed("tenant_id", ...)`): anything not exactly `str`, and anything TEN-001's validator refuses (empty, uppercase, a colon, over 31 characters, `_`-prefixed, `net-`-prefixed). It also refuses an empty `id` or an empty (not `None`) `session_id`, and a payload with a top-level key `tenantId`, `tenant_id` or `tenant` (`ValidationFailed("payload", "must not carry the tenant")`): the tenant is a message property, never part of the body, because a body copy would be a second, forgeable source (audit B section 7). It does not copy the payload; it is the same dict the caller passed.

*3. Pure wire functions (in `event_bus.py`, shared by both adapters and by the consumers; no SDK import).*
- `@dataclass(frozen=True, slots=True) class WireView: message_id: str; session_id: str | None; subject: str; application_properties: Mapping[str, str]`.
- `to_wire(message: BusMessage) -> WireView`: `message_id` and `session_id` qualified (rule 1; over-length refused), `subject = message.event_type`, `application_properties` = exactly `{"event_type": event_type, "tenantId": tenant_id}` plus `"channel": <value>` when the payload has a top-level `channel` that is a `str` (as today; a non-str channel is ignored, never stringified). No other payload value ever becomes a property (rule 8).
- `from_wire(topic: str, *, message_id: str | None, session_id: str | None, subject: str | None, properties: Mapping[str | bytes, object] | None, payload: object) -> BusMessage`: the only reader of the tenant. Property keys and values may be `str` or `bytes` (the SDK returns either; decode bytes as strict UTF-8). Steps and the exact reason for each failure (raise `MessageTenantError`, below):
  1. no `tenantId` key, or its value is `None` or `""`: `tenant-missing`;
  2. the key present in both its `str` and `bytes` forms, a value that is not `str` or `bytes` (an `int`, a `bool`), bytes that are not UTF-8, or a value TEN-001's validator refuses: `tenant-malformed`;
  3. `message_id` is `None`, empty, has no colon, or its part before the first colon differs from the property; or `session_id` is present and not empty and its part before the first colon differs, or the part after is empty: `tenant-mismatch`;
  4. then the event type is the `subject` or, if empty, the `event_type` property; none: `ValidationFailed("event_type", ...)`; a `payload` that is not a `dict`: `ValidationFailed("payload", ...)`.
  The result is `BusMessage(id=<local id>, topic=topic, event_type=..., payload=payload, session_id=<local session or None>, tenant_id=<property>)`. A failure never reveals the offending text.
- `MessageTenantError(DomainError)` with attribute `reason: str` and the fixed message equal to the reason. `TENANT_REJECTION_REASONS = ("tenant-missing", "tenant-malformed", "tenant-mismatch")` and the three constants. TEN-025 adds `tenant-unknown` (not in the directory) and the suspended-tenant outcome; this task only knows what it can see in a message.
- `TENANT_PROPERTY = "tenantId"`.
- Round trip: for every valid `BusMessage` `m` with `w = to_wire(m)`, `from_wire(m.topic, message_id=w.message_id, session_id=w.session_id, subject=w.subject, properties=w.application_properties, payload=m.payload) == m`.
