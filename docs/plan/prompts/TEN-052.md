*6. `application/projection.py`.*

- `to_body(dto) -> dict[str, ProjectionValue]` and `from_body(kind: GrantScope, body) -> ServiceProjection | CapacityProjection | CriteriaProjection`: the body keys are the DTO field names, flat (TEN-038's floor): location fields inline, opening hours as a tuple of window strings `"<days csv>|<start>|<end>"` with times `HH:MM:SS` and `"<days csv>|all-day"` (`format_window`, `parse_window`), timestamps ISO 8601 with `Z`, dates `YYYY-MM-DD`. `from_body` accepts exactly the keys of `body_keys(kind)`: a missing key, an extra key, or a wrong type is `ValidationFailed("body", ...)` naming the key position but not echoing values, and the DTO's own validation runs again (so a message built by hand cannot bypass the guard). `from_body(to_body(dto)) == dto`.
- `check_network_write_statement(cypher: str) -> list[str]` returns problem codes (empty means safe); `assert_network_write_statement` raises `ValidationFailed` with the codes. It is a conservative tokenising parse, not a regex over the whole text. It first removes `//` and `/* */` comments and masks string literals; then it must fail closed (`unparseable` on anything it cannot read). Problems:
  - `map-assignment`: `SET x = $p`, `SET x = {..}`, `SET x += $p`, `SET x += {..}` (any `+=`, and any `=` whose left side is a bare variable), in `SET`, `ON CREATE SET` and `ON MATCH SET`.
  - `pattern-parameter-map`: a node pattern with `$param` as its property map, for example `MERGE (n:ProjectedService $props)`; `relationship-properties`: any property map or `SET` on a relationship.
  - `property-not-allowed:<Label>.<prop>`: a property written by `SET x.prop = ...` or named inside a `MERGE` or `CREATE` pattern map, where the variable's label is known from its pattern, and `prop` is in neither `ALLOWLIST[label]` nor `SYSTEM_PROPERTIES[label]`. Labels are those of `ALLOWLIST` plus `ProjectionSource` and `ProjectionCursor`.
  - `label-not-allowed:<Label>`: a written node whose label is not one of those (this refuses a tenant label such as `HealthcareService` or `Practitioner`), and `label-assignment`: `SET x:Label`.
  - `dynamic-property`: `x[...] =` in a `SET`, backticks anywhere, `keys(`, `properties(`, `FOREACH`; `call-not-allowed`: any `CALL`, any `apoc.`; `delete-not-allowed`: `DELETE`, `DETACH DELETE`, `REMOVE` (history stays: projections are ended by setting `endedAt`, never deleted); `relationship-not-allowed:<TYPE>`: a created relationship whose type is not in `NETWORK_RELATIONSHIPS`; `unknown-variable`: a write to a variable no pattern binds.
  - Statements with no write clause return `[]`.
  TEN-053 runs this over every network write it registers, TEN-062 runs it over the whole registry. A statement that spells every property out (`SET s.serviceName = $serviceName, s.sourceVersion = $sourceVersion, ...`) is the accepted form; `UNWIND $rows AS row ... SET s.serviceName = row.serviceName` is accepted too.
