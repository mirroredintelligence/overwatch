**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. **The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build the `ReportCapacity` use case: record a new capacity figure for a service, recompute its status, and write the report, an audit entry and outbox messages to Neo4j in one unit of work. Every reporting path (text, link, app, advisor phoned) ends here.

**Rules you need.**
- Reports are never edited; a correction is a new report. Values are whole numbers 0 to 999; 0 means closed to referrals.
- Status: `compute_status(profile, latest, confirmed_at, now)` before and after, where `profile` is the loaded profile with `suspended=True` (via `dataclasses.replace`) when `uow.flags.service_flags(service_id)` holds an active `suspended` flag. If it changed, emit `StatusChanged(service_id, before, after, at)`. Every report emits `CapacityReported(service_id, report_id, value, source, at)`.
- Domain events go to the outbox with `topic="capacity.events"`, `event_type=<Event>.event_type`, `payload=event.to_payload()`, `session_id=service_id`.
- Echo only when `source == ReportSource.TEXT` and a `performer_role_id` is given [ASSUMED]. C3 (`service, value, unit, recorded_at, next_due`), or C4 when `replaced_value` is set (`… replaced`). "Thanks. UCR West: 4 referrals, as of 08:06. Next prompt 10:00."
- Outgoing messages: a `Communication` (delivery_status "queued") plus outbox `topic="messages.outbound"`, `event_type="SendMessage"`, payload `{communication_id, message_id, channel, recipient_role_id, text}`. Never a phone number.
- A reporter may report only for services in `actor.service_ids`. Advisors and leads may report any service with source `advisor-phoned`.
