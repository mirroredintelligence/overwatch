**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. **Goal.** Extend `SendPrompts` so a phone that looks after several services due at about the same time gets one grouped prompt instead of several.

**Read first.**
- `application/use_cases/send_prompts.py`, `application/scheduling.py` (U03) and their integration tests.
- `domain/rules/multi_service.py` (D28): `GROUP_WINDOW`, `group_due`, `letters_for`.
- `graph_store/person_repository.py` (P03): `services_for_phone_hash(hash, now) -> list[tuple[PractitionerRole, str]]`.
- `docs/spec/ui-screens.md` artboard "MultiServicePhone".

**Rules you need.**
- Services on the same phone with due times within `GROUP_WINDOW = 10 min` [ASSUMED] of each other are prompted together. Letters A, B, C… follow service name order.
- C9 (`reply_by, items` of `(letter, service, value)`): "DIUCS: 2 services need an update by 10:30. A) UCR West 3. B) UCR East 1. Reply Y if both right, or A 4, or B 2." No figure yet shows "?" [ASSUMED].
- Reply-by is the earliest in the group. A partial reply never confirms the others (U05).
- Record keeping without a new node type: one `Communication` per grouped service, all `message_id=C9`, same `payload_text`, `about_id` = that service. Only letter A's gets a `SendMessage` outbox message; the others get `delivery_status="grouped"`.
- Each grouped service gets its own ladder work and next `prompt-due`, as in U03.
- When another grouped service's own `prompt-due` fires later it must do nothing: store the result under each grouped service's key `prompt:{service_id}:{due_at}` in the same unit of work.
- Group only services with the same channel [ASSUMED].

**Build.** In `send_prompts.py`: before sending, look up the phone's other services and due times (`current_due`/`next_due`), group with `group_due`; more than one service → C9. Add `SendPromptResult.grouped_service_ids: tuple[str, ...]`. Single-service path unchanged.

3. Ladder `ScheduledWork` nodes for both services.
4. `SendPrompts` for UCR East at 10:00 afterwards → `replayed`, node counts unchanged.
5. UCR East due 10:20 → two separate single prompts.
6. Three services due together → A, B, C in name order.
7. An email-channel service on the same phone is not grouped.
