**Goal.** Raise report flags when a capacity report breaks a rule, so the shift lead can check it. Flags are their own nodes, because reports are never edited.

**Read first.**
- `application/use_cases/report_capacity.py` (U01; U05 passes `flag=out-of-range-twice`).
- `domain/rules/report_flags.py` (D12).
- `domain/model/flags.py`, `ports/outbound/repositories.py` `FlagRepository`, `graph_store/flag_repository.py` (P14).
- `graph_store/capacity_repository.py` (P01): `reports_since`.

**Rules you need.**
- `out-of-range-twice`: decided by the reply policy and passed in as `command.flag`.
- `many-changes`: 3 or more reports for one service within `MANY_CHANGES_WINDOW = 5 min` [ASSUMED]. Example: Ward A "3 reports in 4 minutes: all Y, then 9, then 2."
- `differs-from-phoned`: a figure differs from an advisor-phoned figure in the previous `PHONED_WINDOW = 60 min` [ASSUMED].
- Flags come from rules, never from a person's speed. New flags are `open`. One open flag per service and reason at a time [ASSUMED].
- Each new flag adds an outbox message `capacity.events`, `event_type="ReportFlagged"`, payload `{flag_id, service_id, report_id, reason, at}`.

**Build.**
- `application/use_cases/report_flags.py`: `async def raise_report_flags(uow, ids, *, profile, report, extra: ReportFlagReason | None, now) -> list[str]`. Reads recent reports with `uow.capacity.reports_since(service_id, now - PHONED_WINDOW)`, calls `flags_for_report`, adds `extra`, drops reasons with an open flag (`uow.flags.open_report_flags`), writes flags and outbox messages.
- Call it from `record_report` in the same unit of work; add `flag_ids: tuple[str, ...] = ()` to `ReportCapacityResult`; add flag ids to the audit `entity_ids`.

**Tests to write first.** `tests/integration/application/test_report_flags.py`, real Neo4j.
1. Command with `flag=out-of-range-twice` → one stored open flag (read back with `uow.flags.open_report_flags`) linked to the report, and a `ReportFlagged` outbox node.
2. Ward A: Y 14:00, 9 at 14:02, 2 at 14:04 → the third raises `many-changes`; the first two raise none.
3. A fourth report at 14:05 does not raise a second `many-changes` while the first is open.
4. Phoned 2 at 13:30, text 5 at 14:00 → `differs-from-phoned`. Text 2 → none. Phoned at 12:30 → none.
5. The report is stored in every case.
6. Confirmations count for `many-changes`.
7. If writing the flag fails (force it with a flag repository stub raising inside the unit of work), neither the report nor the flag is in the graph.
