**Goal.** Build `QueryBoard`: the read model behind the wall board and the exec view, read from Neo4j. One entry per active service with status, number, data age and pending count, plus system pressure. No patient data.

**Read first.**
- `graph_store/service_repository.py`, `capacity_repository.py` (P01): `list_active`, `latest_for_services`; `graph_store/booking_repository.py` (P02): `open_for_services`, `confirmed_since`; `graph_store/flag_repository.py` (P14): `services_with_flag("suspended")`. `ServiceProfile.suspended` is not stored; set it with `dataclasses.replace` for services in that set before calling `compute_status`.
- `domain/rules/status.py` (D07), `freshness.py` (D05), `schedule.py` (D04), `pressure.py` (D08), `availability.py` (D06).
- `docs/spec/contracts.md` "QueryBoard result"; `docs/spec/ui-screens.md` artboards "Main", "TileStates", "BoardSurge", "BoardQuiet".

**Rules you need.**
- Status per service: `compute_status(profile, latest, confirmed_at, now)`, `confirmed_at` = confirmation times of bookings confirmed since the latest report.
- `pending` = bookings in `requested`. Pending never reduces available ("4 · 1 pending").
- `next_due_at = next_due(profile, now)`; `was_due_at` = `Freshness.was_due` when overdue.
- Pressure: count limited, not-accepting, over-capacity; ignore out-of-hours. Under 3 normal, 3–4 watch, 5+ high [ASSUMED]. `all_limited_or_worse` when every in-hours service is limited or worse.
- Order by `ServiceCategory` enum order, then name [ASSUMED].
- Any role except `anonymous-link`.
- Read with a bounded number of queries: one per repository call across all services, never one per service.

**Build.** `application/use_cases/query_board.py`: `QueryBoardQuery(actor)`; `BoardEntry`, `Board` as in the contracts; `QueryBoard(uow_factory, clock)` with `async execute(query) -> Board`. Read-only: no commit, audit or outbox.
