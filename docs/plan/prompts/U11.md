**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build `OpenCase` and `UpdateCase`: an advisor opens an empty case at the start of a call, then fills in age band, postcode, needs, urgency and referrer scores. Cases are stored in Neo4j as a pseudonymous Patient stub and a ServiceRequest. No name, no NHS number, no free text.

**Read first.**
- `domain/model/case.py`, `scores.py` (D18); `domain/rules/postcode.py` (D19); `domain/rules/booking_rules.py` (D14) `new_reference`.
- `ports/outbound/repositories.py` `CaseRepository` (`add`, `get`, `get_by_reference`, `save`), `graph_store/case_repository.py` (P21): how a case maps to the Patient stub (id `pt-<case id>`), ServiceRequest and score Observations.

**Rules you need.**
- Age band `0-15`, `16-64`, `65-79`, `80+`; urgency `within-2-hrs`, `today`, `planned`; optional scores as given: NEWS2 0–20, CFS 1–9, ambulance category 1–4, a Manchester level, a Pathways Dx code. Never calculated.
- Postcode normalised with `normalise_postcode`; "DT4 8X" is refused with `ValidationFailed("postcode")`.
- Reference: 4 digits from `new_reference` [ASSUMED], unique among open cases, retried on collision via `uow.cases.get_by_reference`.
- Only `advisor` and `clinical`. Updating a closed case → `Conflict`.
- Audit snapshots carry reference, age band, needs, urgency, referrer type. Never the postcode.

**Build.** `application/use_cases/open_case.py`: `OpenCaseCommand(idempotency_key, actor, referrer_type)` → `OpenCaseResult(case_id, reference)`, `OpenCase(uow_factory, clock, ids, idempotency, rng)`; `UpdateCaseCommand(idempotency_key, actor, case_id, age_band=None, postcode=None, needs=None, urgency=None, scores=None)` (None = unchanged) → `UpdateCaseResult(case_id, complete: bool, missing: tuple[str, ...])`, `UpdateCase(uow_factory, clock, idempotency)`. Complete = age band, postcode, ≥1 need, urgency. Audit `OpenCase`/`UpdateCase`; no outbox.
