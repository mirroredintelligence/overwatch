**Rules you need.**
- One scope list for the pilot (FHIR `List` with code `scope-list`). Each entry: service id, flag (`in-pilot`, `later`, `out-of-scope`), date, reason.
- Adding an entry creates the service as an inactive `ServiceProfile` placeholder (`active=False`) with name and category only, because the entry exists before the service registers. Use safe defaults for the other profile fields and say so in a code comment.
- A reason is required when the flag is not `in-pilot`.
- Changing a flag away from `in-pilot` does not affect a service that is already live; it only blocks new invitations [ASSUMED].
- Only role `lead` may add or change entries. Every change is audited with before and after flags, in the same unit of work as the change.
