**Goal.** Build the reviewer's side of registration up to the decision: start the review, compute the automatic checks, record the call-back and record the scope decision. All of it persists in Neo4j as registration state and Provenance.

**Rules you need.**
- Start review: `submitted` → `in-review`, lead role only.
- Automatic checks, each passed or failed with a message: ODS code found, active, and an NHS organisation type; name matches the ODS name (ignoring case and punctuation); address found and its district in `Settings.area_districts` (default DT1-DT11 and BH1-BH31 [ASSUMED]); reporting phone hash equals the invitation's phone hash; criteria owner email is an organisation address: `nhs.net` or the same domain as the organisation contact email, while free-mail domains (gmail.com, hotmail.com, outlook.com, yahoo.com) fail [ASSUMED]. A failed check can be explained with a note; explained counts as ok.
- Call-back: to the number on the register, never the applicant's number. Record a Provenance with activity `call-back`, the number called (kept in the `ContactStore`; the graph holds a hash), the role spoken to (required), result `confirmed`, `not-confirmed` or `no-answer`, the lead's role as verifier and the time.
- Scope decision: four questions (on the Dorset pathway, takes SPOA referrals, can report by app/text/email, category on the pilot list), each yes/no/not sure; then `in-pilot`, `later` or `out-of-scope`. Reason required unless `in-pilot`. Recorded as Provenance activity `scope-decision`.

**Build.** `backend/src/diucs/application/use_cases/review_registration.py`: `StartReview`, `RecordCallBack`, `RecordScopeDecision`, `ExplainCheck`, `GetReviewStatus`, each with `<Name>Command` and a result. `AutomaticCheck(name: str, passed: bool, message: str, explained_note: str | None)`; pure `run_automatic_checks(registration, invitation, ods_record, area_districts) -> tuple[AutomaticCheck, ...]` (unit-tested). `GetReviewStatus` returns the checks plus D22's `missing_for_approval`, computed from what is stored.

**Tests to write first.** Pure check cases in `tests/unit`; the rest in `tests/integration/application/test_review_registration.py`, seeding a `submitted` registration in Neo4j:
1. Start review: stored status `in-review`; a second start raises `InvalidTransition`.
2. Owner email `owner@gmail.com` fails with the message "Criteria owner email is not an organisation address".
3. Explaining that check, then reading status in a fresh unit of work: `automatic_ok` true.
4. Call-back `confirmed` with role "Duty manager": a `Provenance` node with activity `call-back` and a `TARGET` to the registration Task; the number called is not on it; the missing list no longer includes the call-back.
5. Call-back without a role raises `ValidationFailed`; no Provenance node is added.
6. Scope `later` without a reason fails; `in-pilot` passes and is stored.
7. `GetReviewStatus` lists "Criteria second approval" as missing until criteria are approved.
