**Rules you need.**
- Change: only the criteria owner (role `owner` with a PractitionerRole for that service). Create version n+1 as `draft` copying the current values with the changes, then move it to `pending-approval` with a required change reason (short, no patient information) and a review-again choice of 3, 6 or 12 months. Create a Task `approve-criteria` owned by the clinical lead. Only one pending version per service.
- Until approval, advisors keep seeing the current version.
- Approve: by a practitioner holding PractitionerRole code `clinical-lead`, who is not the author. Then the new version is `current`, the old one `superseded` (never deleted), the new version `SUPERSEDES` the old, the service's `CURRENT_CRITERIA` relationship moves, review-by = approval date + chosen months, and the outbox gets `criteria.events/CriteriaApproved` (its consumers clear the read-model cache). Open cases keep the version they saw.
- Send back: note optional; `pending-approval` → `draft`; the owner is told.
- Registration version 1 (status `pending-approval`, created by U27) is approved through the same `ApproveCriteria`.
- Confirm still right: owner only; no new version; review-by = today + 3, 6 or 12 months; audit records role and date; clears any `criteria-overdue` service flag.
