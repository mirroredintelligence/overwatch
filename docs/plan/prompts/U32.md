**Goal.** Build the PIN use cases for reporters and COO or ICB users: set a PIN on a device after a verified text code, sign in with it, lock after 5 wrong tries, reset by text code, and force a text code every 30 days or on a new device. Credentials persist in Neo4j as `Credential` nodes.

**Rules you need.**
- PIN: exactly 6 digits. Stored only as a keyed hash (HMAC-SHA256 with secret `pin-hmac`) per practitioner and device. A PIN set on one device does not work on another.
- Setting a PIN needs a text-code verification for the same phone within the last 10 minutes (purposes `setup`, `pin-reset` or `new-device`). Pass `verified_at` from `VerifyTextCodeResult`, checked against the clock.
- 5 wrong tries lock the credential. While locked, even the right PIN fails and the result says `locked=True`. A text code (purpose `pin-reset`) then a new PIN unlocks it.
- Sign-in fails with `needs_text_code=True` when `needs_reverification` is true (30 days since the last text code for this device, or an unknown device). Nothing else changes in that case.
- A successful sign-in resets the wrong-try count and returns the practitioner id, role and the service ids from active PractitionerRoles (for the session claims built by R11).
- Never log or audit the PIN or its hash.

**Build.** `backend/src/diucs/application/use_cases/pin.py`:
- `SetPinCommand(practitioner_id, device_id, pin, verified_at: datetime)` → `SetPinResult(ok: bool)`; `SetPin(uow_factory, secret_store, clock)`.
- `PinSignInCommand(practitioner_id, device_id, pin)` → `PinSignInResult(ok, locked, tries_left, needs_text_code, practitioner_id, role, service_ids)`; `PinSignIn(uow_factory, secret_store, clock)`.
- `RecordTextCodeVerified(uow_factory, clock)` stamping `last_verified_at` for a device (call it after U25 verification).
- If P16's credential port lacks a method you need, add it to the Protocol and the Neo4j adapter together, with a round-trip test.

**Tests to write first.** In `tests/integration/application/test_pin.py`, seeding a practitioner with two service roles:
1. Set "482913" with `verified_at` 2 minutes ago: ok; `node_props(driver, "Credential", deviceId=...)["pinHash"]` exists and does not contain "482913".
2. Set with `verified_at` 11 minutes ago: refused; no Credential node.
3. "48291" or "48291a" rejected by format.
4. Right PIN on the same device: ok, both service ids returned; on another device: `needs_text_code=True`.
5. Five wrong PINs: `locked=True, tries_left=0`, stored `failed=5` and `lockedUntil` set; the right PIN then still fails.
6. Reset: text code verified with `pin-reset`, new PIN set, sign-in works and the stored `failed` is 0.
7. Last verification 30 days and 1 minute ago: `needs_text_code=True`. Audit nodes contain no PIN or hash.
