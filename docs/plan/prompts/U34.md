**Rules you need.**
- Input: `StatusChanged` from `capacity.events`. For each alert from D24 and each subscriber for that kind where `should_notify(prefs, alert, now)`, create an Alert Task (code `acknowledge-alert`, businessStatus `new`, owner the subscriber), queue a push (K3, title "Hospital at home: over capacity", body "+4 since 13:10. Tap to acknowledge."), emit `alerts.events/AlertRaised`, schedule `alert-escalate` at `escalation_at` with `schedule_work`.
- Not-updated alerts: on a change to `not-updated`, schedule `not-updated-check` work (add `"not-updated-check"` to `WorkKind` if absent) at +2 h and +4 h; when it fires and the service is still not updated, alert subscribers whose threshold equals that age.
- System pressure: recompute from the current board; alert on a move to `high`.
- Acknowledge (owner only): `new` → `acknowledged`, cancel the escalation with `cancel_work`, emit `AlertAcknowledged`. It does not change the board.
- Snooze: move the escalation 1 hour later; the alert stays `new`.
- Escalation: if still `new` at the deadline, mark `escalated`, create a new Task `PART_OF` the first owned by the deputy, notify them, schedule the deputy's escalation; if the deputy also does not acknowledge, emit `alerts.events/AlertEscalatedToLead`. An acknowledgement anywhere in the chain closes it.
- No patient data in any alert. Idempotent on message id and work id (`ProcessedMessages`).
