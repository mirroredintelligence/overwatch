**Goal.** Add the BFF session: an HTTP-only cookie that holds who the user is and the back-end token, a double-submit CSRF check for every state change, and a small helper so route handlers can require a role.

**Read first.**
- `frontend/lib/fhir/client.ts`, `frontend/lib/bff/errors.ts` (W01).
- `docs/spec/contracts.md`, "Front end": the `Session` shape and `issueCsrf`/`checkCsrf` names.
- `docs/spec/architecture.md`, "Next.js front end" → Sessions and Link pages; "Security, IG and operations" → Browser.

**Rules you need.**
- `Session { role, services: string[], sub: string, device?: string, backendToken: string, expiresAt: string }`. `role` is one of reporter, advisor, clinical, lead, owner, exec, wall, anonymous-link, support, audit.
- Cookie `diucs_session`: HttpOnly, `SameSite=Strict`, `Path=/`, `Secure` unless `NODE_ENV === "development"`. Its value is encrypted with `jose` `EncryptJWT` (`dir` + `A256GCM`) using `SESSION_SECRET` (32 bytes, base64 env var). An expired or tampered cookie means no session.
- CSRF: double-submit. `issueCsrf()` sets a non-HttpOnly cookie `diucs_csrf` (random 32 bytes, base64url, `SameSite=Strict`) and returns the token. `checkCsrf(request)` passes only when header `X-CSRF-Token` equals the cookie, compared in constant time. Every POST, PUT, PATCH and DELETE BFF route checks it.
- `GET /api/bff/session` → 200 `{ role, services, sub, csrfToken }` or 401 `{ code: "no-session" }`. It never returns `backendToken`. `DELETE /api/bff/session` (CSRF-checked) clears both cookies → 204.
- Helper `withBff(handler, { roles?: Role[], csrf?: boolean })`: 401 `{code:"no-session"}` with no session; 403 `{code:"forbidden"}` when the role is not allowed; 403 `{code:"csrf"}` when CSRF fails; otherwise calls `handler(request, session)` and turns thrown errors into `toBffError`.

**Build.** `lib/auth/session.ts` (`getSession`, `createSession`, `destroySession`), `lib/auth/csrf.ts` (`issueCsrf`, `checkCsrf`), `lib/bff/handler.ts` (`withBff`), `app/api/bff/session/route.ts`. Use `next/headers` `cookies()`; keep pure helpers (`sealSession`, `unsealSession`) testable without Next.

**Tests to write first.**
1. `sealSession` then `unsealSession` round-trips a session.
2. Unseal of a modified string → `null`; of an expired session → `null`.
3. `checkCsrf` true when header equals cookie; false when header missing, different, or cookie missing.
4. GET `/api/bff/session` with a valid cookie → 200 with `csrfToken`, body has no `backendToken`.
5. GET with no cookie → 401 `no-session`.
6. `withBff` with `roles: ["lead"]` and an advisor session → 403 `forbidden`.
7. `withBff` with `csrf: true`, POST without header → 403 `csrf`; with matching header → handler runs.
8. DELETE with CSRF → 204 and both cookies cleared (`Max-Age=0`).
9. Cookie attributes on create include `HttpOnly`, `SameSite=Strict`, `Path=/`.
