**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Goal.** Build the shared UI building blocks every screen uses, matching the design canvas: buttons, toggle chips, option buttons, a number stepper, a card and a banner.

**Read first.**
- `frontend/app/tokens.css`, `frontend/components/ui/StatusBadge.tsx` (F09): tokens and an example component with its test.
- `docs/spec/ui-screens.md`, artboards "AdvisorActions" and "Reporter": how these controls look and read.

**Rules you need.**
- `Button`: `variant: "primary" | "secondary" | "neutral"`. Primary: background `--c-primary`, white text, no border. Secondary: white, `--c-primary` text and 2px border. Neutral: white, `--c-ink-2` text, 2px `--c-closed` border. Min height 52px, padding 0 22px, radius 14px, 19px bold. `busy` sets `aria-busy="true"` and disables it (stops impatient double clicks). Focus: 3px solid `--c-ink` outline, offset 2px. Renders `<a>` when `href` is given.
- `Chip`: a `<button type="button">` with `aria-pressed`. Min height 48px, radius 24px, 2px `--c-unknown` border; pressed: `--c-primary` fill, white, bold. Props `pressed`, `onPressedChange(next)`.
- `OptionButton`: full-width list choice, min height 56px, radius 14px. Selected: `--c-primary` border, `--c-tint` fill, `--c-primary-dark` text, a check-circle icon (`aria-hidden`); unselected shows an empty circle. Uses `aria-pressed`. Optional `hint` line under the label.
- `NumberStepper`: label, `value: number | null`, `min`, `max`, `onChange`, `hint` (for example "referrals · usual range 0 to 8"), `placeholder` ("–"). Buttons with `aria-label` "Decrease by one" and "Increase by one", 56px. Input `inputMode="numeric"`, accepts digits only, clamps to `min`/`max` on change. Decrease from `null` gives `min`.
- `Card`: white, radius 24px, padding 24px 28px, `<section>` with optional heading level prop.
- `Banner`: `tone: "info" | "warning" | "offline"`, `title`, children. `offline` and `warning` use `role="alert"`; `info` uses `role="status"`.
- Every component accepts `dataEl` and renders it as `data-el`.

**Build.** One file plus a CSS module per component in `components/ui/`, and `components/ui/index.ts` exporting them.

**Tests to write first.**
1. `Button` primary renders a button with the text; `busy` → disabled and `aria-busy="true"`; click does nothing while busy.
2. `Button` with `href` renders a link.
3. `Chip` toggles: click calls `onPressedChange(true)`; `aria-pressed` reflects the prop; Space and Enter work.
4. `OptionButton` selected shows `aria-pressed="true"`; the icon is hidden from the accessibility tree.
5. `NumberStepper` value 3, click "Increase by one" → `onChange(4)`; at `max` 8 increase stays 8; typing "12" with max 8 → `onChange(8)`; typing "a" ignored; decrease from `null` → `min`.
6. `NumberStepper` input has an accessible name equal to the label.
7. `Banner` offline has `role="alert"`.
8. `data-el` is rendered on each component.
9. `vitest-axe` reports no violations for each component.
