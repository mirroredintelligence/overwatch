You are a software engineer picking up one task in the `overwatch` repository (product name: DIUCS capacity). You have no memory of any earlier work. Everything you need is in this prompt and in the repository.

**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

Background: `docs/spec/architecture.md`, `docs/spec/fhir-data-model.md`, `docs/spec/observability.md`, `docs/spec/ui-screens.md` (screen wording). **Rules you need.**
- URLs: the reporter app lives under `/app`; put pages in `app/(reporter)/app/…`. Route groups add no URL segment, and `/` belongs to other groups.
- PIN screen "Enter your PIN" with the keypad and "Forgot your PIN?" (links to `/app/locked?reason=forgot`). Wrong PIN: "That PIN is not right. N tries left." On `locked:true` go to `/app/locked`; on `reverify:true` go to `/app/verify` (W37).
- Respond: the service name in large type, "Capacity update", "We have 3 referrals in the next 2 hours, as of 08:15. Still right?", **Yes, still 3**, "Or send a new number" with the stepper and the hint "referrals · usual range 0 to 8", **Send new number**, **We are closed to referrals**. With no figure yet: "How many referrals can you take in the next 2 hours?" and a disabled "Choose a number to send" until a number is chosen. API answer `confirmLimit`: "You confirmed twice already. Please send the number." API answer `outOfRange`: "That is outside your usual range (0 to 8). Send it again to confirm." keeping the number.
- Confirmation: "Thank you", "<Service>: 4 referrals recorded at 10:12.", "Next update due 12:00", a "Today" list (time and figure, newest first) and **Change it**.
- Home (`/app`): with one service, open its respond page when a prompt is open, otherwise show the latest confirmation. (Several services: W38.)
- BFF: `POST /api/bff/identity/pin/verify {pin}` → `{ok:true}` | `{ok:false, triesLeft}` | `{locked:true}` | `{reverify:true}`; `GET /api/bff/reporter/services/[serviceId]/prompt` → `{service, unitLabel, recordedValue|null, asOf|null, low, high, replyBy|null, nextDue}`; `POST /api/bff/reporter/services/[serviceId]/report {kind:"confirm"|"number"|"closed", value?}` → `{result:"recorded", value, recordedAt, nextDue}` | `{result:"confirmLimit"}` | `{result:"outOfRange", value}`; `GET …/history?day=today` → `{items:[{at, value}]}`. CSRF on POSTs. A 401 from any route sends the person to the PIN screen.
- data-el: `REP-APP-PIN-KEY-<N>`, `REP-APP-CONFIRM-BTN`, `REP-APP-SEND-BTN`, `REP-APP-CLOSED-BTN`, `REP-APP-CHANGE-BTN`.
