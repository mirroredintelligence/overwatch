You are a software engineer picking up one task in the `overwatch` repository (product name: DIUCS capacity). You have no memory of any earlier work. Everything you need is in this prompt and in the repository.

**The product.** DIUCS capacity helps an NHS urgent-care single point of access (SPOA) in Dorset. Community services, wards and virtual wards report how many referrals or beds they can take, by text message, a one-tap link, or an installed web app. Call advisors see a live wall board and a filtered list of services that fit a patient's needs, then ask a service to take the patient by text and wait for CONFIRMED. Shift leads chase late reports, register services and keep criteria current. Nothing anywhere holds a patient name or NHS number.

**The architecture.** Hexagonal. A Python back end (package `diucs` in `backend/src/diucs`) with four layers: `domain` (pure rules, no I/O), `application` (use cases and ports defined as `typing.Protocol`), `adapters` (inbound: FHIR REST, SMS webhook, link pages, workers; outbound: Neo4j, Redis, Azure Service Bus, SMS, email, push; `adapters/testing`: fakes for external providers only) and `bootstrap` (settings and the composition root). Dependencies point inwards only. A Next.js front end in `frontend/` talks only to its own `/api/bff/*` route handlers, which call the back end's FHIR R4B API. Neo4j is the only database, Redis is a cache, Azure Service Bus carries messages and scheduled work.

**Rules you need.**
- URL `/console/insight` with tabs Funnels, Paths, Friction, Performance, Releases (hash or `?tab=`). Each tab has a time range: Last 24 hours / Last 7 days / Last 30 days. Product and design users see this page; support code is not needed.
- Funnels: funnel picker (Reporter set-up, Daily capacity loop, Booking service side, Advisor call, Registration, Criteria review, COO and ICB adoption); steps with percentage of the first step as horizontal bars; "Biggest drop" callout naming the two steps, points lost, exit element and median time; a split table (Text link / Email link / App). Groups under 10 come as `suppressed: true` and show "fewer than 10" with no bar.
- Paths: "Most common routes" (route template, sessions, median time on page), "U-turns: left within 5 s", "Never used this week" (element ids).
- Friction: "Elements over 5% are reviewed."; device filter; table Element, Kind, Events, Interactions, Rate; rows at or over 5% are marked with a shape and the word "Review"; **Show example sessions** links to `/console?element=<id>`.
- Performance: web vitals table (Measure, p75, Budget, Status "Within budget"/"Over budget"), slowest routes, slowest Cypher queries by query id, and "Prompt to board: System time 4 s, Human time 8 min".
- Releases: compare chips ("1.4.2 with 1.4.1"), table Measure / old / new / Change ("Slower", "Higher"); pipeline table Queue or topic / Active / Dead-lettered / Oldest; "A dead-lettered message raises an alert to engineering."
- Status words come from a pure function `budgetStatus(value, budget)`; nothing relies on colour alone.
- BFF: `GET /api/bff/console/insight/[tab]?range=7d&…` returning the shapes above; one route handler with a switch on `tab`.
- data-el: `CON-INS-TAB-<NAME>`, `CON-INS-RANGE-<VALUE>`, `CON-INS-FUNNEL-<NAME>`, `CON-INS-EXAMPLES-BTN`.
